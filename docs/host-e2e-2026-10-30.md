## 怎么跑

```powershell
powershell -ExecutionPolicy Bypass -File scripts/host-e2e/run-e2e.ps1
```

脚本负责：起原生进程 → 等 `ready.txt` → 跑浏览器真实后端 E2E → 编译并运行 `SimHost`（真实协议主机 + 全量 HTTP）→ 校验优雅停机与退出码 → 清理临时工作目录。
退出码与 `RESULT=PASS/FAIL` 均作为门禁依据；`scripts/host-e2e/SimHost.java` 单独可跑（`java -cp ".;<protocol classes>;<json classes>" SimHost <http> <hsms> <deviceId>`，退出码=失败项数）。

## 过程中修正的“测试假设”（不是产品缺陷）

1. **配置读取是包装对象**：`GET /configs/{name}` 回 `{"name","text","modifiedMs"}`，不是裸原文；测试改用 `text` 字段再喂 validate/PUT/config-preview。
2. **validate 的语义是“200 + 问题清单”**：内容非法时仍回 200，由 `ok/valid/problems` 表达；只有请求本身坏了才 400/422。
3. **配置没有 DELETE 端点**：只能新建/保存/校验，测试改为断言 405（能力边界）。
4. **运行时 SML 的多顶层项必须包在 `<L …>` 里**：`S5F1 <B ..> <U4 ..> <A ..>.` 会被判“末尾多余内容”，正确写法是 `S5F1 <L …>.`。
5. **`Secs2.getDouble()/getInt()` 必须带值索引**（`getDouble(0)`）；无参形式会 `removeLast` 抛 `NoSuchElementException`。这是协议库的 API 约定，不是本次改动引入。
6. **PowerShell `Start-Process` 带 `-RedirectStandardOutput` 时读不到 `ExitCode`**：验收脚本改为直接启动进程（日志本来就落在 `work/logs`），从而能断言退出码 0。

以上 6 条已回写进脚本注释，避免下次踩同一坑。

## 与单元/集成测试的关系

- 88+ 项后端测试覆盖的是“单点行为 + 进程内假对端”；本报告覆盖的是**同一份二进制 + 真 socket + 真浏览器**，两者互补。
- 唯一的差异点是时延与端口：脚本每次随机挑 HTTP 端口、HSMS 用 15730/15731，避免与本机其它进程冲突。
