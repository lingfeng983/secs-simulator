# 未完成清单（2026-10-24）

> 面向后续 AI 开发的功能缺口清单。基于全量界面走查、真实后端联调与代码审读整理。
> 已完成项见 [unfinished-2026-10-17.md](unfinished-2026-10-17.md)（其中条目在本轮全部落地）。

## P0：核心功能缺口

- [ ] **配置按项热生效（不断连）**：重载语义目前是"关旧会话开新会话"，主机会断连。
  事件编排、设备常量、模板参数这类完全可以在运行中的会话上原地应用
  （事件启停已经有 `setEventEnabled` 先例）；`port`/`passive`/`deviceId` 才需要重建。
  做完后"改配置 → 保存 → 立即生效"就是无感的。工作量集中在 `HsmsSessionRuntime`
  加逐项更新入口 + ConfigPanel 保存后按 diff 决定"原地应用还是提示重载"。
- [ ] **HSMS 超时参数可配**：T3/T5/T6/T7/T8 目前是协议层默认值，配置文件和界面都没有。
  联调现场经常要放宽 T3。加到 `session` 段 + 表单 + `HsmsSsCommunicatorConfig`。
- [ ] **日志级别可调**：`Log` 只有固定输出；没有运行时调级别的能力。
  至少加 `--log-level` 与界面上的级别选择。
- [ ] **设备模板市场 / 内置模板库**：现在新建配置只有一份骨架。常见设备
  （刻蚀腔、CVD、测试机）做成内置模板，批量新建时可直接选型再改参数。

## P1：界面与体验

- [ ] **远程界面会话列表轮询在跨域下的错误提示**：连接设置指向不可达的后端时，
  各面板只显示空数据，没有明确的"连不上"横幅。加一个全局的连接健康横幅
  （后端不可达 / 版本不匹配时顶栏变红）。
- [ ] **批量操作进度**：批量上报/重载/关闭目前是逐台循环 + 一条汇总 toast；
  100 台时中间没有进度。改成分批并发（5 路）+ 进度条。
- [ ] **批量新建的端口冲突预检**：创建前用页面上已有会话的端口做个本地预检，
  冲突直接标红，不用等后端逐台失败。
- [ ] **曲线预览对比模式**：两台设备同屏对比（同 SVID 左右并排），多设备联调时
  需要对比 dev-a 和 dev-b 的温度曲线。
- [ ] **报文 SML 语法高亮**：报文面板与手动发送的正文都是纯文本 mono；
  关键字（SxFy、L/A/U4…）着色能明显提升可读性。
- [ ] **表格列宽自定义 / 记忆**：当前列宽固定，长报文体列只能截断；列宽拖拽 + 偏好记忆。

## P2：工程化

- [ ] **OpenAPI 同步**：`docs/openapi.yaml` 还没有 `POST /api/v1/sessions/bulk`、
  会话创建的 overrides 字段（sessionId/port/bindHost/deviceId）。CI 校验器会过
  （它只校验已有内容），但契约落后于实现。
- [ ] **E2E 覆盖新功能**：批量新建弹窗、批量操作、连接设置、压测面板都没有 e2e；
  现有 mock e2e 9 例 + real 1 例的规模需要扩。
- [ ] **原生镜像 CI 与双包产物**：`package.ps1` / `package-runtime.ps1` 都依赖本地
  GraalVM；CI 只在 native job 每周跑。把两个包的产出挂到 release 流程。
- [ ] **跨平台运行时包**：runtime 包目前只有 win-x64（原生 exe）。Linux 服务器场景
  需要 jar 版启动脚本（`java -cp ... Main --mode=server`）或 GraalVM Linux 镜像。
- [ ] **SSE 断线期间的报文补发**：事件流重连后"断线期间的报文不会补发"，
  界面靠手动"载入历史"。可在重连成功后自动按最后时间戳拉一次增量。
- [ ] **配置编辑器的 diff 视图**：保存前只能靠"与磁盘一致/有改动"判断；加一个
  与磁盘版本的并排 diff，改了什么一目了然。

## 已知技术债

- `Main.java` 的 Context 实现类接近千行，会话/配置/审计的转发逻辑可以按
  `ApiContext` 的能力分面拆掉。
- `HsmsSessionRuntime` 1800+ 行，协议回调、值引擎接线、HTTP 序列化辅助混在一起；
  拆分前先补齐针对它的单元测试。
- 前端 `useBackend` 是单一大控制器（800+ 行），轮询与写操作集中；面板继续增加时
  按域拆成多个 hook（会话域 / 配置域 / 报文域）。
- 前端 e2e 的 mock API 与真实后端行为存在漂移风险（202 状态码那次就是 mock 测不出来的）；
  考虑让 mock e2e 直接复用 OpenAPI 契约生成。
