# SECS Simulator 使用手册

SECS/GEM 多单元设备模拟器:在电脑上模拟出一台(或多台)符合 SECS/GEM 规范的半导体设备,
供主机(Host)程序联调测试。浏览器打开即用,不需要 Spring、不需要安装,一个可执行文件搞定。

本手册面向使用界面的人。配置文件格式(Schema v5)见 [docs/guides/schema-v5.md](schema-v5.md),
HTTP/SSE API 见 [docs/openapi.yaml](../openapi.yaml),架构与模块见 [README.md](../README.md)。

---

## 1. 启动与登录

```powershell
# 最简单:一体化模式,只绑本机,默认开放访问(免令牌)
secs-sim --mode=integrated

# 顺便托管界面(推荐):构建一次前端后,浏览器直接打开 READY 行里的地址
secs-sim --mode=integrated --web-root frontend/dist

# 从配置文件装载设备
secs-sim --mode=integrated --config ./device.json --hsms-port 5000

# 服务端模式:默认只绑回环;对外访问显式 --bind。内部工具不做鉴权,直连即可
secs-sim --mode=server --bind 0.0.0.0 --port 8080
```

启动日志里会打印一行 `READY`:

```
READY mode=integrated http=60331 utf8=true sessions=0 work=...
```

- `http=` 后面是界面地址,浏览器**直接打开就用**——内部工具,没有令牌、没有登录;
- `server` 形态同样直连:没有 `--token` / `--auth-users` 这类参数(写了会被当未知参数拒绝);
- 握手用的 http 端口写进 `<work-dir>/ready.txt`(POSIX 权限 600),不含任何凭据;
- 界面顶栏「连接」只填后端地址(本机/远程),不涉及凭据;
- 要把界面指向另一台机器上的**运行时后端**:顶栏「连接」填后端地址,保存后页面重载。

## 2. 界面总览（v6.1:单功能页面）

每个页面只做一件事,不聚合。左侧导航分组:**总览 → 设备(动态)→ 管理**:

| 位置 | 核心功能 |
|---|---|
| **工作台**（默认页,`#/workbench`） | 模拟器的总控台:一条 KPI 读数条 + **一张「设备与会话」表**。新建设备只选区模板,自动生成唯一设备名/端口/Device ID;勾选多台可批量同步配置、重载、关闭;点行进设备页 |
| **设备页**（`#/device/{id}/{子页}`） | 子页一页一能力:**事件**(CEID 定义 + 绑定报告 + 压测上报)、**报告**(RPTID 与变量)、**事件编排**(计划 CRUD/启停/触发 + 实时事件 + 周期预览 + 单计划预览)、**报警**(置位/清除 + 报警风暴)、**状态变量**(SVID CRUD + 逐变量预览 + 值设定)、**连接**(逐项说明 session)、**结构**(设备全局只留号段/常量；单元只留标识；模板页含快速绑定)、**配置**(只保留 JSON 原文，可导入/导出)、**发送**(手动 SML + 压测)、**消息**(收发监视，可拖拽放大、导入/导出 JSONL)。子页标题与说明不重复展示，悬浮页签可看说明。运行时的增删改不写回配置,重载会话后按配置恢复 |
| **主机模拟**（`#/hostsim/{子页}`） | 顶层入口,与设备页平级。可开**多个主机实例**,每个各连各的(本库里的设备或远程 SECS)。四个子页:**主机实例**(新建/断开/选用)、**① 消息发送**(以主机角色发 SML,下方带主机视角的收发记录与同样的类别屏蔽)、**② S6F1 采集**(S2F23→S6F1,设备推)、**③ S1F3 采集**(主机侧拉取) |
| **系统**（`#/system/audit`） | 审计留痕 |

顶部一栏:刷新、命令面板、连接设置、日志级别、主题与密度。
侧栏是固定的深色「机箱」,「设备」组动态列出会话:左侧绿点 = 在线,右侧一行小字写出状态。
设备组支持按名称/模板筛选,并可切换「平铺 / 按模板分组」;分组后是模板 → 设备 → 子页三级菜单,
模板组和设备子页都能展开/收起。
按 `[` 收起后变成图标栏,设备项显示两字母缩写(如 `LI`)加状态色,悬停看全名。
设备页顶部是一条**设备头**(设备名、会话 id、OPEN/在线、单元数)和一行子页标签,
点哪页改哪块;工作台则是「KPI 读数条 → 设备与会话(一张表)」两段。

**快捷键**(按 `?` 随时看):`Ctrl+K` 命令面板(可直达某台设备的配置/工具);
数字 `1..9`/`0` 跳静态入口;`R` 刷新;`/` 聚焦搜索框;
`[` 收起/展开导航;`Esc` 关浮层。
操作结果统一在**右下角提示条**反馈,绿色=成功、红色=失败;浮层打开时焦点被关在浮层里,
关闭后还给原来的按钮。

**开箱即用的两台演示设备**:首次启动会向 `--work-dir` 播种 `demo-etch.json`
(事件效果演示:超温闭环、pulse/shift/set 跳变)与 `demo-cvd.json`(主机拉取采集演示:
LOT_START/LOT_END 正好可做 S1F3 采集的启停 CEID)。加 `--demo-session` 直接开两台;
删掉文件重启即恢复默认,已有文件永不覆盖。

**快捷键**(按 `?` 随时看):`Ctrl+K` 命令面板;数字 `1..9`/`0` 直接跳面板;`R` 刷新;
`/` 聚焦搜索框;`Esc` 关浮层。操作结果统一在**右下角提示条**反馈,绿色=成功、红色=失败。

**排障**:顶栏「日志」下拉可随时切 error/info/debug(后端日志级别,切换会记审计);
后端连不上时页面顶部出红色横幅,「重试 / 修改地址」就在横幅上。

**历史保留窗口**:报文与审计历史在内存里各有一个回看窗口(报文默认最近 5000 条、
审计默认最近 1000 条,重启后从日志文件恢复这么多),可用 `--messages-recent <n>` /
`--audit-recent <n>` 调整;审计窗口就是界面上「载入更早」能翻多深。
窗口外的旧记录只剩磁盘上的 `logs/messages.jsonl` / `logs/audit.jsonl`,可以 grep 拿全量。

**个性化**:右上角可切浅色/深色/跟随系统、紧凑/宽松密度;当前页面与这些偏好跨刷新保留。
主题在**渲染前**就已定好(首屏不会先闪一下白底);深色不是浅色的反相,两套调色分别校过对比度。
窗口变窄时侧栏变成顶部横排,表格横向滚动,表单一列一列折——手机宽度也能用。

 **事件驱动的曲线**:状态变量页的「预览曲线」与事件编排页的「预览事件周期」画的都是
*串起事件编排之后*的曲线——后端先按当前编排做一次确定性模拟,把事件效果(set/pulse/shift)
叠进值来源再算图,所以「事件触发的跳变」和图上那条橙色竖线(发送事件时刻)是对得上的。
两条曲线用的是同一套后端语义,不是两套近似。

 **表单排版**:全站统一「描述在左、输入框/选择框在右、同一行且上下居中」。
描述列固定宽度,一排字段的控件左边缘齐平;宽度不够时整块换行,不会出现
「控件掉到描述下面」。这条规则由两个令牌控制(--field-label-w 描述列宽、
--field-gap 字段间距),改一处全站生效。

**视觉与排版**:界面按「精密仪器控制台」的语言重做——固定的深色机箱侧栏 +
浅色仪表盘 + 信号青(teal)主色,暖色只留给报警。所有颜色、圆角、间距、字号都走同一套
CSS 令牌(`frontend/src/styles/tokens.css`),深浅两套各自调色并校过正文对比度(≥4.5:1);
曲线也用主题色绘制,切主题时自动重画。

## 3. 典型工作流

### 3.1 开一台设备

1. 先到「模板管理」准备模板：内置模板可直接用，也可从任一模板复制出自定义模板并改 JSON；
2. 工作台「设备与会话」→ 选「设备模板」→ 点「新建设备」；
   后端自动生成唯一设备名并写 `<设备名>.json`，同时分配未占用的端口与 Device ID；
3. 表格里出现该设备:状态 `OPEN`、控制 `离线`(还没主机连)。

**批量管理已有设备**:勾选多台后：
- 「批量同步配置」以**勾选的第一台**为原始配置，把设备/单元/SVID/报告/事件/模板复制到其余设备，
  只改各自的会话 id、端口、Device ID 与设备名；可指定起始端口/Device ID；
- 「批量重载 / 批量关闭」逐台执行。
- 工作台已移除「批量上报」与 CEID 输入，上报统一在设备页做。

**模板管理**：顶层「模板管理」页支持新增（从已有模板复制）、编辑 JSON、校验、保存、删除；
内置模板只读，自定义模板存 `<work-dir>/templates/<id>.json`。没有合适模板时，工作台会引导先建模板。

### 3.2 让主机连上来

设备的 HSMS 端口由配置 `session.port` 决定(passive 模式监听)。主机连上并
Select 之后,控制状态变为 `通信中`;主机发 S1F17(或设备接受通信)后变 `在线`。
只有**在线**的设备才能向主机主动上报(事件、报警)。

没有现成主机?探针模式(`secs-sim --mode=probe --hsms-port 5000`)
可以开一个只应答 S1F1 的假设备,用来验证主机侧。

### 3.3 改配置并让它生效

1. 设备页·配置 → 自动打开本设备的配置文件；**只保留 JSON 原文**，连接/结构/模板到对应子页改；
2. 点「校验」——走的是真实启动路径(解析 → 编译设备模型 → 建模板图),不过不会落盘;
3. 点「保存」——校验通过后原子写盘，相关会话自动按新配置重载;
4. 需要离线编辑时可用「导出 JSON / 导入 JSON」，导入只进草稿，仍要校验/保存。

保存带**并发保护**:编辑器记住打开时的文件修改时间,保存时带回后端核对——
如果这期间配置被别的窗口(或进程)改过,保存会被拒绝(409)并提示「重新载入」,
后保存的一方不会悄悄覆盖先保存的改动。
   重载是智能的:只改了事件编排/模板/限流/W 位时**原地热生效,主机连接不断**;
   设备结构(单元/变量/号段)或连接标识(id/端口/超时)变了才关旧开新、主机需重连。
   编译失败时旧会话原样不动。

配置页**只保留 JSON 原文**：语法高亮、一键格式化，编辑区默认占满窗口剩余高度，
超出后在自己的框里滚动，页面不会跟着撑长。保存逐字节写回,手写的注释键、缩进都不会被改。
结构化字段分别放到**连接**(session，每个属性都有作用说明)与**结构**(设备全局/单元/模板
三个页签;模板页说明曲线/组合/实例的用途、被 SVID 值来源引用的位置和配置顺序)子页;
两处走同一套「校验 → 保存 → 相关会话重载」流程,并发保护也一样。

### 3.4 模拟一次报警

设备页·报警:填 ALID(如 1001)、类别、报警文本 → 点「置位」。设备向主机发
S5F1(带 W 位等 S5F2);点「清除」发 ALCD=0 的 S5F1。
报警是否真的到达主机,去设备「消息」页按「报警」类别看 S5F1/S5F2——
原来的"活动报警/终端消息"本地快照已移除(异步 ACK 失败时会误导)。
报文留档在 `logs/messages.jsonl`,可按 `S5F1` 检索。

### 3.4b 主机模拟(发主机方向的报文)

S2F33(定义报告)/S2F35(链接事件)/S2F37(启停事件)是**主机→设备**方向的报文,
设备侧界面发不出正确语义。主机模拟是顶层入口,与设备页平级,分四个子页:
**主机实例**(新建/断开/选用;可开多个实例,连本库设备或远程 SECS。
**一台设备只允许一个本机主机**,已有连接时该设备在新建下拉里被禁用)、
**① 消息发送**(以主机角色发 SML;内置 16 条常用预设:心跳/建链/上线/下线、
S1F3/S1F11/S2F13/S2F17、报告/事件、Trace、终端消息。展开「预设说明」能看到每条
是干什么的、正常回复是什么;预设只是模板,填入后仍可改 ID/数值。
勾选一至多台主机即可把同一条报文逐台发出,结果逐台列出。
发送后「事件设置」页的定义来源会变成"主机",事件编排启停状态同步变化;
页面下方是**主机视角的收发记录**,可导出该主机 JSONL,也可按探测/采集/Trace/事件/通信/报警/终端屏蔽)、
**② S6F1 采集**(S2F23 周期采样,设备按 REPGSZ 分条回 S6F1。
每台主机有独立的 TRID/周期/样本/变量配置,汇总表分开展示,可逐行发送。
**S6F1 只在设备 ONLINE 后上报**:主机刚连上(通信中)时下发只会回 S2F24、没有帧,
页面会提示并提供「发送 S1F17 上线」按钮；在线时同一位置变为「下线」（S1F15）。
想更快看到帧,把「每条样本数」调成 1)、
**③ S1F3 采集**(主机主动轮询拉取,可编辑采集计划、实时画图、导出 CSV;
每 SVID 一张带坐标轴的大图,支持框选缩放/滚轮缩放;顶部汇总表按主机列出配置/状态/采样点/RTT)。

**W 位默认要求回复**:手动 SML 的奇数 function(primary)不写 W 也会按 W 发送,
secondary(偶数)不允许带 W;设备配置里 S6F11/S6F1 默认带 W,S5F1 始终带 W。
主机模拟会自动回 S1F2/S5F2/S6F12/S6F2/S10F4,设备也会回复主机发来的 W primary。
S1F3 采集与 S6F1 采集的采集变量都用同一套紧凑多选网格。

设备页的**消息**子页是同一份实时报文,方向按设备视角标成"收 ← 主机 / 发 → 主机";
主机模拟里方向相反。过滤只影响显示,报文仍照常落盘:混合日志 `logs/messages.jsonl`,
以及按会话拆分的 `logs/devices/<会话>.jsonl`(设备视角)和
`logs/hosts/<会话>.jsonl`(主机视角、方向翻转)。设备页/主机页都有"只导出本实体"的按钮。远程主机的报文不经过本进程,
页面会明确提示无法在此监视。

> 侧栏设备状态:`通讯中` 表示主机已建立 HSMS 连接但还没有 S1F17;`在线` 表示设备已进入
> ONLINE。两种都算"已连接",不再显示为离线。

### 3.5 手动发报文与压测

设备页·发送:输入 SML 文本(如 `S1F1 W.`),点「发送 SML」。带 `W` 时会等
主机应答并显示回复报文与耗时;主机没连时会返回 409。SML 语法:报文头 `SxFy`,
数据项支持 `L/A/B/BOOLEAN/I1..I8/U1..U8/F4/F8`。

### 3.6

下方的**压测**把同一份报文重复发送 N 次(1–1000,并发 1–20,可设每轮间隔),
实时显示进度,结束后给出成功/失败/超时数、往返延迟(平均/最小/最大/P95)和吞吐。
同一条消息要重复发送:填好次数/间隔后点「压测发送」,服务端循环并统计成功/失败与延迟。

看曲线

设备页·状态变量:每个 SVID 一行,点「预览」画该变量最近一段时间的曲线
(带坐标轴、min/max 包络与事件竖线;事件按计划分色,图下列出当前视图的事件清单)。
回放从窗口之前开始,窗口内仍在生效的 set/shift 效果也会带进来。
时间窗最长可选 30 分钟;图可拖动框选放大、滚轮缩放时间轴、Shift+滚轮平移、
Ctrl+滚轮纵向缩放、双击复位;「事件标记」开关可只看曲线。
「设定」把变量钉在给定值上(覆盖曲线与事件效果),「取消设定」回到曲线值。

事件周期预览同样有缩放按钮与「显示事件图例」开关;列表行「预览」只回放单条计划,
时间窗也可选到 30 分钟。

## 4. 页面速查

### 导入 / 导出
- 可编辑表格（会话 / 主机实例 / SVID / 事件 / 报告）在「导出 CSV」旁边都有「导入 CSV」，按导出表头解析并逐行写入；
- 配置页支持「导出 JSON / 导入 JSON」，导入只进草稿，仍需校验/保存；
- 消息列表支持导出/导入 JSONL（导入只在本页查看，不写回服务端日志）；S1F3 采集支持导出/导入 CSV 离线看图；
- 审计 CSV 可导入后只读查看（不写回服务端）；报警页没有可写回的导入目标。

### 会话管理
- 表格列:id / 状态(OPEN…) / 控制(离线・通信中・在线) / 设备 / 单元数 / 计数器;
- 操作:**上报**(手动触发一次 S6F11,要求设备在线)、**重载**(按配置重建会话)、**关闭**(解绑端口);
- 搜索框即时过滤,点列头排序,「导出 CSV」拿全量;
- CEID 框配合设备页·目录的「填入」按钮用,不用背数字。

### 报警
- 置位/清除即时生效;是否到达主机看设备「消息」页的 S5F1/S5F2(报警类别)。
- 原来的活动报警/终端消息本地表已移除,避免异步 ACK 失败时给出误导性快照。

### 事件编排
- 改的是**运行时状态**:禁用后不再触发、已排队的延迟事件清掉;重载会话后按配置恢复。

### 设备页·配置
- 表单视图覆盖 session / equipment(号段、全局 SVID/CEID、ECV 常量、单元)/ events / templates;
- 事件计划的 CEID 输入框带自动补全;类型下拉是后端支持的 12 种 SECS-II 类型;
- 未知键永远保留;表单改动会把整份文件统一成 2 空格缩进(界面上有说明)。

### 审计
- 审计记录登录后的每个写操作(动作/目标/结果),落盘在 `logs/audit.jsonl`(重启保留最近 1000 条);
  动作/操作者是**服务端**精确过滤,「载入更早」以最早一条为游标往前翻,本地搜索是包含式过滤,三者互补。

## 5. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 上报/报警返回 409 | 设备不在线。主机必须已连接、完成 S1F13/S1F17 让设备进入**在线**;或先查工作台会话表的控制状态 |
| 新建会话报"必须是 .json 文件" | 输入的配置名带 `.json` 后缀(界面会自动补,直接输文件名即可) |
| 改了配置没生效 | 配置在会话启动时读入内存,保存后必须到工作台「会话管理」**重载**该会话 |
| 重载后主机断了 | 重载 = 关旧开新,HSMS 连接会断,主机重连即可;设备会重新监听原端口 |
| 事件断线 | SSE 断了,界面 2 秒后自动换票据重连;断线期间的报文留档在 `logs/messages.jsonl` |
| 报警文本含中文被拒 | S5F1 的 ALTX 是 ASCII 编码,换纯英文文本 |
| 曲线全是 0 | 配置有 `templates` 段时,没绑定到实例的 SVID 恒为 0(见 schema-v5);删掉 templates 段可回到默认随机曲线 |
| 校验报 `UNKNOWN_CEID` | 事件计划里的 `ceid` 在该设备的单元/全局 CEID 里没有定义;先在 `equipment` 段补上,或改计划引用的编号 |
| 主机写完 ECV 后配置被重排 | 正常现象:S2F15 回写只替换 `constants` 段,其余键与值不变,但缩进会统一成 2 空格 |
| 加了 --token 后启动报"未知参数" | 令牌已移除：内部工具直连访问，删掉该参数即可 |

## 6. 两种安装形态

| 形态 | 内容 | 用法 |
|---|---|---|
| **Windows 安装程序** `SECS Simulator_<版本>_x64-setup.exe` | Tauri 壳(前端内嵌) + 原生 exe 后端 | 安装后打开直接进界面,默认连本机后端(无需 JVM);`scripts/package-windows.ps1` 产出 |
| **Linux 服务端** `secs-sim-server-<版本>-linux.zip` | 模块 jar + 前端 + `start-server.sh` | 部署在 Linux 设备机,`./start-server.sh` 以 server 模式对外(目标机需 JDK 25+);`scripts/package-linux.ps1` 产出 |

远程场景:设备在 Linux 机(A)解压服务端包并 `./start-server.sh` 启动;
操作者在 Windows 机(B)安装程序,打开后点右上角「连接」,填 A 机地址(`http://A 机 IP:8080`)
保存——界面仍由 B 机的壳提供,但配置、批量、曲线、报文全部操作 A 机,本机后端自动停止。
要切回本机,同一对话框里清空地址保存即可。
本机场景则完全不依赖网络:安装程序内置后端与前端,打开即用。
