# SECS Simulator 使用手册

SECS/GEM 多单元设备模拟器:在电脑上模拟出一台(或多台)符合 SECS/GEM 规范的半导体设备,
供主机(Host)程序联调测试。浏览器打开即用,不需要 Spring、不需要安装,一个可执行文件搞定。

本手册面向使用界面的人。配置文件格式(Schema v7)见 [docs/guides/schema-v7.md](schema-v7.md),
HTTP/SSE API 见 [secs-simulator-service/scripts/openapi.yaml](../secs-simulator-service/scripts/openapi.yaml),架构与模块见 [README.md](../README.md)。

---

## 1. 启动与登录

```powershell
# 最简单:一体化模式,只绑本机,默认开放访问(免令牌)
secs-sim --mode=integrated

# 顺便托管界面(推荐):构建一次前端后,浏览器直接打开 READY 行里的地址
secs-sim --mode=integrated --web-root secs-simulator-ui/dist

# 从配置文件装载设备
secs-sim --mode=integrated --config ./device.json

# 服务端模式:默认监听 0.0.0.0;需要收窄时显式 --bind。内部工具不做鉴权,直连即可
secs-sim --mode=server --port 8080
```

启动日志里会打印一行 `READY`:

```
READY mode=integrated http=60331 utf8=true sessions=0 work=...
```

- `http=` 后面是界面地址,浏览器**直接打开就用**——内部工具,没有令牌、没有登录;
- `server` 形态同样直连:没有 `--token` / `--auth-users` 这类参数(写了会被当未知参数拒绝);
- 握手用的 http 端口写进 `<work-dir>/ready.txt`(POSIX 权限 600),不含任何凭据;
- 界面顶栏「连接」只填后端地址(本机/远程),不涉及凭据;
- 要把界面指向另一台机器上的**运行时后端**:顶栏「连接」填后端地址,保存后页面重载。

## 2. 界面总览（3.2：按操作对象分组，配置区 / 运行区分开）

左侧导航分三组:**设备 / 主机清单 / 独立工具**。「设备」组下是「设备清单」入口 + 动态设备树，
「主机清单」组下是主机列表入口 + 动态主机树，「独立工具」组下表列主机模板 / 设备模板 /
参数模板 / 审计（见 `src/app/layout/navigation.ts` 的 `NAV_GROUPS`）。旧版的「总览」组、
按名称/模板筛选、平铺/按模板分组切换**均已下线**。

3.2 的核心划分是**配置区 / 运行区**：配置区回答「我定义了什么」（改了要显式保存，
产生一个配置版本）；运行区回答「现在正在发生什么」（改了即刻生效，进 `runtime.db`，
不产生配置版本）。

| 位置 | 核心功能 |
|---|---|
| **工作台**（`#/workbench`） | 设备清单：「设备与会话」一张表，筛选在左、动作在右。新建设备只选区模板，自动生成唯一设备名/端口/Device ID；表头复选框=全选（再点=清空）；勾选多台可批量同步配置、重载、停止、删除；行内可重载/启停/上下线/删除；点行进设备页 |
| **设备·配置区**（`#/device/{id}/config/{页}`） | 共 **11 页**：**概览**、**链接配置**（端口/Device ID/超时/Trace 容量）、**结构配置**（号段规划/事件发送/单元）、**设备常量**（ECV）、**晶圆属性**（LOTID/RCPID/PPID/WAFERID）、**变量配置**（SVID 定义与值来源）、**事件与报告**（CEID/RPT 定义）、**工艺周期**（节拍/片内事件）、**事件计划**（触发规则）、**全量配置**（JSON 导入/导出）、**版本历史**（每次保存一条，可看差异） |
| **设备·运行区**（`#/device/{id}/runtime/{页}`） | 共 **4 页**：**事件执行**（计划启停 + 单步试跑 + 执行台账：状态/报文条数，可只看失败、导出 CSV）、**工艺周期**（运行态启停 + 片内事件台账）、**消息发送**（手动 SML + 压测发送）、**报警风暴**（活动报警 + 置位/清除 + 风暴压测）。实时状态并入页头实例行，报文收发统一收进右侧抽屉 |
| **主机**（`#/hosts`） | 主机实例列表：新建（可从模板）、连接/断开/删除，批量链接/断开/删除（表头复选框全选）；看链路相位与最近错误。主机实例独立于会话，可同时开多台，各连各的（本机设备或远程 SECS） |
| **主机详情**（`#/hosts/{hostId}/{区}/{页}`） | 配置区 4 页：**概览 / 报文模板 / Trace 设置 / 采集设置**（目标地址在概览里改）；运行区 3 页：**消息发送 / Trace 采集 / 数据采集**，实时状态并入实例头，收发记录统一收进右侧抽屉 |
| **系统**（`#/system/audit`） | 审计留痕 |

### 断开 ≠ 删除

设备列表里的「停止」只断端口监听：行留在列表里、按钮变成「启动」，模型、钉值、
计划启停全都保留，点一下就能再开。真正的删除是另一个动作——
`DELETE /api/v1/configs/{name}`：后端先停掉这台设备的会话，再把库里的设备行软删，
它从清单里消失、名字可以重新使用；配置正文与版本历史仍留在库里。
删除会弹确认框，单个删和批量删走同一个确认。v1 的 `DELETE /api/v1/sessions/{id}` 仍是断开语义，响应带 `Deprecation` 头。

### 运行时的改动去哪了

钉值、计划启停、运行时新增的 CEID/报告/SVID，都写进 `runtime.db`，重启后自动恢复；
但它们**不会**变成配置版本。想让某个改动长期生效，去配置区保存一次。
需要「回到配置定义的样子」时用「重载」——重载会清掉运行态编辑但保留计划启停。

顶部一栏:刷新、命令面板、连接设置、日志级别、主题与密度。
侧栏是固定的深色「机箱」,「设备」组动态列出会话:左侧绿点 = 在线,右侧一行小字写出状态;
每台设备展开后是配置区 / 运行区两组子页,点击进入对应页。
按 `[` 收起后变成图标栏,设备项显示两字母缩写(如 `LI`)加状态色,悬停看全名。
设备页顶部是一条**操作栏**：配置区 / 运行区切换、监听端点标签，以及「启动/停止设备」「上线/下线」
动作按钮（设备名在页签与侧栏里都有，状态在设备清单里看）；下方一行子页标签，点哪页改哪块；
工作台则是「一行操作 + 设备与会话一张表」。

**快捷键**(按 `?` 随时看):`Ctrl+K` 命令面板(可直达某台设备的配置/工具);
数字 `1..9`/`0` 跳静态入口;`R` 刷新;`/` 聚焦搜索框;
`[` 收起/展开导航;`Esc` 关浮层。
操作结果统一在**右下角提示条**反馈,绿色=成功、红色=失败;浮层打开时焦点被关在浮层里,
关闭后还给原来的按钮。

**两台演示设备**:`demo-etch.json`(wafer 周期 + 三类数据演示:晶圆属性进报告、
时间变化型设备常量、双腔温度/压力)与 `demo-cvd.json`(表达式 + 分段工艺演示)。
演示设备 JSON 只作测试资产(host-e2e/IT 用 `--config` 显式启动),日常不自动创建。
设备一旦建好就存在数据库里:进程重启后列表原样保留,但都是「停止」状态——
由用户点「启动」才开始监听 HSMS,重启不会自动拉起任何会话。

**排障**:顶栏「日志」下拉可随时切 error/info/debug(后端日志级别,切换会记审计);
后端连不上时页面顶部出红色横幅,「重试 / 修改地址」就在横幅上。

**历史保留窗口**:报文与审计历史在内存里各有一个回看窗口(报文默认最近 5000 条、
审计默认最近 1000 条,重启后从日志文件恢复这么多),可用 `--messages-recent <n>` /
`--audit-recent <n>` 调整;审计窗口就是界面上「载入更早」能翻多深。
窗口外的旧记录只剩磁盘上的 `logs/messages.jsonl` / `logs/audit.jsonl`,可以 grep 拿全量。

**个性化**:右上角可切浅色/深色/跟随系统、紧凑/宽松密度;当前页面与这些偏好跨刷新保留。
主题在**渲染前**就已定好(首屏不会先闪一下白底);深色不是浅色的反相,两套调色分别校过对比度。
窗口变窄时侧栏变成顶部横排,表格横向滚动,表单一列一列折——手机宽度也能用。

  **值定义预览**:变量配置页每行 SVID 的「预览曲线」按前端本地试跑画出这条值定义的形状
（不连后端、不写配置）；事件预览只画触发时刻的竖线——**事件不改值**，
跳变只能来自曲线本身（比如 `sequence` 的一段或 `step`）。

 **表单排版**:全站统一「描述在左、输入框/选择框在右、同一行且上下居中」。
描述列固定宽度,一排字段的控件左边缘齐平;宽度不够时整块换行,不会出现
「控件掉到描述下面」。这条规则由两个令牌控制(--field-label-w 描述列宽、
--field-gap 字段间距),改一处全站生效。

**视觉与排版**:界面按「精密仪器控制台」的语言重做——固定的深色机箱侧栏 +
浅色仪表盘 + 信号青(teal)主色,暖色只留给报警。所有颜色、圆角、间距、字号都走同一套
CSS 令牌(`secs-simulator-ui/src/styles/tokens.css`),深浅两套各自调色并校过正文对比度(≥4.5:1);
曲线也用主题色绘制,切主题时自动重画。

## 3. 典型工作流

### 3.1 开一台设备

1. 先准备设备模板：内置 6 个（空骨架/刻蚀/CVD/测试机/装载锁/CMP），也可复制出自定义模板改 JSON；
2. 工作台「设备与会话」→ 选「设备模板」→ 点「新建设备」；
   后端自动生成唯一设备名，写进 `config.db`（不再是 `config/<设备名>.json`），
   同时分配未占用的端口与 Device ID；
3. 表格里出现该设备：状态 `OPEN`、控制 `离线`（还没主机连）。

**批量管理已有设备**:勾选多台后：
- 「批量同步配置」以**勾选的第一台**为原始配置，把设备/单元/SVID/报告/事件/模板复制到其余设备，
  只改各自的会话 id、端口、Device ID 与设备名；可指定起始端口/Device ID；
- 「批量重载 / 批量断开」逐台执行（3.0 起「断开」只断链路，行会留在列表里）。
- 工作台已移除「批量上报」与 CEID 输入，上报统一在设备页做。

**模板管理**：`#/templates` 页支持新增（从已有模板复制）、编辑 JSON、校验、保存、删除；
内置模板只读，自定义模板存进 `config.db`（2.x 的 `<work-dir>/templates/<id>.json`
会在首次启动时迁入库并留在 `legacy/`）。没有合适模板时，工作台会引导先建模板。

**参数模板库**（`#/svid-templates`，独立工具）：所有设备共享的「值定义」库。
每条就是一段 `source`（单曲线、分段序列、或带私有变量的表达式），不绑定任何变量。
列表里可新建 / 编辑 / 复制为自定义 / 删除，内置 16 套只读。
使用方式是**复制**：在「设备 · 配置区 · 变量配置」里选「从模板库填入」，
把那段值定义深拷贝进这个变量（之后改库不影响这台设备，要更新就再填一次）。
设备里存的是展开后的 `source`，没有引用、没有实例。

### 3.2 让主机连上来

设备的 HSMS 端口由配置 `session.port` 决定(passive 模式监听)。主机连上并
Select 之后,控制状态变为 `通信中`;主机发 S1F17(或设备接受通信)后变 `在线`。
只有**在线**的设备才能向主机主动上报(事件、报警)。

没有现成主机?探针模式(`secs-sim --mode=probe --hsms-port 5000`)
可以开一个只应答 S1F1 的假设备,用来验证主机侧。

### 3.3 改配置并让它生效

1. 分段改到配置区对应子页：**链接配置**（session）、**结构配置**（号段规划/事件发送/单元）、
   **变量配置**、**事件与报告**、**工艺周期**、**事件计划**、**设备常量**；
2. 各页保存方式不同，页面自己会写清楚：
   - **链接配置 / 工艺周期 / 结构配置的设备全局**：填完点页内「保存」，只提交本页拥有的段；
   - **变量配置 / 设备常量 / 事件与报告 / 事件计划 / 结构配置的单元**：新建、编辑、删除
     弹窗点「确定」即保存落盘，页面上没有额外的保存按钮；
3. 要改整份原文去「全量配置」页：语法高亮、一键格式化，可校验、保存、导入/导出 JSON；
4. 改动生效范围看段：`session`（端口/绑定地址/Device ID）保存后按新参数重建会话，
   当前连接断开、运行状态清空；`structure` 保存即落盘，但**运行中的设备继续跑旧模型，
   重启设备后才换新结构**；其余段（变量/事件/周期/常量/限流）热应用，主机连接不断。
   编译失败时旧会话原样不动。

保存带**并发保护**:编辑器记住打开时的文件修改时间,保存时带回后端核对——
如果这期间配置被别的窗口(或进程)改过,保存会被拒绝(409)并提示「重新载入」,
后保存的一方不会悄悄覆盖先保存的改动。

配置页**只保留 JSON 原文**：编辑区默认占满窗口剩余高度，
超出后在自己的框里滚动，页面不会跟着撑长。保存逐字节写回,手写的注释键、缩进都不会被改。

### 3.3b 跑一条事件计划并看台账

1. 设备·**配置区**「事件计划」页新建计划（CEID、触发规则、动作），保存后到**运行区**「事件执行」页；
2. 在「事件执行」页勾选「启用」，倒计时开始走；列表上能看到状态、累计触发次数与最近一次错误，
   也可对任意一条计划点「单步试跑」（dry-run，不计触发次数）；
3. 同页**执行台账**每次触发追加一条：状态（SENT / PARTIAL / FAILED / SKIPPED）、
   发出几条报文、耗时；台账可只看失败、可导出 CSV；
4. 想看某一时刻到底发了什么，去右侧报文抽屉按 CEID 过滤——台账记的是「谁触发了什么」，
   报文记的是「线上真实流动的字节」，两边对得上才说明链路是通的。

台账存 `runtime.db`，重启不丢；「事件执行」页的「累计」读的就是它。
设备离线时按 `offlinePolicy` 处理：`skip` 记 SKIPPED，`fail` 记 FAILED 并把错误写进计划卡。

### 3.4 模拟一次报警

设备·运行区「报警风暴」页：填 ALID（如 1001）、类别、报警文本 → 点「置位报警」。设备向主机发
S5F1(带 W 位等 S5F2);点「清除报警」发 ALCD=0 的 S5F1。同页还有「报警风暴」压测（填次数/间隔连发，
若已有一轮在跑会提示等待，不会重复启动）。
报警是否真的到达主机,去右侧报文抽屉按「报警」类别看 S5F1/S5F2——
原来的"活动报警/终端消息"本地快照已移除(异步 ACK 失败时会误导)。
报文留档在 `logs/messages.jsonl`,可按 `S5F1` 检索。

### 3.4b 主机模拟(发主机方向的报文)

S2F33(定义报告)/S2F35(链接事件)/S2F37(启停事件)是**主机→设备**方向的报文,
设备侧界面发不出正确语义。主机模拟是顶层入口「主机清单」(`#/hosts`)：先在这里
新建主机实例（可从主机模板套用）、连接/断开/删除，勾选多台可批量链接/断开/删除；
新建弹框里**名称不能与已有主机重名、同一个 IP 上端口不能重复**（撞了就地红字提示、创建不可点，
默认名称/端口会自动避开已占用的），建完**留在清单里**不跳转，要看细节点行尾「详情」；
点实例进入主机详情，同样是**配置区 / 运行区**两段式（不像旧版那样平铺五页）。
可同时开多台主机，各连各的（本机设备或远程 SECS）；**一台设备只允许一个本机主机**，
已有连接时该设备在新建下拉里被禁用。

主机详情的 **配置区 4 页**：**概览**（目标地址/端口/Device ID、自动重连，改后需「使设置生效」）、
**报文模板**（16 条常用预设：心跳/建链/上线/下线、S1F3/S1F11/S2F13/S2F17、报告/事件、
Trace、终端消息；展开「预设说明」看每条用途与正常回复，预设只是模板，填入后仍可改）、
**Trace 设置**（S2F23 采样方案库）、**采集设置**（S1F3 采集方案库）。

**运行区 3 页**：**消息发送**（以主机角色发 SML，勾选多台逐台发出；同页还能**压测发送**：
填次数与间隔，服务端后台连发，给出成功/失败与 P50/P95/Max，W 位逐条等回复最长 5 分钟）、
**Trace 采集**（下发 S2F23，设备按 REPGSZ 分条回 S6F1）、
**数据采集**（下发 S1F3 采集配置、启停采集、实时画图、导出 CSV；远程主机手填 SVID 列表）。
配置入口按主机类型分流：本机设备有完整 catalog 可变量多选（Trace 上限 `session.trace.maxSvidCount`
默认 10，采集器上限 256），远程主机没有本地 catalog，整条报文手填直接发。
**S6F1 只在设备 ONLINE 后上报**：主机刚连上（通信中）时下发只回 S2F24、没有帧，
页面提示并提供「发送 S1F17 上线」按钮；在线时变为「下线」（S1F15）。

所有主机实例（含远程）的收发报文统一收进右侧**报文抽屉**实时汇总，按时间倒序滚动，
可按主机、方向、SxFy、报文体关键字过滤并导出 JSONL。**远程主机的报文由主机实例自己采集**
——设备侧看不见它们，只有报文抽屉能监视；方向按主机视角标注，与设备页相反。

**W 位默认要求回复**:手动 SML 的奇数 function(primary)不写 W 也会按 W 发送,
secondary(偶数)不允许带 W;设备配置里 S6F11/S6F1 默认带 W,S5F1 始终带 W。
主机模拟会自动回 S1F2/S5F2/S6F12/S6F2/S10F4,设备也会回复主机发来的 W primary。
S1F3 采集与 S6F1 采集的采集变量都用同一套紧凑多选网格。

设备页与主机页共用右侧**报文抽屉**看同一份实时报文，只是方向标注相反
（设备视角"收 ← 主机 / 发 → 主机"，主机视角反过来）。过滤只影响显示,报文仍照常落盘:
混合日志 `logs/messages.jsonl`,以及按会话拆分的 `logs/devices/<会话>.jsonl`(设备视角)和
`logs/hosts/<会话>.jsonl`(主机视角、方向翻转),每条都带 `hostId`(空串 = 设备会话自己收发的)。
设备页/主机页都有"只导出本实体"的按钮。
远程主机的报文由主机实例自己发布并带 `hostId`,因此在报文抽屉里看得到,
但在设备视角里没有(设备根本没收到它们)——这是设计上的区分,不是漏收。

> 侧栏设备状态:`通讯中` 表示主机已建立 HSMS 连接但还没有 S1F17;`在线` 表示设备已进入
> ONLINE。两种都算"已连接",不再显示为离线。

### 3.5 手动发报文、压测与看曲线

**手动发报文**：设备·运行区「消息发送」页输入 SML 文本(如 `S1F1 W.`),点「发送 SML」。
带 `W` 时会等主机应答并显示回复报文与耗时;主机没连时会返回 409。SML 语法:报文头 `SxFy`,
数据项支持 `L/A/B/BOOLEAN/I1..I8/U1..U8/F4/F8`。

**压测**：「消息发送」页把同一份报文（或一次事件上报）在服务端后台循环发送，
「报警风暴」页把一组报警置位/清除循环发送，
填次数（1–5000）与间隔（ms，0=全速）后点「压测发送」/「开始压测」/「报警风暴」，
结束后给出成功/失败数与往返延迟分位值。服务端有互斥保护：同一设备同时只允许一轮压测，
已有一轮在跑时再点会提示等待，不会重复启动。

**看曲线**：设备·配置区「变量配置」页每行 SVID 的「预览曲线」按前端本地试跑画出该值定义的形状
（不连后端、不写配置），带坐标轴与 min/max 包络；时间窗最长 30 分钟，
支持框选放大、滚轮缩放、双击复位。「事件执行」页的预览只画触发时刻的竖线——
**事件不改值**，曲线跳变只能来自值定义本身。旧版运行区「状态变量」页及其「设定/取消设定」
钉值能力已下线。

## 4. 页面速查

### 导入 / 导出
- 可编辑表格（会话 / 主机实例 / SVID / 事件 / 报告）在「导出 CSV」旁边都有「导入 CSV」，按导出表头解析并逐行写入；
- 配置页支持「导出 JSON / 导入 JSON」，导入只进草稿，仍需校验/保存；
- 消息列表支持导出/导入 JSONL（导入只在本页查看，不写回服务端日志）；S1F3 采集支持导出/导入 CSV 离线看图；
- 审计 CSV 可导入后只读查看（不写回服务端）；报警页没有可写回的导入目标。

### 设备清单（工作台）
- 表格列:id / 状态(OPEN…) / 控制(离线・通信中・在线) / 设备 / 单元数 / 计数器;
- 操作:**上报**(手动触发一次 S6F11,要求设备在线)、**重载**(按配置重建会话)、**关闭**(解绑端口);
- 搜索框即时过滤,点列头排序,「导出 CSV」拿全量;
- CEID 输入框在设备·配置区「事件与报告」/「事件计划」页，带自动补全，不用背数字。

### 报警
- 置位/清除即时生效;是否到达主机看右侧报文抽屉里的 S5F1/S5F2(报警类别)。
- 原来的活动报警/终端消息本地表已移除,避免异步 ACK 失败时给出误导性快照。

### 事件编排
- 改的是**运行时状态**:禁用后不再触发、已排队的延迟事件清掉;重载会话后按配置恢复。

### 设备页·配置
- 表单视图覆盖 session / equipment(号段、全局 SVID/CEID、ECV 常量、单元)/ events / templates;
- 事件计划的 CEID 输入框带自动补全;类型下拉是后端支持的 12 种 SECS-II 类型;
- 未知键永远保留;表单改动会把整份文件统一成 2 空格缩进(界面上有说明)。

### 审计
- 审计记录登录后的每个写操作(动作/目标/结果),落盘在 `logs/audit.jsonl`(重启保留最近 1000 条);
  动作/操作者是**服务端**精确过滤,「载入更早」以最早一条为游标往前翻,本地搜索是包含式过滤,三者互补。

## 5. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 上报/报警返回 409 | 设备不在线。主机必须已连接、完成 S1F13/S1F17 让设备进入**在线**;或先查工作台会话表的控制状态 |
| 新建会话报"必须是 .json 文件" | 输入的配置名带 `.json` 后缀(界面会自动补,直接输文件名即可) |
| 改了配置没生效 | 配置在会话启动时读入内存,保存后必须到工作台设备清单里对该设备**重载**（或到设备页点「启动设备」重启）|
| 重载后主机断了 | 重载 = 关旧开新,HSMS 连接会断,主机重连即可;设备会重新监听原端口 |
| 事件断线 | SSE 断了,界面 2 秒后自动换票据重连;断线期间的报文留档在 `logs/messages.jsonl` |
| 报警文本含中文被拒 | S5F1 的 ALTX 是 ASCII 编码,换纯英文文本 |
| 曲线全是 0 | 整台设备只要有任意一个变量配了 `source`,未配值定义的变量出口就是 0;给那些变量也配上值定义,或全部删掉 `source` 回到默认曲线 |
| 校验报 `UNKNOWN_CEID` | 事件计划里的 `ceid` 在该设备的单元/全局 CEID 里没有定义;先在 `equipment` 段补上,或改计划引用的编号 |
| 主机写完 ECV 后配置被重排 | 正常现象:S2F15 回写只替换 `constants` 段,其余键与值不变,但缩进会统一成 2 空格 |
| 加了 --token 后启动报"未知参数" | 令牌已移除：内部工具直连访问，删掉该参数即可 |

## 6. 两种安装形态

| 形态 | 内容 | 用法 |
|---|---|---|
| **Windows 安装程序** `SECS Simulator_<版本>_x64-setup.exe` | Tauri 壳(前端内嵌) + 原生 exe 后端 | 安装后打开直接进界面,默认连本机后端(无需 JVM);`scripts/package.ps1 -Target Windows` 产出 |
| **Linux 服务端** `secs-sim-server-<版本>-linux.zip` | 模块 jar + 前端 + `start-server.sh` | 部署在 Linux 设备机,`./start-server.sh` 以 server 模式对外(目标机需 JDK 25+);`scripts/package.ps1 -Target Linux` 产出 |

远程场景:设备在 Linux 机(A)解压服务端包并 `./start-server.sh` 启动;
操作者在 Windows 机(B)安装程序,打开后点右上角「连接」,填 A 机地址(`http://A 机 IP:8080`)
保存——界面仍由 B 机的壳提供,但配置、批量、曲线、报文全部操作 A 机,本机后端自动停止。
要切回本机,同一对话框里清空地址保存即可。
本机场景则完全不依赖网络:安装程序内置后端与前端,打开即用。
