# M6-c 验收报告 · 主机动态定义报告（S2F33 / S2F35 / S2F37）

## 交付

| 组件 | 内容 |
|---|---|
| `HostReportTable` | 纯数据结构：主机定义的报告（RPTID→VID）、链接（CEID→RPTID）、启用状态；不依赖协议与 JSON |
| 会话路由 | S2F33 → S2F34、S2F35 → S2F36、S2F37 → S2F38；ACK 码 0=接受 / 1=格式非法 |
| S6F11 组装 | 先问覆盖层：主机定义过就用主机的，没碰过就用本地配置；**主机定义的报告不注入 UNIT_ID** |
| 禁用语义 | S2F37 禁用后事件**直接丢弃**并计入 `skipped`，不缓存（缓存会在重新启用时涌出一批过期事件） |
| 计数器 | `counters()` 增加 `skipped` / `hostReports` / `hostLinks` |

语义细节见 [ADR 0006](adr/0006-dynamic-reports.md)。

### 用例

`HostReportTableTest`（6 个，纯数据）：定义/读取、空列表即删除、链接覆盖、清空全部、
禁用单个事件不影响其它事件、整体禁用与恢复。

`SessionDynamicReportTest`（4 个，真链路）：

| 用例 | 断言 |
|---|---|
| S2F33 把本地 3001（3 个值）改成只有 TEMP_PV | 上报的报告只有 1 个值，**且没有注入 UNIT_ID** |
| S2F33 定义 3100 + S2F35 把 2001 链到 3100 | 上报的是 3100，值是 UNIT_ID=1 |
| S2F37 禁用 2001 | 该事件不上报且 `skipped` 计数为 1；同设备另一个单元不受影响；重新启用后恢复 |
| S2F33 传空列表 | 回落到本地配置（3 个值、含 UNIT_ID） |

## 一个实现细节值得记下

主机自定义报告时**不能注入 `UNIT_ID`**。本地配置会在报告首位插单元号方便区分腔体，
但主机声明的是精确的 VID 列表——多插一个值，主机按自己的定义解析整条报文就会错位。
这类错误不会报错，只会让主机的数据全部偏移一格。
