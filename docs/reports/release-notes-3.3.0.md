# 3.3.0 发布说明

发布日期：2026-11-19
类型：功能版（新增批量新建设备端点；批量新建的语义变更；无数据库 schema 变更、无破坏性 API 变更）

3.2.0 之后围绕「一次把一批设备建对」重做了新的批量新建：原来一批设备共用一份配置、
设备名相同，清单里分不清谁是谁；现在一台设备一份配置，名字是「批次前缀 + 序号」，
名字重复整批拒绝。同期修掉了 CI 在 GitHub 上一直红的两个根因，并清掉界面文案门禁的
存量违规。升级即生效，无需迁移；旧的 `POST /api/v1/sessions/bulk` 保持原语义不变。

## 批量新建设备：一台一份配置

3.2.0 的批量新建是「一份基础配置 + 运行期覆盖开多个会话」：设备名一批全一样，
Device ID 逐台递增，清单里几台设备看起来像同一台，删一台、点开一台都说不清是谁。

| | 3.2.0 | 3.3.0 |
|---|---|---|
| 配置 | 一批共用 `前缀-模板id-base.json` | 每台一份独立配置，可分别编辑 / 重载 / 删除 |
| 设备名 | 一批同名 | 前缀 + 序号（`dev-1`、`dev-2`…），全库唯一 |
| 序号来源 | 固定从 1 起 | 新增「起始序号」，从任意值起算 |
| Device ID | 逐台递增 | 恒为 0（同一批设备同一角色） |
| 端口 | 起始端口逐台 +1 | 不变 |
| 立即启动 | 批量恒启动 | 新增开关，可只建设备不启动 |
| 重名 | 建到一半才发现 | **整批拒绝**，一台都不建 |

- 新端点 `POST /api/v1/devices/bulk`：`{template, prefix, start, count, portBase, bindHost,
  passive, startNow}`，逐台回 `name / deviceName / port / deviceId / sessionId / sessionError`。
- 状态码分得清：全部建成 `201`；设备名重复 `409` 并在 `conflicts` 里列出撞上的文件名；
  一台都没建成 `422`；入参本身不合法（前缀带斜杠、台数越界…）`400` 并在 `problems` 里说明原因。
  「名字被占」与「参数写错」是两件事，混成一个状态码会让人去改一个没问题的地方。
- 名字同时是配置文件名与设备名，两者同源：清单按配置名去重、编辑器按设备名展示，
  不同源就会出现「点开 A 改的是 B」。
- 重名整批拒绝的理由：建到第 4 台才发现撞名，会留下三台半成品让人自己收拾；
  宁可整批重来，改一下前缀或起始序号即可。
- 三道唯一性防线：界面提交前比对清单（撞名在弹框里就变红字、不发请求）→ 后端整批校验
  （大小写不敏感）→ 存储层 `idx_device_name_live ON device(name) WHERE deleted_at IS NULL` 兜底。
- 会话起不来的那台仍算建成：设备已保存，界面以「停止」态出现，点「启动」可再试；
  原因随 `sessionError` 回来，不再让整批跟着失败。

## 缺陷修复

| 问题 | 修复前表现 | 修复后 |
|---|---|---|
| 起始序号留空悄悄变 0 | 数字输入框空值经 `Number('')` 得到 0，名字变成 `dev-0`，界面不报错 | 空白视为非法输入，提交前拦下并提示 |
| 批量参数错误被报成「名字已被占用」 | 前缀带斜杠时回 409 + `conflicts`，用户会去改一个没问题的名字 | 回 400 + `problems`，直接指出前缀不能含空白 / 斜杠 / 引号 |

## CI 恢复绿

GitHub Actions 自 v3.2.0 之后一直红，两个独立根因：

| Job | 根因 | 修复 |
|---|---|---|
| 契约检查 | `scripts/live-backend.ps1` 含中文但缺 UTF-8 BOM，BOM 门禁 `exit 1`（PowerShell 5.1 会把无 BOM 的 UTF-8 按 ANSI 读，中文乱码） | 补 BOM |
| 后端（ubuntu + windows） | `HttpApiServerTest` 4 个用例仍在请求已下线的 v1 手动触发端点，拿 404，与断言的 202 / 409 / 400 全部不符 | 迁到 v2 设备域；并补一条「中文文本必须 400」（SECS-II 的 A 类型只允许 US-ASCII） |

## 界面：清掉文案门禁的存量违规

`check-ui-words.ps1`（设计 §3.5）从 6 处失败回到全绿，只改用户可见文案、不动注释：

| 位置 | 原写法 | 现写法 |
|---|---|---|
| 事件计划的计划 id 说明 | 启停/试跑**台账**按它归属 | 启停/试跑**记录**按它归属 |
| 版本历史页脚注 | 版本历史来自后端 `config_revision` **快照**（新→旧） | **版本按时间从新到旧排列** |
| 连接页保存确认 / 页内说明 | **钉值**、计划启用态、周期进度… | **手动设定的变量**、计划启用态、周期进度… |
| 分段保存后的提示 | 事件计划与**钉值**已重置 / 有 N 个**钉值**因变量被删而失效 | 事件计划与**手动设定的变量**已重置 / 有 N 个**手动设定的变量**因被删而失效 |

版本历史那句顺手去掉了界面上的后端表名；「因变量被删」读起来像数学术语，改成「因被删而失效」。

## 兼容性

- 数据库 schema 不变，沿用 3.x 的 `config.db` / `runtime.db`，升级不需要迁移。
- `POST /api/v1/sessions/bulk` 语义不变，仍可用于「一份配置开多个会话」（多实例压测等场景）；
  界面上的批量新建改走新端点。
- 既有配置、计划、钉值与区域分组原样保留。
