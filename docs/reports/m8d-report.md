# M8-d 验收报告 · SML 报文渲染

## 问题

协议层只提供 `Secs2.toJson()`，没有 SML 输出。报文面板原先显示的是：

```json
{"L":{"L":[{"U4":3001},{"L":[{"U4":1},{"F4":[178.2]},{"F4":[0.11]}]}]}}
```

对做过 SECS 的人来说这几乎不可读——层级藏在对象的键里，数据类型藏在数组里。

现在显示：

```
<L[2] <U4 2001> <L[1] <L[2] <U4 3001> <L[3] <U4 1> <F4 178.2> <F4 0.11>>>>>
```

## 交付

| 项 | 内容 |
|---|---|
| `SmlRenderer` | `Secs2 → SML` 只读渲染器，递归处理 LIST / ASCII / 数值 / 二进制 / 布尔 |
| 会话 | 发布 `MessageEvent` 时用 SML 文本作为 `body`（原来用 JSON） |
| 防御 | 深度上限 32 层、单点异常只影响该节点（显示 `?`），渲染永不抛 |

支持的形态：

| SECS-II | 渲染 |
|---|---|
| `L[n]` | `<L[2] ...>` |
| `U4` 多值 | `<U4 1 2 3>` |
| `A` | `<A "CH1">` |
| `B` | `<B 0x01>`（补零到两位，正数大写） |
| `BOOLEAN` | `<BOOLEAN 0x01>` / `0x00` |
| 空列表 | `<L[0]>` |
| `null` | `<>` |

## 实测

| 项 | 结果 |
|---|---|
| `mvn verify` | BUILD SUCCESS |
| 单元测试 | **152 个**（core 79 + app 16 + api-http 14 + runtime 12 + cli 31），全绿 |
| 原生镜像 | `secs-sim.exe` 13.0 MB，原生端到端 2 个用例 2.0 s |

### 用例（`SmlRendererTest`，6 个）

列表 + 标量、空列表、嵌套列表、二进制与布尔、单数据项多值、`null` 与中文内容。
