# 3.0.1 发布说明

发布日期：2026-11-13
类型：缺陷修复版（无新功能、无破坏性变更）

3.0.0 发布后做的一轮三域全量代码评审（后端领域逻辑 23 处 / HTTP 层 21 处 / 前端 34 处），
高危全部修复，中低危按性价比修复了一部分。升级即生效，无需迁移——
`config.db` / `runtime.db` 的 schema 没有变化。

## 必须升级的理由（用户可见的缺陷）

| 问题 | 触发方式 | 修复前表现 | 修复后 |
|---|---|---|---|
| Trace 采集永久停发 | 配 `s6f1Wbit=true` → 断开 → 重连 | 每帧 S6F1 发送被拒（ACK 池在断开时已关闭），S2F24 照样回成功，界面看不出原因，只能重启进程 | 每次发送现取当前 ACK 池 |
| 重载失败丢运行态编辑 | 钉值/运行时计划/目录编辑后点「重载」，而配置恰好非法或端口被占 | 编辑已被删除，旧会话虽然恢复，钉值与计划正文永久丢失 | 失败回滚并重放进恢复的会话 |
| 主机详情页状态不刷新 | 停在主机详情页，同时有设备在发报文 | 页面 2 秒轮询的定时器被 150ms 一次的重渲染反复重置，相位/重试次数/「设置待生效」横幅永不更新 | 轮询只依赖稳定的刷新回调 |
| CSV 导入假成功 | 工作台导入含不存在配置的 CSV | 全部失败也报「已按配置导入 N 个会话」 | 按 HTTP 201 计数，失败/跳过分开报 |
| 切设备首帧拿上一台的数据 | 在设备 A 的「事件与报告」页点侧栏设备 B | 首帧显示 A 的 CEID/计划；这一帧里点「删除」动的是 A 的数据 | 换会话先清明细，写操作闭包锁定当前设备 |

## 其他修复

**后端**
- 计划执行摘要节流窗口与发布交错时丢一条（锁内先摘表再取快照）。
- 幂等判重改 `compute` 原子操作；清理改批量（计划周期 1ms 时原来每次执行全表扫描）。
- `BurstRunner.close` 补主机级压测状态，停机不再往断链发报文。
- 创建主机不再经共享字段回读实例 id（并发创建会串号），改为随结果返回。

**HTTP 层**
- SSE 帧按规范逐行加 `data:` 前缀，载荷里的换行不再能伪造事件字段；事件名白名单化。
- `POST /api/v2/hosts` 等端点收到「合法 JSON 但不是对象」（`[]`、`"x"`、`null`）统一 400，不再 500。
- 主机连接/断开/应用设置不再无论成败都回 200，按结果回 200 / 404 / 409 / 502。
- `POST /api/v1/sessions/{id}/host-sim` 请求体超限不再被当成「没给远程目标」而连到本机设备。
- 路径里非数字的 CEID/SVID/RPTID 从 404 改为 400 `bad-id`；`?limit=abc` 从静默用默认值改为 400。
- 两条 SML 发送路径上限统一 64 KiB；发送失败状态码统一 502（文档同步）。
- `DELETE /api/v1/sessions/{id}/`（尾斜杠）语义与不带斜杠一致。
- 纯 API 模式（无 `--web-root`）未知路径回 JSON 404。
- 绑定非回环地址时启动日志明确告警（本工具无账号体系，恒 ADMIN）。

**前端**
- 路由子页名按各区合法清单收口：旧书签/手输的非法子页不再渲染出空面板，回落到该区首页。
- 报文合并（150ms 高频路径）不再每次全量排序；主机收发记录渲染上限 500 行，压测时页面不再卡死。
- 模态浮层打开时全局快捷键只放行 Esc（确认框开着按 1..9 不再在背后跳页）。
- 审计「载入更早」与改过滤并发时，旧过滤的记录不再混进新列表。
- 本地偏好设置：写入移到提交后（React 更新函数保持纯函数）；另一标签页删除键时回默认值。
- 保存配置的提示只说「已保存」，是否生效由重载路径如实上报（成功 N / 失败 N）。

## 升级步骤

- **桌面版**：直接覆盖安装 `SECS Simulator_3.0.1_x64-setup.exe`（工作目录与两个 SQLite 库向前兼容）。
- **服务端（Linux/JVM）**：解压覆盖 `secs-sim-server-3.0.1-linux.zip`，重启进程即可。
- 3.0.0 → 3.0.1 无配置迁移；从 2.x 升级请先看 [3.0.0 发布说明](release-notes-3.0.0.md) 的迁移段。
