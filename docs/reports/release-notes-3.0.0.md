# SECS Simulator 3.0.0 发布说明

发布日期：2026-11-13

## 下载

| 平台 | 文件 | 适用场景 |
|---|---|---|
| Windows | `SECS Simulator_3.0.0_x64-setup.exe` | 现场调试：装完即用，内置原生后端（`secs-sim.exe`），不需要 JVM |
| Linux | `secs-sim-server-3.0.0-linux.zip` | 部署在设备所在网段的服务端，由 Windows 端远程连接；需要 JDK 25+ |

## 这版是什么

3.0.0 是一次**领域模型重构**，不是补丁版。三件事变了：

1. **配置与运行态搬进 SQLite**（`config.db` + `runtime.db`，ADR 0017）。设备/主机从"一个文件一个实体"变成带事务、版本历史、结构化查询的持久对象；旧的 `<work-dir>/*.json` 在首次启动时自动迁移，原文件留在 `legacy/`。
2. **"关闭"不再是"删除"**。断开只断链路，设备行保留、可一键重连；真正的销毁是独立动作。
3. **界面按操作对象重组**（3.0 IA）。侧栏三组；设备域与主机域各分「配置区 / 运行区」，配置是"我定义了什么"，运行时是"现在正在发生什么"。

升级不需要改配置：老配置自动迁移，`--work-dir` 等启动参数不变。

## 三个必须先知道的行为变化

| 变化 | 之前 | 现在 |
|---|---|---|
| 设备列表里的「关闭」 | 关闭并**移除**该设备 | 改叫「断开」，只断链路；行留在列表里，按钮变成「连接」 |
| `DELETE /api/v1/sessions/{id}` | 删除会话 | 转 `POST /api/v2/devices/{id}/link/disconnect`，响应带 `Deprecation: true` 与 `Sunset: 2027-06-30` |
| 运行时编辑（钉值/计划/目录改动） | 重启即丢 | 成功那一刻写进 `runtime.db`，重启按依赖顺序恢复 |

`Sunset` 之前的两个大版本内 v1 端点继续可用，但语义已经是"断开"。

## 新能力

### 配置与运行态分离

- `config.db`：设备、主机、模板、报文模板、计划动作、报警、报告、SVID 的**单一事实源**。每次保存产生一个配置版本，可看差异、可回滚。
- `runtime.db`：钉值、计划启用态、运行时计划正文覆盖、运行时目录编辑、链路相位、执行台账。**运行态改动不回写配置**——改配置仍然要显式保存。
- 启动时按依赖顺序重放运行态：目录编辑（重建模型）→ 计划正文覆盖 → 钉值 → 计划启用态。顺序反过来会丢东西（先恢复钉值，运行时新增的 SVID 还不在模型里，那次钉值就被拒了）。
- 上次进程留下的 `CONNECTED / LISTENING / STARTING` 相位在启动时收敛成 `DISCONNECTED`，不会显示一堆"连着但其实早就死了"的设备。

### 事件计划执行器

- 每条计划可以挂多个动作：`s6f11` / `sml` / `alarm` / `terminal` / `trace`，各动作可单独指定 W 位。
- 离线三策略：`skip`（默认）/ `queue`（有界 256，重连按 FIFO 补跑）/ `fail`。
- 发送失败策略：`keep`（默认）/ `rollback`（仅当本次全为 set/add 且此后未被其它触发触碰，否则记 `rollback_skipped`）。
- **执行台账**：每次触发落一条记录（`GET /api/v2/devices/{id}/runtime/executions`），带状态、报文条数、SVID before→after、耗时。
- **SSE `plan-fired`**：同一设备 200ms 窗口内的执行摘要合并成一帧，`FAILED` 立即推、不合并。明细仍逐条落库，时间轴按需拉。

### 主机域独立

- 主机实例不再依附会话：`/api/v2/hosts/**` 自成命名空间，可建多台、各连各的（本机设备或远程 SECS）。
- 主机模板可保存、复用；主机可断链（设置保留）→ 改设置 → `apply` 生效。
- 主机侧也有独立的收发记录、报文模板、Trace 设置、采集设置。

### 智能工具

- 命令面板（`Ctrl/Cmd + K`）、可拖动侧栏宽度、主题与密度切换、快捷键表（`?`）。
- 报文监控支持按流/功能/方向过滤、SML 与结构视图切换、导出 NDJSON。

## v2 API

设计文档 §2.5 定下的命名空间全部落地：

| 命名空间 | 用途 |
|---|---|
| `/api/v2/devices/{id}/link/**` | 配置 → 运行的分界：`connect` / `disconnect` / `reload` |
| `/api/v2/devices/{id}/runtime/**` | 纯运行态：计划、目录编辑、钉值、手动报文、报警、手动触发、台账 |
| `/api/v2/hosts/**` | 主机实例与其运行态 |
| `/api/v2/host-templates/**` | 主机模板 |

状态码口径统一：`201` 新建、`200` 改/删、`404` 对象不存在、`409` 状态冲突（还连着、内置不可删、不可重载）、`400` 请求不合法、`502` 对端/链路失败。`docs/openapi.yaml` 覆盖 72 个 path。

## 本版修复（发版前全量评审）

一轮全量代码评审收敛出的问题，集中在"状态码会误导客户端"和"并发下的静默丢失"两类：

### HTTP 契约

- 请求体是合法 JSON 但不是对象（`[]`、`"x"`、`null`）时，以前 500；现在 400。
- `POST /v2/hosts/{id}/connect|disconnect|apply` 以前无论成败都回 200——客户端按状态码判断会把"连接失败"当成功，界面显示已连接、实际一条链路都没建起来。现在按结果回 200/404/409/502。
- 保存失败、删除失败、模板 id 重复以前一律报 404「不存在」，会让人去重建一个明明还在的实例；现在 404 只用于真的不存在，冲突回 409，其它失败回 502。
- `GET /v2/hosts/{id}/messages` 按文档支持 GET（以前只挂在 POST 分支，curl 按文档发 GET 得 404）；`limit` 非法或越界回 400。
- `?limit=abc` 以前静默用默认值（以为取 10 条、实际拿到 50 条），现在 400。
- 路径里非数字的 CEID/SVID/RPTID 以前报「没有这个对象」，现在 400 `bad-id`。
- `POST /sessions/{id}/host-sim` 请求体超限以前被当成"没给目标"而**静默连到本机设备**，现在 400 `body-too-large`。
- 两条 SML 发送路径的上限统一 64 KiB（以前 4 KiB vs 64 KiB，长报文只有一条能发）。
- 静态资源路径里的 `%00` 不再 500。

### 并发

- 设备链路 `open/disconnect/close` 互斥：并发调用不再泄漏 socket、不再双心跳双发。
- 主机连接的失败路径统一善后：以前连接失败只关连接不清字段，`autoReconnect` 从此永久失效且线程泄漏。
- 报文缓冲遍历与写入互斥：报文正在流动时查收发记录不再抛并发修改异常（500）。
- 执行台账：队列满时丢当前条目并计数（不再自旋）；停机前把剩余批次冲完（以前最多丢 4096 条）；清理旧记录不再误删保留窗口内的最新行。
- 计划执行摘要不再丢（窗口冲刷与发布交错时那条摘要会永久消失）；停机后的摘要也照发。
- 计划幂等判重改为原子操作（并发同键不再可能双发）；清理从"每次执行全表扫"改为批量（计划周期最小 1ms，原来是 O(n²)）。
- 心跳线程、Trace 管理器、会话注册失败、SSE 断开回调各自的资源泄漏已修。

## 已知问题

- Windows 安装包首次启动会把 `native/sqlitejdbc.dll` 释放到工作目录，首次启动比之后慢 1–2 秒。
- 前端部分编辑操作仍走 v1 路径（`/api/v1/sessions/**`），与 v2 端点语义一致；计划在 v1 退役时一起切。
- 台账保留策略：5000 条 / 7 天，启动时跑一次裁剪，运行期每小时增量清理尚未挂上。

## 升级步骤

1. 备份 `<work-dir>`。
2. 装新版本（Windows 直接覆盖安装；Linux 解压新包到新目录）。
3. 首次启动会自动迁移：旧 `*.json` → `config.db`，原文件移入 `legacy/`。
4. 打开界面确认设备列表与主机实例都在；设备首次都是「已断开」，点「连接」即可。

迁移是单向的：回到 2.x 需要把 `legacy/` 里的 JSON 放回原位。
