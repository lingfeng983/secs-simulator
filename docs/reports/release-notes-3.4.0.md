# 3.4.0 发布说明

发布日期：2026-11-23
类型：功能版（配置区交互重做：分段保存 + 行内确认即落盘；结构改动不再要求先停设备。无数据库 schema 变更、无破坏性 API 变更）

3.3.0 之后这一轮只做一件事：把配置区从「一页一个保存按钮、改完必须自己记得按」改成
**按页保存、按段生效、行内确认即落盘**，并顺手拆掉一条用起来很别扭的守卫——
改单元结构不必再先把设备停下来。配置文档格式没变，`events.maxPerSec` 这些键还在原处，
只是界面入口换了页；升级即生效，不用迁移。

## 一、三个页签改名

| 旧名 | 新名 | 管什么 |
|---|---|---|
| 连接 | **链接配置** | HSMS 链接参数（`session`）：模式、地址、端口、Device ID、超时、Trace 容量 |
| 结构 | **结构配置** | 号段规划、事件发送口径、单元标识（`structure` + `throttle`） |
| 配置原文 | **全量配置** | 整份 JSON 原文：格式化、校验、保存、导入/导出、版本差异 |

改名的理由很实际：原来「连接」既指链路又容易和顶栏的「连接后端」混，「结构」看不出
里面还有事件发送，「配置原文」听起来像只读视图，其实它是唯一能整份改的入口。

## 二、两种保存节奏，页面自己写清楚

同一页里再也不会出现「弹窗点了确定，还要记得去顶部按保存」这种两步动作：

| 页面 | 保存方式 | 提交的段 |
|---|---|---|
| 链接配置 | 表单末尾「保存」（启动中会先确认重启会话） | `session` |
| 结构配置 · 设备全局 | 标题行右侧「保存」 | `structure` + `throttle` |
| 结构配置 · 单元 | 新增 / 编辑 / 删除，确认即保存 | `structure` |
| 变量配置 | 新建 / 编辑 / 删除，确认即保存 | `svids` |
| 设备常量 | 同上 | `constants` |
| 晶圆属性 | 同上 | `context` |
| 事件与报告 | 三张表，确认即保存 | `ceids` / `reports` |
| 工艺周期 | 标题行右侧「保存」（整份周期定义配完按一次） | `cycle` |
| 事件计划 | 新建 / 编辑 / 删除，确认即保存 | `plans` |
| 全量配置 | 工具条「保存」 | 整份原文 |

- 顶部不再常驻「本页有未保存改动 / 其它页 N 段未保存」两条提示——页签上的小圆点已经
  表达同一件事，而常驻提示会跟着页面一直挂在最显眼的位置。
- 结构化页收掉了「校验 / 重新载入」两个按钮：保存路径本来就会先校验（不通过就不落盘），
  重新载入在「全量配置」页仍然保留（那里才有丢草稿的语义）。**全量配置**页的校验、
  重新载入、导入、导出、查看差异全部收进编辑区上方同一行工具条。

## 三、结构改动不再要求先停设备

以前改一个单元名要先停设备：后端有一条 `not-offline` 守卫，会话端口一开就拒保存。
代价是停设备会清掉运行态（钉值、计划启用态、周期进度），为了改个名字付这个价不划算。

现在：

- 后端删掉这条守卫，结构段随时可保存落盘；保留的另一条守卫不变——**运行中的周期正在
  引用的 SVID / 晶圆属性仍禁改**（那会真的把跑着的曲线改坏）。
- 前端保存时把 `structure` 从热应用列表里摘掉：文件落盘，运行中的设备**继续跑旧模型**，
  提示语明确写「结构改动在设备重启后生效」。
- 其余段照常热应用（变量 / 报告 / 事件 / 计划 / 周期 / 常量 / 限流），主机连接不断；
  `session` 段保存仍按新参数重建会话，这一点没变。

代价要说清楚：从保存到重启设备之间，**磁盘上的结构与正在跑的结构会短暂不一致**。
这是有意的取舍——宁可让人看到一句「重启后生效」，也不要让改一个单元名必须先清空运行态。

## 四、「事件发送」三项搬到结构配置

`events.maxPerSec`、`s6f11Wbit`、`s6f1Wbit` 从「事件计划」页搬到「结构配置」页的设备全局里，
`throttle` 段随之归结构页（`PAGE_SECTIONS` 一并调整，页签小圆点跟得上）。

这三项是 `events` 段的**发送口径**，不是某一条计划的参数；和计划列表放在一起时，
每次都要解释「这个不是这条计划的」，搬走之后「事件计划」页只剩计划本身。

## 五、事件与报告页重做

原来是「按单元分块」：每台单元两张表，单元一多就要滚很久才能确认某条报告属于谁。现在三张表：

| 表 | 内容 | 说明 |
|---|---|---|
| 全局 CEID | 跨单元事件 | 引用报告写「单元名.报告名」 |
| 报告（RPT） | 所有单元的报告合并 | 有「所属单元」列，可按列搜索、排序 |
| 事件（CEID） | 所有单元的事件合并 | 引用同单元报告名 |

新建/编辑走弹窗（字段校验在弹窗里给出），删除二次确认；每次确认后直接保存落盘，
保存结果与「未生效」的原因留在页面上。

## 六、其它调整

- **链接配置**：T3–T8 超时与 Trace 容量不再折叠在「高级」里，直接平铺；13 个字段一屏能核完。
  保存按钮挪到表单最后——改完一口气按一次，而不是先按保存再往下改。
- **工艺周期**：「+ 周期事件」与「保存」并排放在标题行右侧；删掉「移除周期段」按钮
  （删整段去「全量配置」改原文，那个入口本来就存在）；删掉「N 片 × M 条 = K 条计划」的
  编译期展开提示，这条信息在运行区台账里能看到真实结果。
- **事件计划**：删掉「计划口径」那张当前运行表（运行态统一到运行区「事件执行」页看）；
  预览说明改成「按当前已保存的计划重放」。
- **概览**：删掉「自动连接：后端未提供」那一行——列一个不存在的开关只会让人去点它。

## 七、兼容性与升级

- 配置文档格式不变：`events.maxPerSec` / `s6f11Wbit` / `s6f1Wbit` 位置不变，只是入口换页。
- API 变更只有一处：`POST .../sections` 不再可能返回 `409 not-offline`，其余状态码与字段不变。
- 无数据库 schema 变更；版本号统一 3.4.0（9 个 pom、两个 `package.json`/lock、
  `tauri.conf.json`、`Cargo.toml`/`Cargo.lock`、`BuildInfo.VERSION`）。
