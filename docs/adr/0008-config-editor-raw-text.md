# ADR 0008 · 配置编辑器走原始 JSON 文本

- 状态：已接受
- 日期：M12
- 影响范围：`secs-runtime` 的 `ConfigStore` / `ConfigTemplate` / `SessionLauncher`，`secs-api-http` 的 `ApiContext` / `HttpApiServer`，前端「配置编辑器」面板

## 问题

要把配置读出来、改一改、存回去，最省事的做法是：

```
读文件 → 解析成 SessionConfig → 改模型 → toJson → 写回
```

这条路在模型与文件一一对应时没问题，但配置是**人手写**的，现场的 JSON 里
常有模型里没有的键（预留字段、第三方工具塞的注释性字段、还没实现的 Schema v5 子集）。
模型往返会**静默丢掉**它们。

更糟的是：用户点一次"保存"，磁盘上的文件就变了个样，
而他并没有要求任何转换。**一个保存动作悄悄改掉用户的配置，比报错糟糕得多。**

## 决策

### 1. 编辑器操作的是原始文本，不做模型往返

`GET /api/v1/configs/{name}` 返回的是文件原文（`{"name":…,"text":…}`），
`PUT /api/v1/configs/{name}` 的请求体就是配置原文，**服务端逐字节写回**。

多写的键、空格、缩进、换行都不会被动过。编辑器里看到的和磁盘上的是同一份。

模型往返仍然保留，但只用于**生成一份新配置**（`ConfigTemplate.skeleton`）——
那条路上本来就没有"用户的原文"要保护。

### 2. 先校验再落盘，校验判据与真实启动路径一致

`ConfigStore.validate` 走的是 `SessionLauncher.prepare` 的同一条路：
解析 → 编译设备模型 → 建模板图。

只编译设备是不够的：模板表达式写错一样起不来，而用户是从编辑器里按下"校验"的，
他要的就是"这份配置能不能起得来"这句话的答案。

**校验不过时原文件一个字节都不动。** 存一份编译不过的配置等于给下一次启动埋雷。

### 3. 校验与保存分成两个动作

`POST /api/v1/configs/{name}/validate` 只校验不落盘，`PUT` 才写盘。

想确认改动能不能编译，不该被迫先覆盖一份能用的配置。

### 4. 写盘是原子的

先写同目录临时文件，再 `ATOMIC_MOVE` 整体替换（不支持时降级为 `REPLACE_EXISTING`）。

直接 `writeString` 到目标文件的话，中途崩掉会留下半截 JSON——
而这份配置正是设备启动时要读的东西。

### 5. 名字规则只有一份出处

`ConfigStore.requireFileName` 是唯一实现，`SessionLauncher`（建会话）也调它。

接口给的是"名字"不是"路径"：挡住 `/ \ .. :`，否则一次 API 调用就能把服务器上
任意 JSON 当配置读进来试。两处各写一份校验，迟早会出现"这里能读、那里读不了"
这种只在一条路径上复现的现场问题。

### 6. 保存是 operator，读与校验是 viewer

分级依据仍是 ADR-0007 的"这个操作会不会改变设备状态"。
配置决定了下一台设备长什么样，改它属于会改变设备状态那一类，
和触发 CEID、增删会话同属一级。

### 7. 改配置不会让已在跑的会话自动改变

会话是启动那一刻把配置读进内存的。存完要在会话表点"重载"才生效，
服务端日志会直接点名是哪个会话还在用旧配置。

不自动重载是有意的：重载会换掉设备实例，正在跑的通信会断，
这不该由一次"保存"顺手做掉。

### 8. 模板表单是原文之上的投影，不是第二份配置

「曲线 / 实例参数」结构化表单读取的是**当前原文解析出来的 JSON**，
不是 Java 模型，也不另外保存一份表单状态：

1. 原文不是合法 JSON，或 `templates` 形状不对时，表单直接禁用并指出字段路径；
2. 表单编辑的是克隆后的 JSON 文档，改完把整份文档重新序列化（2 空格缩进）；
3. JSON 里模型不认识的键仍然保留；但**缩进、空行与键的排版会被统一**——
   这是结构化编辑的代价，界面上必须写明；
4. 改模板 id 会同步实例的 `template` 引用；改实例 id 会同步组合表达式里的
   `in.<实例>.`；删除仍被实例引用的模板会被拒绝，而不是默默留下悬空引用；
5. 表单只改草稿，不落盘；「保存」仍走 ADR-0008 的"先校验再原子写盘"。

不用后端模型往返，是因为模型只认识 Schema 的一个子集；用原文 + 前端 JSON 投影，
既能让表单看到 `templates` 的真实结构，又不会把模型不认识的键写丢。

## 后果

- 编辑器不会改坏用户的配置；模型里没有的键也能安全地留在文件里。
- 校验的判据是"这份配置能不能起得来"，而不是"这份 JSON 能不能解析"。
- 配置文件里出现的任何非 ASCII 内容都能原样往返（HTTP 响应固定 UTF-8）。
- **模板表单已落地**：曲线（含 step/pwl 关键帧）、组合模板输出表达式、
  实例的 SVID 绑定与参数都能在界面上改；表单之外仍保留原文编辑器。
  结构化编辑会重排缩进，纯文本编辑仍逐字节保真。
- **曲线预览的截断不再静默**：`GET /api/v1/preview` 返回
  `svidTotal` 与 `truncated`，界面会明说"共 N 个 SVID，只显示前 32 条"。
- 配置目录**不支持子目录**：接口只收文件名。
