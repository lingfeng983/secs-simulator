# ADR 0002 · 领域模型与 ID 空间

- 状态：已接受
- 日期：M1
- 影响范围：`secs-core`

## 问题

一台设备（一个 SECS 端口）可能有多个单元（腔体 / 工位 / 装载口），
每个单元有自己的一组 SVID 和 CEID。主机侧报文里**只有数字**，
没有"这是哪个单元"的字段。因此：

1. SVID / RPTID / CEID 必须**全局唯一**；
2. "某个事件属于哪个单元"必须靠**配置期的唯一归属**来保证；
3. 一份单元配置要被多个单元复用，但解析出不同的号段。

## 决策

### 1. 定义是"槽位相对"的，绝对 ID 由编译器解析

`UnitSpec` 里所有定义只写**段内偏移**（`SvidDef.offset`），绝对 ID = 段起点 + 偏移。
段起点 = `base + (position - 1) × stride`。

这样"三腔体同款配置"就是同一份 `UnitSpec` 实例化三次，
而不是三份手抄的配置——后者一定会漂移。

### 2. `unitPosition` 与 `UnitId` 是两件事

- `unitPosition`：单元在列表中的位置，决定号段，从 1 开始。
- `UnitId`：写给主机看的语义编号，通常由 `UNIT_ID` 这个 SVID 上报。

编号可以跳号（1、3、7），但号段只按位置推进。混用这两者会导致
"删掉一个腔体后另外两个的 SVID 全变了"，那是灾难。

### 3. 编译顺序固定：全局 SVID → 单元 → 全局 CEID

报告可能引用设备级共享 SVID，设备级 CEID 可能引用任意单元的报告，
所以顺序必须是：先登记全局 SVID，再编译单元（解析 SVID / 报告 / CEID），
最后编译全局 CEID。否则"跨单元引用"会因为目标尚未登记而误报。

### 4. 一次报出全部问题

`EquipmentCompiler` 收集所有 `Issue` 后再返回，不短路。
改配置的人希望看到 5 条错误一起出现，而不是改一条跑一次。

### 5. 错误代码稳定

`Issue.code` 是机器可读的稳定标识（`DUPLICATE_SVID`、`STRIDE_TOO_SMALL_SVID`…），
前端按代码高亮字段，测试按代码断言。文案可以改，代码不能改。

## 已知取舍

- 全局 CEID 引用报告时，短名可能歧义，因此提供 `单元名.报告名` 限定写法；
  歧义时返回 `AMBIGUOUS_REPORT_REF` 而不是随便挑一个。
- 段步长必须大于最大偏移（`offset >= stride` 即报错），不做自动扩张：
  号段是设备规范的一部分，不能由工具猜。
