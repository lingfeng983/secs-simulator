# ADR 0006 · 主机动态定义报告（S2F33/S2F35/S2F37）

- 状态：已接受
- 日期：M6-c
- 影响范围：`secs-app` 的 `HostReportTable`、`secs-runtime` 的 S6F11 组装

## 问题

E30 允许主机用 S2F33/S2F35/S2F37 在运行时定义"报告有哪些变量""哪些事件挂哪些报告""哪些事件启用"。
协议层的 `Gem` 只更新 ACK 码，**不保存任何定义**。

因此仿真器必须自己决定：主机下发的定义与本地的 Schema v4 配置**谁是主**。

## 决策

### 1. 本地配置是基线，主机定义是覆盖层

- 主机定义过的 RPTID / CEID，**以主机为准**；
- 主机没碰过的，仍按本地配置；
- 主机**删除**某个定义（S2F33/S2F35 传空列表），该条目回到本地配置，而不是变成"没有报告"。

理由：仿真器的首要用途是"让主机跑通"。若主机清空一次报告就导致设备永远发不出 S6F11，
现场只会看到"设备坏了"，而真实设备的本地逻辑通常仍会保留自己的默认报告。

### 2. 主机定义的报告**不注入** `UNIT_ID`

本地配置里我们会在报告首位注入单元号，方便主机区分腔体。
但主机自定义报告时，它声明了精确的 VID 列表——多插一个值会让整条报文错位。
**主机定义优先，注入只作用于本地配置的报告。**

### 3. CEID 被禁用后，事件**直接丢弃**，不缓存

S2F37 禁用事件上报的语义是"不要上报"，而不是"稍后补发"。
缓存会在重新启用时瞬间涌出一批过期事件，主机侧时间序列直接失真。

### 4. ACK 码自己发，不过 `Gem`

`Gem` 的 `DRACK/LRACK/ERACK` 枚举只有 OK，无法表达"格式非法"。
这三个应答本质是一个字节，直接 `comm.send(primary, 2, 34/36/38, false, <B code>)` 更清楚：

| 码 | 含义 |
|---|---|
| 0 | 接受 |
| 1 | 格式非法（结构不对/ID 无法解析） |

## 后果

- 主机的自动配置流程（S2F33 → S2F35 → S2F37 → 等 S6F11）可以跑通。
- 本地配置与主机定义并存，界面需要展示"这条报告来自本地还是主机"（M8 的字段预留）。
- 实现集中在 `HostReportTable`（纯数据 + 纯方法），可以脱离协议单测。
