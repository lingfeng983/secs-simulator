# ADR 0007 · API 账号与角色分级

- 状态：**已被取代**（2026-10-28）
- 日期：M10
- 影响范围：`secs-api-http` 的 `AccessControl` / `ApiRole` / `HttpApiServer`，`secs-runtime` 的 `RuntimeOptions` / `Main`

> **取代说明**：本工具定位为车间/实验室内部工具，远程访问一律直连。
> 令牌与账号文件（`--token` / `--auth-users`）已全部移除，界面也不再提供令牌输入；
> `AccessControl` 只保留"恒为本机管理员"的直连语义，角色判断留作将来接入鉴权时的挂点。
> 下文保留为历史决策记录，不再代表当前行为。

## 问题

TLS 落地后，SERVER 模式的安全边界只剩"一个令牌 + 明文口令文件"。

现场的实际问题是**一把钥匙开所有门**：能看曲线的人，也能停掉正在跑产线的仿真器，
也能手动把报警打上去把主机侧的时间序列搅乱。单一令牌无法表达"值班工程师只读"。

## 决策

### 1. 单 token 是"一个 admin 账号"，不是特例分支

`--token` 与 `--auth-users` 走**同一条鉴权路径**：`AccessControl.singleToken(t)`
就是构造一个名字叫 `token`、角色为 `ADMIN` 的账号。

理由：两条代码路径意味着两份语义，以后必然出现"单 token 下能停机、
账号文件下停不了"这类只在其中一个模式下复现的现场问题。
现有脚本、前端、`start.ps1` 一行都不用改。

### 2. 三级角色，边界是"这个操作会不会改变设备状态"

| 角色 | 能做 |
|---|---|
| `viewer` | health 详情、会话列表、报警/终端查询、曲线预览、SSE |
| `operator` | viewer + 触发 CEID（S6F11）、置位/清除报警（S5F1） |
| `admin` | operator + 优雅停机 |

没有更细的权限点，也没有"只对某个会话可写"——那需要引入资源级 ACL，
而现场一个部署通常就是一套配置、一台设备仿真的场景。

### 3. 401 与 403 必须分开

未认证/口令错 → **401**；认证通过但角色不够 → **403**。

两者混用会让现场无法判断"是我口令打错了，还是我本来就没这个权限"，
而这正是最常见的两类支持问题。

### 4. 比对口令不提前 break

`AccessControl.authenticate` 遍历**全部**账号后才返回。
提前 break 会让"命中第 1 个"与"命中第 5 个"的响应时间不同，
计时侧信道可以据此逐字符猜出口令。账号表通常只有几个条目，
多比几次的开销可以忽略。

### 5. 配置错误必须在启动阶段失败

账号名为空、口令为空、账号名重复、口令重复、角色拼错、账号列表为空——全部在
`Main` 启动阶段抛错退出（退出码 2），错误信息带 `$.users[0].role` 这样的字段路径。

理由：带着半个鉴权跑起来比根本起不来危险得多。
"空账号表"尤其危险——它等价于**没有鉴权**，因此显式拒绝而不是当作"未配置"。

### 6. 口令明文存储，并明确这是取舍

服务端要在运行时比对，没法只存哈希。账号文件因此与私钥同级：
不进版本库、不进分发包、靠文件系统权限保护。这条写进 README 而不是藏在代码里。

### 7. `--token` 与 `--auth-users` 是二选一，不是叠加

同时给出时按账号文件走，**并打一条错误日志**。
悄悄忽略用户明确写了的参数，比直接报错更难排查；
叠加则会让"我明明删掉了 token"变成一个安全疑问。

## 后果

- 单令牌部署完全不受影响；多账号部署不需要反向代理就能做到值班只读。
- SSE 票据本身记录签发身份与角色，`/api/v1/health`（带凭据时）也回显
  `user` / `role`，前端下一轮就能据此隐藏无权限的按钮。
- 口令比对是明文的、低强度的：口令强度仍需靠运维纪律，换密钥轮转能力要等后续版本。
- 角色枚举常量按能力递增排列（viewer < operator < admin），
  判断直接比 `ordinal()`；代价是**不能重排常量**，重排等于给已部署账号集体降级/升级。
