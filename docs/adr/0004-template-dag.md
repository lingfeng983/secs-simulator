# ADR 0004 · 模板 DAG 与受限表达式

- 状态：已接受
- 日期：M3
- 影响范围：`secs-core` 的 `template`

## 问题

M2 的形态是"一个 SVID 一条曲线"。但真实设备里变量是彼此耦合的：

- 总流量必须等于各支路之和；
- 温度偏差决定加热器通断；
- 腔体温度和压力同源、但幅度不同。

一条曲线表达不了这种关系，只能靠人肉对齐两份配置，迟早漂移。
而且一旦漂移，主机侧看到的是一组"物理上不可能"的数据。

## 决策

### 1. 模板是"多输出生产单元"，输出之间用表达式关联

```java
new CompositeTemplate("thermal", Map.of(
    "TOTAL", Expression.parse("in.ch1.PV + in.ch1.PRESS"),
    "DELTA", Expression.parse("in.ch1.PV - p.target")));
```

### 2. 表达式刻意做小

没有赋值、循环、副作用、动态调用。只有：四则运算 + 一元负号 +
12 个纯函数（`clamp/lerp/min/max/abs/roundTo/sum/avg/select/sin/floor/ceil`）。
需要状态的东西（积分、滞后、计数）**不属于表达式**——它们要么做成模板，
要么做成包装层（见 ADR 0003）。

理由：表达式会被用户在 GUI 里天天改。引入副作用之后，
"改一个参数为什么影响了另一个变量"就再也解释不清了。

### 3. DAG 在构建期完成三件事

| 检查 | 为什么必须在构建期 |
|---|---|
| 拓扑排序 | 运行期顺序错会让下游读到上一 tick 的旧值，表现为"数据延迟一拍"，极难发现 |
| 环检测 | 否则运行期无限递归或读到初始值 |
| **单写者**（一个 SVID 只能被一个输出绑定） | 否则"谁最后写谁生效"，数据会随机漂移且不可复现 |

### 4. 参数分 5 层覆盖

`模板默认值 → 单元模板 → 单元实例 → profile → 运行时手动`。

分级依据是"改动的人与频率不同"：模板默认值由模板作者定，
单元参数由工程配置，profile 随工艺切换，运行时手动只用于临时试验且不落盘。
`ParameterLayers` 是**不可变**的（`with` 返回新实例），
避免"改了一层把别人正在跑的场景也改了"。

## 后果

- **正面**：多 SVID 关系可表达、可校验（`sum(分项) == 总量` 这类约束，
  以及 `SVID 单写者` 这类结构约束）；拓扑序让求值顺序不再是隐含知识。
- **负面**：配置比"一个曲线一个值"复杂，因此必须在 GUI 里提供
  拖拽式编辑与来源徽章（M8），否则用户看不懂"这个值从哪来"。
- **约束**：模板图是纯函数图（`Template.evaluate` 必须无副作用），
  这样才能支持预览批算（`evaluateRange`）与任意时刻重算。
