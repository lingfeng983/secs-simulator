# SEMI SECS/GEM 标准参考资料

本目录是**本项目的协议知识底座**，供实现、联调、评审三类场景查证使用。

**入口原则**：任何关于 SECS/GEM 标准的查阅都从本文件开始。后面几张表分别回答
"我想读标准"、"我想看本项目怎么实现"、"我想看原文"三个问题，末尾给出阅读路径、速查卡片与整理规则。

---

## 1 目录结构

```
docs/reference/
├── README.md                 ← 本文件（唯一入口）
├── standards/                标准正文的中文整理（按标准编号）
├── project/                  标准条款 ↔ 本项目代码的对照手册
└── pdf/                      英文原版 PDF（版权文档，不进版本库）
```

三层的分工：

| 目录 | 是什么 | 什么时候用 |
|---|---|---|
| `standards/` | 按原版章节顺序整理的中文正文：定义了哪些状态、哪些消息、哪些码值 | 查"标准怎么规定"、"这个字段什么含义" |
| `project/` | 按功能主题组织的对照表：标准要求 vs 本项目实现位置与状态 | 查"我们实现了没"、"这段代码对应标准哪条"、"问题出在哪" |
| `pdf/` | SEMI 官方英文原文 | 需要逐字核对、或整理版标注"以原文为准"时 |

**冲突裁决**：三者不一致时，以 `pdf/` 英文原文为准；`standards/` 是整理，
`project/` 是带时间戳的实现快照，两者都可能滞后。

**第一次接触这套协议** → `05 理解指南` → `03 GEM` 第 3 章状态模型 → `02 E5` 第 6 章数据编码

## 6 速查

**建链顺序（HSMS）**

```
TCP connect → Select.req/rsp → S1F13/S1F14 → S1F17/S1F18(进入 ONLINE)
→ 数据交换 → Linktest 保活 → Deselect → TCP close
```

**定时器一览**（E4 与 E37 是两套独立编号，不要混用）

| 定时器 | 出自 | 含义 | 典型值 |
|---|---|---|---|
| T1 | E4 | 块内字符间超时 | 0.5–1 s |
| T2 | E4 | 协议超时（ENQ→EOT 等握手） | 10 s |
| T3 | E4 / E5 / E37 | 应答超时 | 30–45 s |
| T4 | E4 | 多块消息块间超时 | 45 s |
| T5 | E37 | 连接重试间隔 | 10 s |
| T6 | E37 | 控制事务超时 | 5 s |
| T7 | E37 | 建连后未 Select 的等待上限 | 10 s |
| T8 | E37 | 消息内字节间超时 | 5–6 s |

**GEM 主机上线必发的核心消息**

| 用途 | 消息 |
|---|---|
| 在线探测 / 建链 | S1F1/F2、S1F13/F14 |

| 状态变量查询 | S1F3/F4、变量目录 S1F11/F12 |
| 动态报表三件套 | S2F33/F34（定义）→ S2F35/F36（链接）→ S2F37/F38（使能） |
| 事件上报 | S6F11/F12 |
| 报警 | S5F1/F2 |
| 远程命令 | S2F41/F42 |
| 时间同步 | S2F17/F18、S2F31/F32 |
| 错误回告 | S9F1/F3/F5/F7/F9/F11/F13 |

## 7 整理规则（新增文档时遵守）

1. **一个标准一份文件**，放在 `standards/`，命名为 `NN-<标准号>-<短名>-中文整理.md`。
2. 文件名**只用 ASCII 与连字符**，避免空格与全角括号——否则 Markdown 链接必须转义，容易断。
3. 每份文档头部固定四段：`原标准` / `覆盖范围` / `未覆盖` / `整理基线`。
4. 正文小节编号**沿用原版编号**，即使原版跳号也不重排；跳号处在节首注明原因。
5. 引用原文页码时注明 PDF 文件名与页码，便于回查。
6. 涉及本项目实现的段落，写到 `project/`，不混进 `standards/`。
