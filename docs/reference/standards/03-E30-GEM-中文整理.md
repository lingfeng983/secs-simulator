## 1 引言

### 1.2 范围
GEM 定义**半导体制造设备的标准行为模型**：设备在 SECS-II 消息接口上应呈现的行为——状态模型、事件、报警、远程控制、数据采集等。GEM 建立在 E5（SECS-II）之上，不定义传输层（由 E4/E37 承担）。

### 1.4 概述（GEM 组件）
- 三大状态模型：**通信状态模型、控制状态模型、设备加工状态模型**；
- 若干**设备能力（Capabilities）**：建立通信、数据采集、报警管理、远程控制、设备常数、配方管理、物料移动、终端服务、错误消息、时钟、Spooling、控制等。

## 3 状态模型

GEM 采用 Harel 状态图记法（OR 子状态/AND 子状态）。每个模型附**状态转换表**，规定触发与动作。

### 3.2 通信状态模型（Communications State Model）

定义设备相对于"与主机之间通信链路是否存在"的行为，指**逻辑连接**而非物理连接。

**关键术语**：
- **connection transaction failure（连接事务失败）**：试图建立通信时由通信失败、S1F14 应答超时、或收到的 S1F14 格式错误/COMMACK≠0 引起。
- **通信链路建立**：首次成功完成任一 S1F13/F14 事务且应答为"接受"（COMMACK=0）。
- **CommDelay 计时器**：两次发送 S1F13 之间的间隔，由设备常数 `EstablishCommunicationsTimeout`（秒）设定，对主机不可见。
- 主机可因自身初始化或检测到通信失败而**随时**发起 S1F13。

**状态结构**：

```
DISABLED  ──使能──►  ENABLED
                       ├── NOT COMMUNICATING
                       │     ├── HOST-INITIATED CONNECT / WAIT CR FROM HOST（等主机 S1F13）
                       │     └── EQUIPMENT-INITIATED CONNECT
                       │           ├── WAIT CRA（已发 S1F13，等 S1F14）
                       │           └── WAIT DELAY（失败后等 CommDelay 到期重试）
                       └── COMMUNICATING（正常工作）
```

**状态规则**：
- **DISABLED**：与主机无 SECS-II 通信。操作员从 ENABLED 切到 DISABLED 时所有 SECS-II 通信**立即停止**，发送队列中的消息丢弃，一切未闭合事务与会话终止。DISABLED 可为系统默认。
- **系统默认状态必须可在设备端配置**（跳线或非易失存储）；初始化完成后操作员可随时通过终端功能或瞬时开关改变通信状态（**不得使用双位开关**，以免与默认态冲突）。设备必须**持续显示**当前通信状态（含两个子状态）。
- **ENABLED/NOT COMMUNICATING**：只允许发送 S1F13、S1F14、S9Fx；丢弃除 S1F13/S1F14 外收到的一切消息；按 CommDelay 周期性发 S1F13 尝试建链，但**同一时刻只允许一个设备发起的 S1F13 事务未闭合**。
- **ENABLED/COMMUNICATING**：可收发任何消息；收到 S1F13 应回 S1F14（COMMACK=0）；通信失败则回到 NOT COMMUNICATING 并尝试重建。
- **双发冲突**：双方同时发起 S1F13 时，任一事务先成功完成即进入 COMMUNICATING，另一事务保持开启直至正常关闭。

### 3.3 控制状态模型（Control State Model）

定义主机与设备的**控制协作级别**（通信模型解决"能不能说话"，控制模型解决"设备是否执行消息"）。三个基本控制级别：

```
OFF-LINE ──► ON-LINE
              ├── LOCAL（本地：操作员操作设备）
              └── REMOTE（远程：主机全面控制）
```

**状态定义**：

- **OFF-LINE**：设备由操作员在操作台操作。消息传送仍可能，但自动化用途严重受限。
  - 只响应 S1F13 与 S1F17（请求上线）；对其他主消息回 **SxF0**（中止）。
  - 除 S1F13、S9Fx、S1F1（ATTEMPT ON-LINE 时）外不发送任何主消息。
  - 三个子状态：
    - **EQUIPMENT OFF-LINE**：保持离线，等操作员指令；
    - **ATTEMPT ON-LINE**：响应操作员上线指令，尝试向主机发 S1F1；此间不响应上下线开关；
    - **HOST OFF-LINE**：操作员想让设备上线但主机未同意（上线尝试失败或主机请求下线）；**仅此子状态**下主机发 S1F17 才会被接受。
- **ON-LINE**：SECS-II 消息可交换并可执行；主机能力应尽量与操作台一致。ON-LINE 下不要求（且不建议）使用 SxF0。
  - **LOCAL**：设备由操作员直接操作。主机限制：
    - 禁止引发物理动作或启动加工的远程命令；加工中禁止影响该过程的远程命令；
    - 加工中禁止修改影响该过程的设备常数（其他常数可改；无加工时可改全部）；
    - 可上/下载配方、选择不影响当前执行配方的配方；
    - 可配置自动数据上报（报警/事件/追迹）并按时接收；
    - 可查询状态、常数、事件报告、配方目录、报警；
    - 设备应能执行终端服务。
  - **REMOTE**：主机可通过通信接口以自动化方式操作设备完成完整工艺循环；**设备不限制任何主机能力**。操作员仍可能在远程加工中交互（上下料、辅助等）。

### 3.4 设备加工状态模型（Equipment Processing States）

```
IDLE（空闲）→ SETUP（设置）→ EXECUTING（加工执行）→ （正常完成/STOP/ABORT）
```

- 必须上报加工状态相关采集事件（见第 6 章：Processing Started / Completed / Stopped / State Change）。
- 状态迁移须有对应采集事件；具体子状态由设备厂商扩展。

### 4.1 建立通信
场景：任一方发 S1F13（可携带 MDLN/SOFTREV），对方回 S1F14（COMMACK=0 接受 + MDLN/SOFTREV）。首次成功完成即建立逻辑通信链路。

### 4.2 数据采集
- **事件通知（4.2.1.1）**：事件发生时设备发 S6F11（含 DATAID、CEID、按 RPTID 组织的变量值），主机回 S6F12。
- **动态事件报表配置（4.2.1.2）**：主机用 S2F33 定义报表（RPTID→VID 列表）、S2F35 链接（CEID→RPTID 列表）、S2F37 使能/禁用事件。
- **变量数据采集（4.2.2）**：SVID/VID 查询与事件报表携带。
- **追迹数据采集（4.2.3）**：S2F23/F24 按时间间隔采样的数据流。
- **限值监测（4.2.4）**：变量进入 ABOVE LIMIT / BELOW LIMIT / WITHIN LIMIT 区域时产生事件（每变量独立 CEID）。
- **状态数据采集（4.2.5）**：S1F3/F4 查询 SV。
- **在线识别（4.2.6）**：S1F13/F14 中的 MDLN、SOFTREV。

### 4.3 报警管理
- 报警状态模型：每报警 ALIDn 有 **ALARMnCLEAR → ALARMnSET** 两个状态；
- 置位时发 **S5F1**（L:3{ALCD, ALID, ALTX}，期待应答）；清除时也发 S5F1（ALCD 表示清除）。
- S5F3/F4 使能/禁用报警；S5F5–F8 列出报警及已使能报警。
- 报警用于"可能危及人身/设备/物料安全的状况"，是硬件安全报警的补充而非替代。

### 4.4 远程控制
- 主机发 **S2F41**（RCMD + 参数列表 CPNAME/CPVAL），设备回 **S2F42**（HCACK）。
- HCACK 取值：0=确认完成；1=命令不存在；2=暂时无法执行；3=参数错；4=已初始化无法执行；5=拒绝；6=无权限；7=已处于该状态。
- 异步执行：先回确认，完成后用事件通知（如 Processing Started）。

### 4.5 设备常数
- S2F13/F14 查询、S2F15/F16 设置（任一值非法则全部不生效）、S2F29/F30 列清单（含最小/最大/默认值与单位）。

### 4.6 工艺程序（配方）管理
- 上传：S7F1（询问，含长度）→ S7F2（授权）→ S7F3（发送）→ S7F4（ACKC7 确认）。
- 下载：S7F5（请求）→ S7F6（数据）。
- 列目录 S7F7/F8；删除 S7F17/F18；当前配方 S7F19/F20。
- 结构化配方（Formatted）：S7F23–F26、S7F25/F26。
- 配方变更/选择应产生采集事件（Process Program Change / Selected）。

### 4.7 物料移动
Material Received / Material Removed 事件及 S3F17/F18（载具动作请求/应答）。

### 4.8 终端服务
- 主机→设备显示：S10F3（单块）；操作员→主机：S10F1；
- "New Host Message" 指示灯与确认按钮（Message Recognition 事件）。

### 4.9 错误消息
设备检测到主机消息错误时按 E5 发 Stream 9（S9F1/F3/F5/F7/F9/F11/F13）。

### 4.10 时钟
- S2F17/F18 查询时间；S2F31/F32 设置时间（16 字符 `YYYYMMDDhhmmssTT` 格式）。
- 时钟变更应产生 Clock 事件。

### 4.11 Spooling（消息暂存）
通信中断时设备把待发消息（Stream 2/5/6/10 中配置的）存入 Spool，恢复后（SPOOL OUTPUT 状态）按 S2F43–F48 配置与 S6F23 请求补发。Stream 1 不入 Spool。状态机：INACTIVE → ACTIVE（存） → TRANSMIT（发）。

### 4.12 控制
- 操作员发起上线（ATTEMPT ON-LINE 时设备发 S1F1）；主机请求上下线用 S1F15/S1F17。
- ON-LINE↔LOCAL/REMOTE 切换产生对应控制事件。

## 5 数据项（GEM 定义的标准变量）

GEM 定义的标准状态变量（SVID）与数据变量（VID）示例：

| 变量 | 类型 | 说明 |
|---|---|---|
| Clock | SV | 设备时钟 |
| ControlState | SV | OFF-LINE / LOCAL / REMOTE / HOST OFF-LINE… |
| ProcessState | SV | 当前加工状态 |
| PreviousProcessState | SV | 前一加工状态 |
| AlarmsEnabled | SV | 已使能的报警集合 |
| AlarmsSet | SV | 当前置位的报警集合 |
| AlarmID | DV | 报警号 |
| EstablishCommunicationsTimeout | EC | S1F13 重试间隔（秒） |
| OperatorCommand | DV | 操作员在 REMOTE 态发出的命令 |
| PPChangeName / PPChangeStatus | DV | 配方变更名/状态 |
| SpoolCountActual / SpoolCountTotal | DV | Spool 计数 |

数据项格式限制：Status Data 用 U1/U2/U4/U8 或 ASCII；AlarmsSet 等用二进制位图（B）或列表；Clock 用 ASCII 时间戳。

### 8.3 GEM 合规定义
设备对某能力"GEM 合规"当且仅当：
1. 基本要求全部满足；
2. 该能力按标准中全部适用定义/描述/要求实现；
3. 不存在与该能力 GEM 行为冲突的行为。

设备可用 SECS-II 消息提供 GEM 之外的附加功能，只要不与 GEM 能力冲突。

**"Fully GEM Capable"（全 GEM 能力）**：提供 8.2 全部能力且每项均合规。

### 8.4 文档要求
- SECS-II 接口文档须**单卷**提供：消息文档（按 E5 第 8 章）+ GEM 合规声明 + 第 3、4 章要求的文档。
- **GEM 合规声明**（Table 8.3）：对每项基本要求与能力勾选"是否实现（Implemented）"与"是否 GEM 合规（GEM-Compliant）"；附加能力只有在基本要求合规时才可标合规。
- 可用 SML 记法提供数据项格式文档。
