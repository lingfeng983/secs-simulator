## 1 引言

### 1.1 修订历史
本版是自 1980 年 SECS-I 首次发布以来的第一次大修订。原版意图基本未变，仅增加少量重要内容（差异汇总见附录 1）。本标准与日本电子工业发展协会（JEIDA）设备通信第 12 委员会合作制定。

### 1.2 范围
SECS-I 定义适用于**半导体加工设备与主机（Host）之间交换消息**的通信接口。设备包括晶圆制造、晶圆加工、工艺测量、组装与封装设备；主机是与设备交换信息以完成制造任务的计算机或计算机网络。

本标准规定：物理连接器、信号电平、数据速率，以及在**串行点对点数据链路**上交换消息所需的逻辑协议。

本标准**不定义消息内的数据内容**——消息含义须由消息内容标准（即 SEMI E5 / SECS-II）确定。

### 1.3 意图
使不同厂商独立生产的设备与主机无需了解对方细节即可互联。

- **1.3.1 分层协议**：SECS-I 可视为点对点分层协议，分三层：物理链路（Physical Link）、块传输协议（Block Transfer Protocol）、消息协议（Message Protocol）。
- **1.3.2 速度**：不追求满足所有应用；RS-232 速率对大批量数据/程序传输（如高速功能测试）可能不足。
- **1.3.3 网络支持**：不规定数据块在网络中的路由方式。网络中任一方都可扮演主机或设备角色，但链路一端必须担任设备角色，另一端担任主机角色。

### 1.4 引用文档
- EIA RS-232-C（DTE/DCE 串行二进制数据交换接口）
- EIA RS-269-B（同步信号速率）、RS-334（信号质量）、RS-422/RS-423（平衡/非平衡电压数字接口电路电气特性）
- ISO 2110-1980（接口连接器与引脚分配）
- SEMI E5（SECS-II）、SEMI E6（设施接口规范格式）

### 1.5 SECS-I 概述
- 采用 EIA RS-232-C（日本为 JIS C 6361）的连接器与电平子集。
- 实际传输为 8 位字节串行发送，1 个起始位 + 1 个停止位。
- 通信双向但**异步、同一时刻仅单向**；方向由特殊字符（握手）确定，握手完成后发送数据。
- 数据以**块（Block）**为单位发送，每块 ≤ 254 字节，由 **10 字节块头 + 数据**组成。
- **消息（Message）**是一个方向上的完整通信单元，由 1 ~ 32767 个块组成；块头标识该块属于哪条消息。
- 请求消息与其应答消息配对，合称**事务（Transaction）**。

### 1.6 文档结构
正文按标准的主要方面分节；实现相关的辅助信息放在"Related Information（参考信息）"部分，不属于标准本体。

## 3 电气接口（Coupling）

### 3.2 电气接口
采用 EIA RS-232-C E 型接口、全双工通信，并按本节修改（增删与例外）。

**3.2.1 连接器**：可用 25 针或 9 针 D 型连接器。
- 25 针：设备侧装**孔座**，主机线缆侧装针座。
- 9 针：设备侧装**针座**，线缆侧装孔座。
- 设备侧连接器带 4-40 螺纹锁紧钉。

**3.2.2 信号引脚**（必需引脚）：

| 25 针 | 9 针 | RS-232-C 电路 | 说明 |
|---|---|---|---|
| 1 | — | AA | 屏蔽 |
| 2 | 3 | BA | 设备发送数据（Data from Equipment） |
| 3 | 2 | BB | 设备接收数据（Data to Equipment） |
| 7 | 5 | AB | 信号地 |
| 18 | — | — | +12 ~ +15 V（25 针可选电源） |
| 25 | — | — | −12 ~ −15 V（25 针可选电源） |

**3.2.3 逻辑电平**：引脚 2/3 上，逻辑 1 < −3 V，逻辑 0 > +3 V，电压不超过 ±25 V。

**3.2.4 电源**：25 针连接器的 18、25 脚为可选隔离电路电源；若提供则两者齐备且至少供 50 mA。

### 3.3 数据速率
支持 **9600 / 4800 / 2400 / 1200 / 300 波特**，收发同速，精度优于 0.5%。可选 19200 与 150 波特。

### 3.4 物理介质
只要在设备连接器处提供符合 RS-232-C 质量的信号即可；误码率应低于 1×10⁻⁶。距离与隔离取决于 SECS-I 之外的物理介质设计。

## 4 字符结构

- 每字符 10 位：**1 起始位（0）+ 8 数据位 + 1 停止位（1）**，各位等宽。
- 8 个数据位按发送顺序编号 1~8，合称一个字节。
- 字符间时序与波特率异步。
- 加权码（如二进制）：位 1 最低有效，位 8 最高有效。
- 非加权码（如 ASCII）：按标准码表解释。
- SECS-I **不做奇偶校验**或其他单字节内容校验。

## 5 块传输协议（Block Transfer Protocol）

### 5.1 概述
块传输协议用于确定通信方向并传递消息块，主要靠**单字节握手**完成。当两端同时想发送时发生**线路争用（contention）**，协议通过强制一端（**从方，即主机**）推迟发送、进入接收模式来解决。块重传用于纠正通信错误。

### 5.2 握手字节

| 名称 | 编码（b8…b1） | 功能 |
|---|---|---|
| ENQ | 00000101 (05h) | 请求发送 |
| EOT | 00000100 (04h) | 准备接收 |
| ACK | 00000110 (06h) | 正确接收 |
| NAK | 00010101 (15h) | 错误接收 |

### 5.3 超时参数
超时用于检测通信故障，须按应用"调参"：

- **T1 字符间超时**：收到长度字节后到收到第二个校验和字节之间，块内字符间的时间上限。
- **T2 协议超时**：发送 ENQ 到收到 EOT、发送 EOT 到收到长度字节、发送第二个校验和字节到收到任意字符之间的时间上限。

### 5.4 重试上限 RTY
宣布发送失败前，块传输协议最多重试发送一个块的次数。

### 5.5 主/从（Master/Slave）
**设备为主（master），主机为从（slave）**。该约定基于"设备存储消息的能力通常弱于主机"的假设。

### 5.6 块长度
收到 EOT 后发送的第一个字节（无符号整数）为块长，**不含 2 字节校验和**。块长范围 **10 ~ 254 字节**。

### 5.7 校验和
- 对块内"长度字节之后、校验和之前"的所有字节按**无符号二进制值求和**。
- 以 16 位两字节发送，**高 8 位在前**。
- 接收方以相同算法验证。

### 5.8 算法（五状态：Idle、Line Control、Send、Receive、Completion）

- **5.8.1 空闲（Idle）**：两端初始均处于空闲态。两个出口：
  - A. SEND——要发送一个消息块；
  - B. RECEIVE——对方要发送消息块。
- **5.8.2 线路控制（Line Control）**：建立方向、解决争用、处理重试。
  - 空闲态收到 ENQ 且本方准备好接收 → 回 EOT，进入接收态。
  - 要发送 → 发 ENQ；在 T2 内收到 EOT → 进入发送态。
  - **争用**：从方发 ENQ 后收到 ENQ（而非 EOT），即发生争用。从方推迟发送、准备接收并回 EOT；收到主方块后回到空闲态，再当作新的发送请求重发。主方发 ENQ 后忽略除 EOT 外的一切字符；从方发 ENQ 后忽略除 ENQ/EOT 外的一切字符。
  - **重试**：ENQ→EOT 超时、校验和后超时或收到非 ACK 字符时，重试计数 +1；未超 RTY 则从 ENQ 重试，超过则判定发送失败。
- **5.8.3 发送（Send）**：先发长度字节 N，再发 N 字节数据，最后发 2 字节校验和。T2 内收到 ACK 即成功；收到非 ACK 或超时则回到线路控制考虑重试。发送最后一个校验和字节之前收到的字符可忽略。
- **5.8.4 接收（Receive）**：先收长度字节 N，随后保存 N+2 字节，最后 2 字节为校验和，与本地计算比对。
- **5.8.5 接收完成**：块正确接收后回 ACK 并通知消息协议。等长度字节超 T2 或字符间超 T1 → 回 NAK；长度字节非法或校验和错 → 继续收听直到字符间超 T1，然后中止接收并回 NAK。发 NAK 后可丢弃该块已收数据。收发完成后立即回到空闲态。
- **5.8.6 发送完成**：第二个校验和字节发出后 T2 内收到 ACK → 通知消息协议成功；失败则通知失败，应用层须自行考虑发送失败的可能。

## 6 块头结构（10 字节）

所有块传输协议之上的功能都依赖 10 字节块头。块头格式（与 SECS-II 的 Stream/Function 对应）：

| 块头字段 | 说明 |
|---|---|
| R-bit | 方向位 |
| Device ID | 15 位设备标识 |
| W-bit | 是否期待应答 |
| Message ID（Stream/Function） | 消息标识 |
| E-bit | 是否最后一个块 |
| Block Number | 15 位块号 |
| System Bytes | 4 字节系统字节 |

### 6.2 反向位 R-bit
- **R=0：发往设备**（Device ID 为目的地址，Host → Equipment）
- **R=1：发往主机**（Device ID 为源地址，Equipment → Host）

### 6.3 设备 ID
15 位，标识消息的源或目的（取决于 R-bit），属于设备属性、可按第 8 节设置。主机视其为设备内物理器件的逻辑标识；**主机本身没有设备 ID**。

### 6.4 等待位 W-bit
- W=1：主消息发送方期待应答；W=0：不期待。
- **所有从消息中 W-bit 必须为 0**。
- 多块消息中每个块的 W-bit 必须一致。

### 6.5 消息 ID
- **奇数消息 ID = 主消息**（低消息 ID 的位 1 = 1）
- **偶数消息 ID = 从消息**（低消息 ID 的位 1 = 0）
- 注：在 SECS-II 中，块头第 3 字节（除 W-bit）称 **Stream**，第 4 字节称 **Function**。

### 6.6 结束位 E-bit
- E=1：本块是消息的最后一个块；E=0：后续还有块。

### 6.7 块号
- 多块消息的第一块块号为 1，随后每块递增 1，按顺序发送。
- 单块消息块号必须为 0 或 1。
- 最大块号 32767。

### 6.8 系统字节
- **唯一性**：主消息的系统字节须区别于同端所有未闭合事务、最近一个已完成事务、以及上次成功发送以来所有发送失败块的系统字节。
- **应答消息**：从消息的系统字节必须与对应主消息相同。
- **多块消息**：同一消息所有块的系统字节必须相同。

## 7 消息协议（Message Protocol）

### 7.1 消息
消息 = 消息数据 + 块头中的 R-bit、设备 ID、W-bit、消息 ID、系统字节。

### 7.2 消息发送
- **7.2.1 消息长度**：单块数据最多 **244 字节**；最多 **32767 块**，故单条消息最大数据量 = 244 × 32767 字节。
- **7.2.2 分块（Blocking）**：建议（非强制）除最后一块外每块填满 254 字节。接收方应能接受 11~254 字节任意块长。1988 版起新应用不得对入向块长施加应用层限制。
  - 注：SECS-II 中定义为单块消息的消息必须单块发送。
- **7.2.4 消息交织**：允许（但不要求）支持多个并发未闭合事务、以及不同多块消息的块交织。

### 7.3 事务
- 事务 = 一条主消息 + 可选的对应从消息（应答）。
- 主消息准备好发送即开启事务；不要求应答的主消息最后一块发完，或应答最后一块收完，即关闭事务。
- **7.3.1 应答链接**：期待应答时，主消息最后一块成功发出后启动应答计时器；并建立"期望块"（R-bit 取反、设备 ID 相同、为从消息首块、系统字节相同）。
  - 注：SECS-II 中，应答的 Stream 与主消息相同，Function 比主消息大 1 或为 0。
- **7.3.2 应答超时 T3**：主消息最后一块发出到应答首块到达的时间上限。超时则移除期望块并中止事务。每个期待应答的未闭合事务需独立计时器。

### 7.4 消息接收
- **7.4.1 路由错误**：设备收到设备 ID 不匹配且无法识别的块，可视为误发。
- **7.4.2 重复块检测**：与上一个被接受的块完全相同（10 字节块头一致）的块视为重复块，丢弃之。旧实现（1980 版）可能没有唯一块头，须提供禁用重复检测的选项以兼容。
- **7.4.3 块间超时 T4**：多块消息相邻两块成功接收的间隔上限。超时则取消消息、中止事务。每个接收中的多块消息需独立块间计时器，每收到一块重置。
- **7.4.4 接收算法**：按"期望块"列表匹配收到的块：
  - 非期望块 → 必须是某主消息首块，否则丢弃；若是主消息首块且 E=0，则设置块间计时器与下一个期望块（块号 +1）。
  - 期望块 → 是应答首块（取消应答计时器）或未闭合消息的后续块。
  - E=1 → 消息完整；若为期待应答的主消息（W=1），保存系统字节用于应答。
  - E=0 → 重置块间计时器，期望块号 +1。

## 附录 1：与 1980 版 SECS-I 的主要差异

1. 25 针连接器 18/25 脚电压变为可选；
2. 150 波特变为可选；
3. 新增 T4 超时，澄清 T3 用法；
4. 发送 EOT 后等待长度字节期间也使用 T2；
5. 校验和后收到任何非 ACK 字符均按 NAK 处理；
6. 非法块长/坏校验和时先等 T1 让对方发完再回 NAK；
7. 澄清块号 0 仅用于单块消息；
8. 主机发送从消息时的系统字节处理与设备一致，并增加系统字节功能要求；
9. 新增重复块检测机制；
10. 澄清并扩展块组装为消息的描述；
11. 事务处理与应答链接从 SECS-II 移入并扩展；
12. 附录部分移至"Related Information"；
13. 标题由"Data Link"改为"Message Transfer"；
14. W-bit 要求所有块中一致；
15. 新增合规文档章节。

## 参考信息（Related Information）要点

- **R1-1.1 与 OSI 模型对照**：SECS-I 早于 ISO/OSI 且非真正开放系统。物理链路≈OSI 第 1 层；块传输协议≈第 2 层（部分覆盖第 4 层）；网络层为主机功能；消息协议部分覆盖第 5 层（会话层）。
- **R1-1.2 T1/T2 可共用一个计时器**。
- **R1-2 RS-232 隔离**：RS-232-C 不提供地隔离，长距离或工厂环境建议光电隔离；可用 25 针 18/25 脚电源驱动隔离电路。
- **R1-4 一般节点事务算法**：树状网络拓扑中，节点可将设备与下级节点聚合为一个逻辑节点，块按存储-转发方式中继。
