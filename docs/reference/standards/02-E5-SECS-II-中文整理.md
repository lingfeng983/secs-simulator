## 1 引言

SECS-II 定义设备与主机之间交换的**消息内容**：消息如何编号（Stream/Function）、数据如何编码（Item/List 结构）、以及事务与会话协议的约定。SECS-II 与传输层无关——可运行在 SECS-I（RS-232）或 HSMS（TCP/IP）之上。

**注意**：Stream 4 相关实现可能涉及德州仪器持有的美国专利 4,884,674、5,216,613（原标准中的专利声明）。

## 3 消息传输协议（与传输层的接口要求）

### 3.2 消息
传输层必须能够：
- 发送主消息（Primary），并标明是否请求应答；
- 若请求应答，则将对应的从消息（Secondary/Reply）与原主消息关联。

术语：**originator（发起方）**＝创建主消息的一端；**interpreter（解释方）**＝在目的地解释主消息并按需生成应答的一端。

### 3.3 分块要求
- **单块消息**：标准中定义为单块的消息必须单块/单包发送；单块 SECS-II 消息最长 **244 字节**（兼容 SECS-I）。传输层最低要求是能发送单块消息。
- **多块消息**：超过 244 字节的消息为多块消息；某些消息即使不超长也允许按多块发送。1988 版起新应用不得对入向块长施加应用层限制。

### 3.4 消息头（传输层必须随消息提供的逻辑信息）
- **设备 ID**（0–32767）：消息的源/目的。
- **Stream 和 Function**：至少 15 位消息识别码；SECS-II 用 Stream（0–127，7 位）+ Function（0–255，8 位）。
- **是否请求应答**（Reply Requested）。
- 注：SECS-I 中这些信息即每块 10 字节块头的内容。

### 3.5 事务超时
传输层须在事务超时后通知 SECS-II（SECS-I 中＝T3 应答超时或 T4 块间超时）。

### 3.6 多个未闭合事务
允许但不要求支持多个并发未闭合事务。

## 4 Stream 与 Function

### 4.1 Stream（流）
Stream 是**消息大类**，服务于相似或相关的活动。

### 4.2 Function（功能）
Function 是 Stream 内具体活动的**具体消息**。编号约定：

- **主消息（Primary）：Function 为奇数**。
- **应答消息（Secondary）：Function = 主消息 Function + 1（偶数）**。
- 不期待应答的主消息之后的偶数 Function 保留不用。
- **Function 0 在所有 Stream 中保留用于中止事务**（SxF0，见 7.4）。

### 4.3 Stream/Function 编号分配

| 范围 | 保留情况 |
|---|---|
| Stream 0，Function 0–255 | 标准保留 |
| Stream 1–63，Function 0–63 | 标准保留 |
| Stream 64–127，Function 0 | 标准保留 |
| **Stream 1–63，Function 64–255** | **用户自定义** |
| **Stream 64–127，Function 1–255** | **用户自定义** |

## 5 事务与会话协议

### 5.2 事务定义
事务（Transaction）＝不请求应答的主消息，或请求应答的主消息 + 对应从消息。**从消息不能再请求应答。**

### 5.3 事务级合规要求（SECS-II 最低要求）
1. 收到 S1F1 须以 S1F2 应答（见 7.5）；
2. 对无法处理的消息，在 Stream 9 发相应错误消息（S9F1/F3/F5/F7/F11）；
3. 其他支持的消息按第 7 章格式化；
4. 设备端检测到事务超时 → 向主机发 **S9F9**；
5. 收到 Function 0 作为应答 → 终止相关事务，且不向主机发错误消息。

### 5.4 会话协议（Conversation）
**会话**＝完成一项特定任务所需的一个或多个相关事务的序列。会话结束时应让发起方与解释方都释放已占用的资源。

**七种会话类型**：
1. **无应答主消息**（最简单，必须单块）；
2. **请求/数据**（request/data）：请求数据并收到应答数据；
3. **发送/确认**（send/acknowledge）：发送单块数据并收到确认；
4. **询问/授权/发送/确认**（inquire/grant/send/acknowledge）：多块发送前先请求许可；解释方可设会话超时，超时释放资源并（设备侧）发 S9F13；
5. **数据集传送会话**（Stream 13）；
6. **物料传送会话**（Stream 4）；
7. **请求/确认/发送/确认**（request/acknowledge/send/acknowledge）：需较长时间获取的信息（如需操作员输入），解释方先确认、稍后主动发送。

## 6 数据结构（Item 与 List）

所有 SECS-II 信息用两种结构表达：**Item（数据项）**与 **List（列表）**，为消息提供"自描述"的内部结构。

### 6.2 Item（数据项）
每个 Item 由**项头（Item Header，2/3/4 字节）+ 项体（Item Body）**组成：

```
第 1 字节（格式字节）:  位 7 6 5 4 3 2 = 格式码（6 位）
                      位 1 0 = 长度字节数（0~3）
随后 0~3 字节:        项体长度（不含项头）
随后 n 字节:          项体数据
```

- **格式字节位 1–0 只能是 1/2/3**：取 0 表示"无长度字节"，标准规定这是非法编码（E5 6.3.1）。
- **长度为 0 与"无长度字节"是两件事**：长度字节存在但值为 0（如 `L0`、空 ASCII 项）是合法的，
  且被大量消息用作语义信号（"返回全部"、"该值不存在"、"无此项"），具体含义见各消息的例外条款。
- 长度字节数与可表示的最大数据量：

| 长度字节数（格式字节位 1–0） | 项体长度上限 | 说明 |
|---|---|---|
| 0 | — | **非法**。E5 6.3.1：格式字节中长度为 0 会产生错误 |
| 1 | 255 字节 | 最常见的短项 |
| 2 | 65 535 字节 | |
| 3 | 16 777 215 字节（≈16 MiB） | 24 位长度；超出应改用多块消息或 Stream 13 |

| 格式码（二进制） | 八进制 | 含义 | 备注 |
|---|---|---|---|
| 000000 | 00 | **List** | 长度按元素计 |
| 001000 | 10 | Binary | 任意二进制串 |
| 001001 | 11 | Boolean | 0=false，非 0=true |
| 010000 | 20 | ASCII | 非打印字符为设备自定义 |
| 010001 | 21 | JIS-8 | 日文编码 |
| 010010 | 22 | 2 字节字符（本地化字符串） | 详见 6.4 |
| 011000 | 30 | I8（8 字节有符号整数） | 高位在前 |
| 011001 | 31 | I1（1 字节有符号整数） | — |
| 011010 | 32 | I2（2 字节有符号整数） | 高位在前 |
| 011100 | 34 | I4（4 字节有符号整数） | 高位在前 |
| 100000 | 40 | F8（8 字节浮点） | IEEE 754，符号字节在前 |
| 100100 | 44 | F4（4 字节浮点） | IEEE 754 |
| 101000 | 50 | U8（8 字节无符号整数） | 高位在前 |

有符号整数为二补码；浮点符合 IEEE 754。

### 6.3 List（列表）
- List 是**有序元素集合**，元素可以是 Item 或另一个 List（可嵌套）。
- List 头与 Item 头同构，格式码为 0；**长度字段计数的是元素个数而非字节数**。
- 多个 Item 的数组化表示（同一格式码下存多个值）用于节省重复项头。

### 6.4 本地化字符串（格式码 22）
项头之后、字符串之前有 **2 字节本地化字符串头（LSH）**，指定编码方案（计入项长）：

| 编码码（十进制） | 方案 |
|---|---|
| 0 | 保留（无） |
| 1 | ISO 10646 UCS-2（Unicode 2.0） |
| 2 | UTF-8 |
| 3 | ISO 646-1991（7 位 ASCII） |
| 4 | ISO 8859-1（西欧拉丁） |
| 5/6 | 泰文（ISO 8859-11 / TIS 620） |
| 7 | ISCII |
| 8 | Shift JIS |
| 9 | EUC-JP |
| 10 | EUC-KR |
| 11/12 | 简体中文（GB / EUC-CN） |
| 13/14 | 繁体中文（Big5 / EUC-TW） |
| 15–32767 | 保留 |
| 32768–65535 | 自定义 |

### 6.5 编码示例

**a. 一个二进制值 10101010：**
```
00100001   Item=Binary，1 个长度字节
00000001   1 字节长
10101010   数据
```

**b. 三个 ASCII 字符 "ABC"：**
```
01000001   Item=ASCII，1 个长度字节
00000011   3 字节长
01000001 01000010 01000011   'A' 'B' 'C'
```

**c. 三个 2 字节有符号整数：**
```
01101001   Item=I2，1 个长度字节
00000110   6 字节（6/2=3 个数）
xx xx  yy yy  zz zz   （每个数高字节在前）
```

**d. 一个 IEEE 754 单精度浮点数：**
```
10010001   Item=F4，1 个长度字节
00000100   4 字节
ff ff ff ff   浮点数
```

**e. 完整消息示例（S5F1 报警，设备 66 → 主机，W=0，E=1，块 1，系统字节 0）：**
```
块头（SECS-I 10 字节）:
10000000  R=1（发往主机）
00101110  设备 ID=66
00000101  Stream=5, W=0
00000001  Function=1
10000000  E=1（最后一块）
00000001  块号=1
00000000 (×4)  系统字节=0

消息体:
00000001  List
00000011  3 个元素
  00100001 00000001 00000100    Binary 项：报警集合/类别 4
  01100101 00000001 00010001    I1 项：报警号 17
  01000001 00000101 + "T1 HIGH"  ASCII 项：报警描述
```
整条消息 17 字节数据 + 10 字节头 + 1 长度字节 + 2 校验和 = 30 字节；9600 波特下约 31 ms 发完。

## 7 消息字典速查（按 Stream 分类）

| Stream | 类别 | 方向要点 |
|---|---|---|
| 0 | 事务中止（S0F0） | — |
| 1 | 设备状态 | 建立通信、在线识别、状态查询 |
| 2 | 设备控制与诊断 | 远程命令、时间、报表定义、Spooling |
| 3 | 物料状态 | 物料/载具动作请求 |
| 4 | 物料控制 | 物料传输握手 |
| 5 | 异常（报警）处理 | 报警上/下报与使能 |
| 6 | 数据采集 | 事件报告、追迹数据 |
| 7 | 工艺程序（配方）管理 | 配方上传/下载/删除/校验 |
| 8 | 控制程序传送 | 引导/执行程序 |
| 9 | 系统错误 | 设备侧错误回告 |
| 10 | 终端服务 | 主机消息显示 |
| 11 | （已删除） | — |
| 12 | 晶圆映射 | Map 数据 |

| 消息 | 名称 | 方向 | 应答 |
|---|---|---|---|
| S1F1 | Are You There Request（在线请求） | H↔E | S1F2 |
| S1F2 | On Line Data（在线数据，L:2 {MDLN, SOFTREV}） | 回 S1F1 | — |
| S1F3 | Selected Equipment Status Request（SVID 列表查询；L:0=全部） | H→E | S1F4 |

### Stream 2 设备控制与诊断（常用）

| 消息 | 名称 | 说明 |
|---|---|---|
| S2F13/F14 | Equipment Constant Request/Data | 查询设备常数（L:0=全部） |
| S2F15/F16 | New Equipment Constant Send/Ack（EAC） | 设置设备常数 |
| S2F17/F18 | Date and Time Request/Data（TIME） | 时间查询 |
| S2F31/F32 | Date and Time Set Request/Ack（TIACK） | 时间设置（TIACK=0 成功） |
| S2F33/F34 | Define Report（DRACK） | 定义报表：RPTID → VID 列表 |

## 8 高频消息逐条定义

本章按 E5 原文第 7 章的消息明细（Message Detail）逐条整理联调中使用频率最高的消息：
用途、方向、消息结构（SML 记法）、例外约定与应答码取值。

记法约定：

- `H→E` 主机发设备，`E→H` 设备发主机，`H↔E` 双向皆可；
- `W` 表示主消息置位 Wait-bit、期待应答；`[W]` 表示应答可选；
- `L [n]` 表示含 n 个元素的列表，`L0` 表示空列表（长度字节为 0 的列表）；
- 结构中的 `<XXX>` 为数据项，其可用格式见 6.6 数据项字典。

### 8.1 Stream 1 设备状态

> Stream 1 承载"设备还活着吗、通信建立了吗、你是谁、你的状态变量是多少"这几件事。
> 其中 S1F13/S1F14 是 GEM 建立通信的**唯一正式入口**（见 03-E30 的 3.2 与 4.1）。

#### S1F1 / S1F2 在线探测（R / D）　H↔E，W

**用途**：判断设备是否在线。这是最轻量的链路级探活，不涉及控制状态。

- **S1F1**：仅消息头，无消息体。
- **S1F2**：

```
S1F2
  <L [2]
    <MDLN>        # 设备型号，ASCII，惯例 ≤ 6 字符
    <SOFTREV>     # 软件版本，ASCII，≤ 6 字节
  >
```

**例外**：
1. 主机发 S1F1 时，S1F2 的第 2 项由**主机**填零长度列表（即主机侧不需要回填型号版本）；
2. 收到 **Function 0**（S1F0）作为应答，表示通信不可用——对设备而言等价于发出 S1F1 后收应答计时器超时。

#### S1F3 / S1F4 状态变量查询（SSR / SSD）　H→E，W

**用途**：按 SVID 列表查询状态变量当前值，是主机侧最常用的数据轮询手段。

**S1F3 结构**（新实现统一采用，适用于所有项格式）：

```
S1F3 W
  <L [n]
    <SVID1>
    ...
    <SVIDn>
  >
```

兼容旧结构（仅 SVID 为 3()/5() 整数格式时可用）：`<SVID1,...,SVIDn>`（单 item 存多个值）。

**S1F4 结构**：按请求顺序逐个返回值：

```
S1F4
  <L [n]
    <SV1>
    ...
    <SVn>
  >
```

**例外**：
1. S1F3 发 `L0`（结构 1）或空 item（结构 2）＝**报告全部 SVID**；
2. S1F4 中第 i 项为空 item ＝ **该 SVID 不存在**。

> **实现注意**：S1F4 的取值顺序必须与 S1F3 的请求顺序严格一致，主机按位置而非按名字匹配。
> 返回"不存在的 SVID"时要用**零长度项**而不是 `0`——后者会被主机当成合法数值 0。

#### S1F5–S1F8 固定格式状态（FSR / FSD / FFR / FFD）　H→E，W

**用途**：按预先约定的"状态格式"（SFCD）一次取回一组固定组合的状态，省去逐次协商 SVID 列表。

- **S1F5**：`<SFCD>`（状态格式码，1 字节）；**S1F6**：结构由 SFCD 指定的格式决定，第 i 项为空 item ＝ 无法报告。
- **S1F7**：`<SFCD>`；**S1F8**：返回该格式的**定义**——每个待返回项替换为 `L,2{名称, 零长度格式项}`。

> 这两个消息在 GEM 中**不属于必备能力**，现代主机几乎只用 S1F3/F4 + 事件报告。老设备上仍可能遇到。

#### S1F9 / S1F10 物料传输状态（TSR / TSD）　H→E，W

**用途**：报告**所有物料端口**的传输状态（不是单个载具）。

- **S1F9**：仅消息头。
- **S1F10**：

```
S1F10
  <L [2]
    <TSIP1,...,TSIPn>     # 各输入端口传输状态
    <TSOP1,...,TSOPn>     # 各输出端口传输状态
  >
```

**例外**：某值为空 item ＝ 无此类端口；整个列表为 `L0` ＝ 一个端口都没有。

#### S1F11 / S1F12 变量目录（SVNR / SVNRR）　H→E，W

**用途**：查询 SVID 的**名称与单位**。主机首次接入设备、尚未拿到点表时靠它自举。

- **S1F11**：`<L [n] <SVID1>...<SVIDn>>`；发 `L0` ＝ 全部 SVID。
- **S1F12**：

```
S1F12
  <L [n]
    <L [3]
      <SVID1>
      <SVNAME1>      # 变量名，ASCII
      <UNITS1>       # 单位，ASCII
    >
    ...
  >
```

**例外**：`SVNAME` 与 `UNITS` **同时**为零长度 ASCII 项 ＝ 该 SVID 不存在。

#### S1F13 / S1F14 建立通信（CR / CRA）　H↔E，W

**用途**：在**应用层**（而非 TCP 层）正式建立主机与设备的逻辑通信。上电后、以及任何一次通信中断之后，都必须重新走这个事务。

**S1F13 结构**：

```
S1F13 W
  <L [2]
    <MDLN>
    <SOFTREV>
  >
```

**S1F14 结构**：

```
S1F14
  <L [2]
    <COMMACK>             # 0 = 接受；1 = 拒绝，稍后重试
    <L [2]
      <MDLN>              # 仅当 COMMACK=0 时有效
      <SOFTREV>
    >
  >
```

**例外**：
1. 主机发 S1F13 时，消息体是**零长度列表**（不带型号版本）；
2. 主机发 S1F14 时，第 2 项是零长度列表。

**COMMACK 取值**：0 = 接受；1 = 拒绝，稍后重试；2–63 保留。

**重试规则**（E5 7.5 原文要求）：发起方必须以**可编程的间隔**重复发送 S1F13，直到在事务超时内收到 COMMACK 为"接受"的 S1F14 为止。
这个间隔在 GEM 中由设备常数 `EstablishCommunicationsTimeout` 规定（见 03-E30 的 4.1）。

#### S1F15 / S1F16 请求离线（ROFL / OFLA）　H→E，W

**用途**：主机要求设备进入 OFF-LINE（不再接受主机控制，但仍保持链路）。

- **S1F15**：仅消息头。
- **S1F16**：`<OFLACK>`，取值 0 = 已进入离线；1–63 保留。

> **易错点**：S1F15 只改变**控制状态**，不关闭 HSMS 连接，也不停止报文收发。
> 把"离线"实现成"断链"会让主机误判设备掉线。

#### S1F17 / S1F18 请求在线（RONL / ONLA）　H→E，W

**用途**：主机要求设备进入 ON-LINE，开始接受远程控制。

- **S1F17**：仅消息头。
- **S1F18**：`<ONLACK>`。

**ONLACK 取值**：

| 值 | 含义 |
|---|---|
| 0 | 已接受，进入 ON-LINE |
| 1 | 不允许上线（如通信尚未建立、本地开关处于 LOCAL） |
| 2 | 设备已处于 ON-LINE |
| 3–63 | 保留 |

#### S1F19 / S1F20 宏级对象属性（GA / AD）　H↔E，W

**用途**：按**对象类型 + 对象标识**读取属性，是 Stream 14 对象服务的轻量前置形式，主要服务于物料传输与配方管理。

**S1F19 结构**：

```
S1F19 W
  <L [3]
    <OBJTYPE>
    <L [m]                # m 个对象；m=0 = 该类型下全部对象
      <OBJID1> ... <OBJIDm>
    >
    <L [n]                # n 个属性；n=0 = 按预定顺序返回全部属性
      <ATTRID1> ... <ATTRIDn>
    >
  >
```

**S1F20 结构**：

```
S1F20
  <L [2]
    <L [m]                # 按请求的对象顺序
      <L [n]
        <ATTRDATA1> ... <ATTRDATAn>
      >
      ...
    >
    <L [p]                # p 个错误；无错误时 p=0
      <L [2] <ERRCODE1> <ERRTEXT1> >
      ...
    >
  >
```

**例外**：
1. `m=0` ＝ 指定的 OBJTYPE **未知**；
2. 某个对象下的 `n=0` ＝ 该对象**未找到**；
3. 某条 ATTRDATA 为零长度项 ＝ 该属性**不存在**。

### 8.2 Stream 2 设备控制与诊断

#### S2F13 / S2F14 设备常数查询（ECR / ECD）　H→E，W

**用途**：获取校准值、伺服增益、报警限值、数据采集模式等**不常变化**的设备常数。

**S2F13 结构**（新实现统一采用，适用于所有项格式）：

```
S2F13 W
  <L [n]
    <ECID1>
    ...
    <ECIDn>
  >
```

兼容旧结构（仅 ECID 为 3()/5() 整数格式时可用）：`<ECID1,...,ECIDn>`（单 item 存多个值）。

**例外**：发送 `L0`（结构 1）或空 item（结构 2）＝按设备预定顺序返回**全部** ECV。

**S2F14 结构**：按请求顺序返回常数值：

```
S2F14
  <L [n]
    <ECV1>
    ...
    <ECVn>
  >
```

**例外**：`ECVi` 为空 item 表示 `ECIDi` 不存在；除"空列表"这一特例外，ECV 不允许 List 格式。

#### S2F15 / S2F16 设备常数设置（ECS / ECA）　H→E，W

**用途**：修改一个或多个设备常数。

**S2F15 结构**：

```
S2F15 W
  <L [n]
    <L [2]
      <ECID1>
      <ECV1>
    >
    ...
    <L [2]
      <ECIDn>
      <ECVn>
    >
  >
```

**S2F16 结构**：`<EAC>`（单 item 确认码）。

**EAC 取值**：

| 值 | 含义 |
|---|---|
| 0 | 确认 |
| 1 | 拒绝：至少一个常数不存在 |
| 2 | 拒绝：忙 |
| 3 | 拒绝：至少一个常数超范围 |
| >3 | 其他设备自定义错误（4–63 保留） |

**要点**：EAC 非 0 时设备**不得改变 S2F15 中指定的任何常数**——要么全改要么全不改。

#### S2F17 / S2F18 时间查询（DTR / DTD）　H↔E，W

**用途**：校对设备时基，或让设备与主机时基同步。

- **S2F17**：仅消息头，无消息体。
- **S2F18**：`<TIME>`。空 item 表示无时间。

#### S2F31 / S2F32 时间设置（DTS / DTA）　H→E，W

**用途**：把设备时钟同步为主机时间。

- **S2F31**：`<TIME>`（12 字节 `YYMMDDhhmmss` 或 16 字节 `YYYYMMDDhhmmssCC` 格式）。
- **S2F32**：`<TIACK>`——0 = 成功；1 = 错误未执行（2–63 保留）。

#### S2F33 / S2F34 定义报表（DR / DRA）　H→E，W

**用途**：主机为设备定义一组报表（RPTID → VID 集合）。报表类型由一个布尔"设备常数"指定：False → 事件报告走 **S6F11**；True → 注释事件报告走 **S6F13**。若 S2F33 为多块消息，必须先经 S2F39/S2F40 询问/授权。

**结构**：

```
S2F33 W
  <L [2]
    <DATAID>
    <L [a]              # a 个报表
      <L [2]
        <RPTID1>
        <L [b]          # 该报表含 b 个 VID
          <VID1> ... <VIDb>
        >
      >
      ...
    >
  >
```

**例外**：
1. `<DATAID>` 后跟 `L0` ＝**删除全部**报表定义及其事件链接；
2. `<RPTID>` 后跟 `L0` ＝删除该 RPTID 报表类型，同时删除指向它的全部 CEID 链接。

**S2F34**：`<DRACK>`。检出错误时**整条拒绝**，不允许部分修改。

| DRACK | 含义 |
|---|---|
| 0 | 接受 |
| 1 | 拒绝：空间不足 |
| 2 | 拒绝：格式非法 |
| 3 | 拒绝：至少一个 RPTID 已定义 |
| 4 | 拒绝：至少一个 VID 不存在 |
| >4 | 其他错误（5–63 保留） |

#### S2F35 / S2F36 链接事件报表（LER / LERA）　H→E，W

**用途**：把 n 个报表链接到事件（CEID）。**链接后默认为"禁用"**——事件发生也不会发送报表，直到 S2F37 使能。多块时须先经 S2F39/F40。

**结构**：

```
S2F35 W
  <L [2]
    <DATAID>
    <L [a]              # a 个事件
      <L [2]
        <CEID1>
        <L [b]          # 该事件链接 b 个报表
          <RPTID1> ... <RPTIDb>
        >
      >
      ...
    >
  >
```

**例外**：CEID 后跟 `L0` ＝删除该事件的全部报表链接。

**S2F36**：`<LRACK>`。错误时整条拒绝。

| LRACK | 含义 |
|---|---|
| 0 | 接受 |
| 1 | 拒绝：空间不足 |
| 2 | 拒绝：格式非法 |
| 3 | 拒绝：至少一个 CEID 链接已定义 |
| 4 | 拒绝：至少一个 CEID 不存在 |
| 5 | 拒绝：至少一个 RPTID 不存在 |
| >5 | 其他错误（6–63 保留） |

#### S2F37 / S2F38 事件使能（EDER / EERA）　H→E，W

**用途**：使能或禁用一组事件（CEID）的报告。

**结构**：

```
S2F37 W
  <L [2]
    <CEED>              # Boolean：TRUE=使能，FALSE=禁用
    <L [n]
      <CEID1> ... <CEIDn>
    >
  >
```

**例外**：`<CEED>` 后跟 `L0` ＝作用于**全部** CEID。

**S2F38**：`<ERACK>`——0 = 接受；1 = 拒绝（至少一个 CEID 不存在）；>1 其他错误。错误时整条拒绝。

#### S2F41 / S2F42 远程命令（HCS / HCA）　H→E，W

**用途**：主机请求设备执行指定远程命令（RCMD）并携带参数。

**S2F41 结构**：

```
S2F41 W
  <L [2]
    <RCMD>                      # 命令名，如 "START" / "STOP"
    <L [n]                      # n 个参数（n 可为 0）
      <L [2]
        <CPNAME1>               # 参数名
        <CPVAL1>                # 参数值
      >
      ...
    >
  >
```

**S2F42 结构**：

```
S2F42
  <L [2]
    <HCACK>                     # 命令级确认码
    <L [n]                      # n 个非法参数（无则 L0）
      <L [2]
        <CPNAME1>
        <CPACK1>                # 该参数非法的原因
      >
      ...
    >
  >
```

**例外**：无非法参数时第 2 项发送 `L0`。

**HCACK 取值**：

| 值 | 含义 |
|---|---|
| 0 | 确认，命令已完成 |
| 1 | 命令不存在 |
| 2 | 暂时无法执行（忙） |
| 3 | 参数非法（附非法参数清单） |
| 4 | 已在执行中，无法完成 |
| 5 | 拒绝 |
| 6 | 无操作权限 |
| 7 | 已处于目标状态 |

**CPACK 取值**：1 = 参数名（CPNAME）不存在；2 = CPVAL 值非法；3 = CPVAL 格式非法；>3 = 其他设备自定义错误。

#### S2F23 / S2F24 追迹初始化（TIS / TIA）　H→E，W（多块）

**用途**：按时间函数采样一组状态变量（SVID）。追迹数据经 **S6F1** 返回，以 **TRID** 与原请求关联；设备可允许同时多个追迹请求。

**要点**：
- 收到与进行中追迹相同 TRID 的 S2F23 → 终止旧追迹、启动新追迹；
- 以原 TRID + **TOTSMP=0** 发送 S2F23 → 终止该追迹；
- 多块 S2F23 必须先经 S2F39/F40；部分设备仅支持单块 S6F1，可能拒绝会导致多块 S6F1 的追迹请求；
- 设备须文档化其追迹性能极限；主机不得发送超出极限的请求，否则设备可能工作异常。

**结构**：

```
S2F23 W
  <L [5]
    <TRID>                  # 追迹 ID
    <DSPER>                 # 采样周期：hhmmss（6B）或 hhmmsscc（8B，含厘秒）
    <TOTSMP>                # 总采样数；0 = 终止追迹
    <REPGSZ>                # 每组样本数
    <L [n]
      <SVID1> ... <SVIDn>   # 被采样变量
    >
  >
```

（旧兼容结构仅第 5 项不同：`<SVID1,...,SVIDn>`，限整数格式。）

**S2F24**：`<TIAACK>`——0 = 正确；1 = SVID 过多；2 = 不允许更多追迹；3 = 周期非法；>3 设备自定义错误。

#### S2F29 / S2F30 常数清单（ECNR / ECN）　H→E，W

**用途**：查询设备有哪些设备常数及其基本信息。

- **S2F29**：`<L [n] <ECID1>...<ECIDn>>`；发送 `L0` ＝返回全部 ECID 的信息。
- **S2F30**（多块，E→H）：

```
S2F30
  <L [n]
    <L [6]
      <ECID1>
      <ECNAME1>    # 名称
      <ECMIN1>     # 最小值
      <ECMAX1>     # 最大值
      <ECDEF1>     # 默认值
      <UNITS1>     # 单位
    >
    ...
  >
```

**例外**：ECNAME/ECMIN/ECMAX/ECDEF/UNITS 为空 ASCII 项表示该 ECID 不存在。

#### S2F39 / S2F40 多块询问与授权（DMBI / DMBG）　H→E，W

**用途**：S2F23 / S2F33 / S2F35 / S2F45 / S2F49 超过一个块时，发送前**必须**先完成本事务（询问/授权/发送/确认会话）。

- **S2F39**：`<L [2] <DATAID> <DATALENGTH>>`
- **S2F40**：`<GRANT>`——0 = 允许；1 = 忙，稍后再试；2 = 无空间；3 = DATAID 重复；>3 设备自定义错误。

#### S2F19 / S2F20 复位/初始化（RIS / RIA）　H→E，W

**用途**：使设备进入若干预定初始状态之一。

- **S2F19**：`<RIC>`（复位码，1 字节）——0 = 未用；**1 = 上电复位**；>1 = 其他复位条件（2–63 保留）。
- **S2F20**：`<RAC>`（复位应答）——0 = 同意执行复位；1 = 拒绝复位；>1 = 其他错误（2–63 保留）。

#### S2F21 / S2F22 远程命令·旧式（RCS / RCA）　H→E，[W]

**用途**：类似按下前面板按钮，或引发/终止某项设备活动。**不带参数**；GEM 远程控制推荐使用 S2F41（带参数），本消息为早期形式，老设备仍常见。

- **S2F21**：`<RCMD>`（远程命令码或字符串，格式 20/31/51）。
- **S2F22**：`<CMDA>`——0 = 已完成；1 = 命令不存在；2 = 暂时无法执行；>2 = 其他设备自定义错误（3–63 保留）。与 S2F28（加工启动应答）共用该数据项。

#### S2F43 / S2F44 Spooling 流/功能配置（RSSF / RSA）　H→E，W

**用途**：主机选择 Spooling 激活期间，哪些 Stream/Function 的消息进入 Spool 暂存（GEM Spooling 能力的配置消息）。

**S2F43 结构**：

```
S2F43 W
  <L [m]                  # m 个流（m=0 关闭全部 spooling）
    <L [2]
      <STRID1>            # 流号（U1）
      <L [n]              # n 个功能号（n=0 = 该流全部功能）
        <FCNID1> ... <FCNIDn>
      >
    >
    ...
  >
```

**注记**（原文 Notes）：
1. 关闭某个流的全部 spooling 的方法是**在本消息中不提及该流**；
2. **Stream 1 不允许 spool**；
3. 设备必须允许主机 spool 一个流的所有主消息（Stream 1 除外）；
4. 本消息中为某流定义的功能清单将**替换**先前选择的功能清单。

**S2F44 结构**（多块，E→H）：

```
S2F44
  <L [2]
    <RSPACK>              # 0 = 接受；1 = 拒绝（2–63 保留）
    <L [m]                # m = 出错的流数；RSPACK=0 时为 L0
      <L [3]
        <STRID1>
        <STRACK1>         # 该流的错误码
        <L [n]            # n = 该流出错的功能数；n=0 表示该流无功能级错误
          <FCNID1> ... <FCNIDn>
        >
      >
      ...
    >
  >
```

#### S2F45 / S2F46 限值属性定义（DVLA / VLAA）　H→E，W（多块）

**用途**：为被监测变量（VID）定义限值——每条限值由一对死区边界（UPPERDB/LOWERDB）构成，是 GEM **限值监测（Limits Monitoring）**能力的配置消息。多块时须先经 S2F39/F40。

**结构**：

```
S2F45 W
  <L [2]
    <DATAID>
    <L [m]                    # m 个变量
      <L [2]
        <VID1>
        <L [n]                # 为 VID1 定义/变更 n 条限值
          <L [2]
            <LIMITID1>
            <L [p]            # p = 0 或 2
              <UPPERDB1>      # 死区上边界
              <LOWERDB1>      # 死区下边界
            >
          >
          ...
        >
      >
      ...
    >
  >
```

**例外**（置"未定义"语义）：
1. `m=0`（顶层 L0）＝**全部被监测变量**的所有限值置"未定义"；
2. `n=0` ＝该 VID 的所有限值置"未定义"；
3. `p=0`（LIMITID 后跟 L0）＝该条限值置"未定义"。

**S2F46 结构**（多块，E→H）——若 DVLA 因参数非法被拒（如 LVACK=3 一类情况），返回非法属性清单及拒绝原因；检出错误时**整条拒绝**，不允许部分修改：

```
S2F46
  <L [2]
    <VLAACK>
    <L [m]                    # m = 非法参数个数；m=0 表示无
      <L [3]
        <VID1>                # 出错的变量
        <LVACK1>              # 拒绝原因（变量级）
        <L [n]                # n = 0 或 2；该变量出错的限值
          <LIMITID1>
          <LIMITACK1>         # 拒绝原因（限值级）
        >
      >
      ...
    >
  >
```

**应答码取值**：

| 码 | 层级 | 取值 |
|---|---|---|
| VLAACK | 命令级 | 0 = 确认将执行；1 = 限值属性定义错误；2 = 暂时无法执行；>2 其他设备自定义错误 |
| LVACK | 变量级 | 1 = 变量不存在；2 = 变量无限值能力；3 = 消息中变量重复；4 = 限值错误（详见 LIMITACK） |
| LIMITACK | 限值级 | 1 = LIMITID 不存在；2 = UPPERDB > LIMITMAX；3 = LOWERDB < LIMITMIN；4 = UPPERDB < LOWERDB；5 = UPPERDB/LOWERDB 格式非法；6 = ASCII 值无法转换为数值；7 = 该变量限值定义重复；>7 其他（8–63 保留） |

#### S2F47 / S2F48 限值属性查询（VLAR / VLAS）　H→E，W

**用途**：查询设备当前的变量限值属性定义。

- **S2F47**：`<L [m] <VID1>...<VIDm>>`；发送 `L0`（m=0）＝请求**全部支持限值属性的 VID 清单**。
- **S2F48**（多块，E→H）：

```
S2F48
  <L [m]                    # 按请求顺序返回
    <L [2]
      <VID1>
      <L [p]                # p = 0 或 4
        <UNITS1>            # 单位
        <LIMITMIN1>          # 限值允许的最小值（厂商规定）
        <LIMITMAX1>          # 限值允许的最大值（厂商规定）
        <L [n]              # 该 VID 已定义的 n 条限值
          <L [3]
            <LIMITID1>
            <UPPERDB1>
            <LOWERDB1>
          >
          ...
        >
      >
    >
    ...
  >
```

**例外**：`p=0` ＝该 VID **不支持**限值；`n=0` ＝该变量当前未定义任何限值。

**要点**：UPPERDB 与 LOWERDB **成对**定义一条限值（死区上下边界）；LIMITMIN/LIMITMAX 是限值本身的允许范围，通常与被监测变量的最小/最大值一致，**格式必须与被监测变量一致**。

#### S2F49 / S2F50 增强远程命令　H→E，W（多块）

**用途**：主机请求**对象**（而非整台设备）执行带参数的远程命令——对象服务（E39/E40 等）时代的远程控制形式。多块时须先经 S2F39/F40。

**S2F49 结构**：

```
S2F49 W
  <L [4]
    <DATAID>
    <OBJSPEC>                # 对象实例标识
    <RCMD>
    <L [m]                   # m 个参数组；m=0 表示无参数
      <L [2]
        <CPNAME1>
        <CEPVAL1>            # 增强参数值
      >
      ...
    >
  >
```

**OBJSPEC 格式**：指向特定对象实例的文本串，由若干格式化子串构成，每个子串含四段——`对象类型` + `:`（冒号终止类型）+ `对象标识` + `>`（大于号终止标识）。对象类型在可推断时可省略；末尾的 `>` 可选。

**CEPVAL 三种形态**：① 单值（同 CPVAL）；② **同格式**单值组成的列表；③ CPNAME/CEPVAL 对的列表（可嵌套）：

```
A) L,2                      B) L,2
   1. <CPNAMEa>                1. <CPNAMEb>
   2. L,m                      2. L,n
      1. <CPVALa1>                1. L,2
      2. <CPVALa2>                   1. <CPNAMEb1>
      ...                            2. <CEPVALb1>
      m. <CPVALam>                ...
                                    n. L,2
                                       1. <CPNAMEbn>
                                       2. <CEPVALbn>
```

**要点**：某个 CPNAME 的 CEPVAL 一旦定义为 LIST，就必须**始终**为 LIST；若对该 CPNAME 发送非 LIST 的 CEPVAL，将导致格式错误。OBJSPEC 可为空长度项。

**S2F50 结构**：

```
S2F50
  <L [2]
    <HCACK>                  # 取值同 S2F42（0–7）
    <L [n]                   # n 个非法参数；无则 L0
      <L [2]
        <CPNAME1>
        <CEPACK1>
      >
      ...
    >
  >
```

**CEPACK 取值**：0 = 无错误；1 = CPNAME 不存在；2 = CEPVAL 值非法；3 = CEPVAL 格式非法；4 = CPNAME 在此用法中无效；5–63 保留。若对应 CEPVAL 为 LIST，则 CEPACK 须与该列表**同构**（而非单字节整数）。

### 8.3 Stream 3 物料状态

> Stream 3 用于传送物料（含载具与在制物料）的信息与动作、完成时间信息及异常物料事件。现代 300mm 设备的载具管理多已改用 E87 对象服务（Stream 14），但 E30 的物料移动能力仍引用本流消息，老设备联调中常见。

#### S3F1 / S3F2 物料状态请求 / 数据（MSR / MSD）　H→E，W

**用途**：主机请求设备报告全部在制物料的状态。

- **S3F1**：仅消息头。
- **S3F2**（多块，E→H）：

```
S3F2
  <L [2]
    <MF>              # 物料量纲：1=晶圆 2=卡匣 3=芯片 4=舟 5=晶锭 6=框架 7=批 8=弹匣
    <L [m]            # m 个位置
      <L [3]
        <LOC1>        # 位置
        <QUA1>        # 数量
        <MID1>        # 物料 ID
      >
      ...
    >
  >
```

**例外**：返回 `L0` 表示无此类数据。

#### S3F3 / S3F4 完成时间请求 / 数据（TCR / TCD）　H→E，W

**用途**：主机查询设备持有物料的预计完成时间。

- **S3F3**：仅消息头。
- **S3F4**（多块）：结构与 S3F2 相同，仅每组为 `L,3 {TTC, QUA, MID}`（TTC 为完成时间）。

#### S3F5 / S3F6 与 S3F7 / S3F8 物料发现 / 物料丢失　E→H，[W]

**用途**：设备主动通知——
- **S3F5（MFS）**：无预约物料出现在某传感器；
- **S3F7（MLS）**：物料从传感器上消失。

```
S3F5
  <L [2] <MF> <QUA> >

S3F7
  <L [3] <MF> <QUA> <MID> >
```

**应答**：S3F6 / S3F8 均为 `<ACKC3>`——0 = 接受；>0 = 错误不接受。

#### S3F11 / S3F12 物料 ID 请求（MIDR / MIRA）　E→H，W

**用途**：设备询问主机指定端口上物料的 ID。

- **S3F11**：`<PTN>`（端口号，1 字节）。
- **S3F12**：

```
S3F12
  <L [3]
    <PTN>
    <MIDRA>           # 应答码
    <MID>             # MIDRA=0 时有效
  >
```

**MIDRA 取值**：

| 值 | 含义 |
|---|---|
| 0 | 接受，MID 直接跟随（空 MID 表示无可用 ID） |
| 1 | 接受，但不会发送 MID |
| 2 | 接受，稍后以 S3F13 发送 MID（"请求/确认/发送/确认"四步会话） |

**MIDRA 语义**：除 MIDRA=0 外，其余取值时消息中的 MID 被接收方忽略。MIDRA=2 时主机稍后用 **S3F13/F14** 事务发送 MID；设备等待 S3F13 超时将发 S9F13（会话超时）或以 S3F11 重启会话。

#### S3F13 / S3F14 物料 ID 发送（MIS / MIA）　H→E，W

**用途**：主机把指定端口物料的 ID 发给设备（通常跟随 MIDRA=2 的 S3F12）。

- **S3F13**：`<L [2] <PTN> <MID>>`；空 MID 表示无可用 ID。
- **S3F14**：`<MIDAC>`（确认或错误码）。

#### S3F17 / S3F18 载具动作请求 / 应答　H→E，W（多块）

**用途**：请求对指定载具执行某项动作（如载具搬运预约/取消等）。多块时必须先经 S3F11/F12 事务（原文如此，E5-0301 的规定）。

**S3F17 结构**：

```
S3F17 W
  <L [5]
    <DATAID>
    <CARRIERACTION>       # 请求的动作
    <CARRIERSPEC>         # 载具对象标识（符合 OBJSPEC）
    <PTN>                 # 端口号；CARRIERSPEC 非空时可置空项
    <L [n]                # n 个载具属性（n=0 表示无）
      <L [2]
        <CATTRID1>        # 属性名
        <CATTRDATA1>      # 属性值
      >
      ...
    >
  >
```

**S3F18 结构**：

```
S3F18
  <L [2]
    <CAACK>               # 载具动作确认码
    <L [n]                # 错误列表（n=0 表示无错误）
      <L [2]
        <ERRCODE1>
        <ERRTEXT1>
      >
      ...
    >
  >
```

**CAACK 取值**：

| 值 | 含义 |
|---|---|
| 0 | 确认，命令已执行 |
| 1 | 无效命令 |
| 2 | 暂时无法执行 |
| 3 | 数据或参数无效 |
| 4 | 确认，稍后以事件通知完成 |
| 5 | 拒绝：状态无效 |
| 6–63 | 保留 |

#### S3F19 / S3F20 取消全部待出载具请求　H→E，W

**用途**：取消所有未完成的载具出站请求。

- **S3F19**：仅消息头。
- **S3F20**：应答（含 CAACK 确认码）。

#### S3F9 / S3F10 物料 ID 等同（IES / IEA）　E→H，W

**用途**：设备为某物料 ID 提供一个**等价的替代名**（EMID），供后续引用。

- **S3F9**：`<L [2] <MID> <EMID>>`（原 ID + 等价 ID，均最多 16 字符）。
- **S3F10**：`<ACKC3>`——0 = 接受；>0 = 错误不接受（1–63 保留）。

#### S3F15 / S3F16 物料多块询问/授权（MMBI / MMBG）　H→E，W

**用途**：Stream 3 中发送**任何多块主消息**前，必须先以本事务按消息总长请求许可（Stream 3 版的询问/授权/发送/确认会话）。

- **S3F15**：`<L [2] <DATAID> <DATALENGTH>>`
- **S3F16**：`<GRANT>`（取值同 S2F40：0 = 允许；1 = 忙稍后再试；2 = 无空间；3 = DATAID 重复；>3 设备自定义错误）。

#### S3F21 / S3F22 端口组定义　H→E，W

**用途**：定义端口组内的端口，并提供初始端口访问方式。

- **S3F21**：

```
S3F21 W
  <L [3]
    <PORTGRPNAME>        # 端口组标识
    <PORTACCESS>         # 端口访问方式（E5-0301 数据项字典未单列其取值，由设备文档定义）
    <L [n]
      <PTN1> ... <PTNn>  # 组内端口号
    >
  >
```

- **S3F22**：`<L [2] <CAACK> <L [n] {L,2 {ERRCODE, ERRTEXT}>>>`；`n=0` 表示无错误。

#### S3F23 / S3F24 端口组动作请求 / 应答　H→E，W

**用途**：对端口组执行动作——可改变其访问模式，或删除该端口组。

- **S3F23**：

```
S3F23 W
  <L [3]
    <PGRPACTION>         # 对端口组执行的动作
    <PORTGRPNAME>
    <L [m]               # m 个参数；m=0 表示无参数
      <L [2]
        <PARAMNAME1>
        <PARAMVAL1>
      >
      ...
    >
  >
```

（PARAMVAL 若为列表，仅限**同格式**单值列表。）

- **S3F24**：`<L [2] <CAACK> <L [n] {L,2 {ERRCODE, ERRTEXT}>>>`；`n=0` 无错误。

#### S3F25 / S3F26 端口动作请求 / 应答　H→E，W

**用途**：对**单个端口**执行动作。

- **S3F25**：按原文排印为 `L,2` 且元素编号跳号（1、2 之后直接 4–8），按语义应为三元素结构（原文如此）：

```
S3F25 W
  <L [3]
    <PORTACTION>         # 对端口执行的动作
    <PTN>                # 端口号
    <L [m]               # m 个参数；m=0 表示无参数
      <L [2]
        <PARAMNAME1>
        <PARAMVAL1>
      >
      ...
    >
  >
```

- **S3F26**：`<L [2] <CAACK> <L [n] {L,2 {ERRCODE, ERRTEXT}>>>`；`n=0` 无错误。

### 8.4 Stream 5 异常（报警）处理

> Stream 5 分两代：**F1–F8 是基础报警**（ALCD/ALID/ALTX 三元组），GEM 只要求这一组；
> **F9–F18 是扩展异常处理**（带异常 ID、恢复动作、恢复结果），属可选增强。
> 混用两代会话会造成主机侧状态错乱——先确认对端支持哪一组。

#### S5F1 / S5F2 报警上报（ARS / ARA）　E→H，[W]

**用途**：报警**置位**时发一条，**清除**时再发一条。不可恢复错误与注意标志可能没有对应的清除消息。

**S5F1 结构**：

```
S5F1
  <L [3]
    <ALCD>        # 报警码字节
    <ALID>        # 报警标识
    <ALTX>        # 报警文本，最长 40 字符
  >
```

**ALCD 位定义**（E5 6.6）：

| 位 | 含义 |
|---|---|
| 位 8 | 1 = 报警置位；0 = 报警清除 |
| 位 7–1 | 报警类别码 |

**报警类别码取值**：

| 值 | 类别 | 说明 |
|---|---|---|
| 0 | Not used | 未分类 |
| 1 | Personal safety | 可能危及**人身** |
| 2 | Equipment safety | 可能损坏**设备** |
| 3 | Parameter control warning | 参数超出预设限值，可能影响**产品** |
| 4 | Parameter control error | 参数超出合理控制限，可能表示设备故障 |
| 5 | Irrecoverable error | 需人工干预才能恢复使用 |
| 6 | Equipment status warning | 出现异常但可继续运行 |
| 7 | Attention flags | 工艺程序到达某一特定步骤的信号 |
| 8 | Data integrity | 可能导致数据丢失，通常与 Stream 6 相关 |
| 9–63 | Reserved | |

**S5F2**：`<ACKC5>`——0 = 接受；>0 = 错误未接受（1–63 保留）。

> **GEM 的限制**：E30 §5.1 明确规定，GEM 实现中 **ALCD 只使用位 8**（置位/清除），
> 位 1–7 的类别码**不使用**。因此 GEM 设备回 ALCD 时类别位为 0 是合规的；
> 类别码只在非 GEM 的纯 SECS-II 设备上才有意义。这一点与某些评审意见相左，见
> [E30 项目对照](../project/E30-GEM-项目对照.md) 的说明。

#### S5F3 / S5F4 报警使能/禁用（EAS / EAA）　H→E，[W]

**用途**：改变单个报警的使能位。使能位决定该报警**是否上报主机**；不可控报警不受影响。

**S5F3 结构**：

```
S5F3
  <L [2]
    <ALED>        # 位 8：1 = 使能；0 = 禁用
    <ALID>        # 零长度项 = 作用于全部报警
  >
```

**S5F4**：`<ACKC5>`。

#### S5F5 / S5F6 报警清单（LAR / LAD）　H→E，W

**用途**：请求设备报告其已知的全部报警（**不论使能状态**）。

- **S5F5**：`<ALID1,...,ALIDn>`；**空 item ＝ 返回全部报警**（忽略 ALED 状态）。
- **S5F6**：

```
S5F6
  <L [m]
    <L [3] <ALCD1> <ALID1> <ALTX1> >
    ...
  >
```

**例外**：`m=0` ＝ 无法给出应答；某条 ALCD 或 ALTX 为零长度项 ＝ 该值不存在。

#### S5F7 / S5F8 已使能报警清单（LEAR / LEAD）　H→E，W

- **S5F7**：仅消息头。
- **S5F8**：结构与 S5F6 相同，但**只列已使能**的报警。

#### S5F9–S5F18 扩展异常处理（可选能力）

这一组把"报警"抽象成带生命周期的**异常（exception）**：置位 → 主机确认 → （可选）执行恢复动作 → 恢复完成/中止。

**S5F9 异常置位通知（EXPN）**　E→H，[W]　**必须单块**

```
S5F9
  <L [5]
    <TIMESTAMP>
    <EXID>              # 异常唯一标识，≤ 20 字符
    <EXTYPE>            # "ALARM" 或 "ERROR"
    <EXMESSAGE>         # 异常性质描述
    <L [n]              # n 个可选恢复动作；n=0 表示无可用恢复动作
      <EXRECVRA1> ... <EXRECVRA n>   # 每条 ≤ 40 字节
    >
  >
```

**S5F10 异常置位确认（EXPC）**　H→E：仅消息头。

**S5F11 异常清除通知（EXCN）**　E→H，[W]：`L [4] {TIMESTAMP, EXID, EXTYPE, EXMESSAGE}`，无恢复动作列表。

**S5F12 异常清除确认（EXCC）**　H→E：仅消息头。

**S5F13 异常恢复请求（EXRR）**　H→E，W：`L [2] {EXID, EXRECVRA}`——主机指定执行哪个恢复动作。

**S5F14 异常恢复应答（EXRA）**　E→H：

```
S5F14
  <L [2]
    <EXID>
    <L [2]
      <ACKA>            # Boolean：TRUE = 成功
      <L [m]            # m 只能是 0 或 2；恢复被接受时为 L0
        <ERRCODE1>
        <ERRTEXT1>
      >
    >
  >
```

**S5F15 恢复完成通知（EXRCN）**　E→H，[W]：`L [3] {TIMESTAMP, EXID, L [2] {ACKA, L [m]{ERRCODE, ERRTEXT}}}`。
恢复成功时 `m=0`。

**S5F16 恢复完成确认（EXRCC）**　H→E：仅消息头。

**S5F17 恢复中止请求（EXRAR）**　H→E，W：`<EXID>`。

**S5F18 恢复中止应答（EXRAA）**　E→H：结构与 S5F14 相同；中止成功时 `m=0`。

**EXTYPE 常用取值**：`"ALARM"`、`"ERROR"`（ASCII 文本，通常是单个词）。

### 8.5 Stream 6 数据采集

> Stream 6 是 GEM 的**数据出口**：事件报告（S6F11）、追迹（S6F1）、离散变量（S6F3/F9）、
> 单报表查询（S6F19–F22）、Spool 补发（S6F23/F24）都走这里。
> 其中 **S6F11 是 GEM 设备最高频的一条消息**，结构错一位就整条错位。

#### S6F1 / S6F2 追迹数据（TDS / TDA）　E→H，[W]

**用途**：按 S2F23 设定的采样周期，把一组 SVID 的采样值成批送回主机。追迹是"时间驱动"的状态采集。

**S6F1 结构**：

```
S6F1
  <L [4]
    <TRID>              # 追迹 ID，与 S2F23 关联
    <SMPLN>             # 样本号
    <STIME>             # 采样时间
    <L [n]              # 值按 样本 × SVID 顺序扁平排列
      <SV1> ... <SVn>
    >
  >
```

**例外**：`STIME` 为零长度项 ＝ 不提供时间，接收方须按 SMPLN 与请求时的采样周期推算。

**分块规则**：即便 S6F1 是多块消息，**也不需要**先做询问/授权事务——主机发出的 S2F23 本身即构成隐式授权。
但部分设备只支持单块 S6F1，此时它可以拒绝那些会导致多块 S6F1 的 S2F23。

**S6F2**：`<ACKC6>`——0 = 接受；>0 = 错误。

#### S6F3 / S6F4 离散变量数据（DVS / DVA）　E→H，[W]

**用途**：由**事件**（而非时间）触发的数据报告，是 S6F11 出现之前的旧式事件上报形式。

```
S6F3
  <L [3]
    <DATAID>
    <CEID>
    <L [n]
      <L [2]
        <DSID1>
        <L [m]
          <L [2] <DVNAME1> <DVVAL1> >
          ...
        >
      >
      ...
    >
  >
```

多块时须先经 S6F5/S6F6。**S6F4**：`<ACKC6>`。

#### S6F5 / S6F6 多块询问与授权（MBI / MBG）　E→H，W

**用途**：S6F3/F9/F11/F13/F25 需要多块发送时，**发送前必须先完成本事务**。

- **S6F5**：`<L [2] <DATAID> <DATALENGTH>>`
- **S6F6**：`<GRANT6>`

**GRANT6 取值**：

| 值 | 含义 |
|---|---|
| 0 | 允许发送 |
| 1 | 忙，稍后再试 |
| 2 | 无兴趣（不接受该数据） |
| 3–63 | 其他错误 |

#### S6F7 / S6F8 数据传送请求/数据（DDR / DDD）　H→E，W

- **S6F7**：`<DATAID>`。
- **S6F8**：结构与 S6F3 类似；请求的数据无法发送时返回**零长度项**。

#### S6F9 / S6F10 格式化变量发送（FVS / FVA）　E→H，[W]

**用途**：与 S6F3 相同，但变量名来自主机已知的**预定义格式**（PFCD），报文中省略变量名，因而更紧凑。

```
S6F9
  <L [4]
    <PFCD>              # 预定义格式码
    <DATAID>
    <CEID>
    <L [n]
      <L [2] <DSID1> <L [m] <DVVAL1>...<DVVALm> > >
      ...
    >
  >
```

**S6F10**：`<ACKC6>`。

#### S6F11 / S6F12 事件报告（ERS / ERA）　E→H，W

**用途**：事件（CEID）发生时，把已定义、已链接、已使能的报表组一次性发给主机。这是 GEM 事件通知能力的核心消息。

**S6F11 结构**：

```
S6F11 W
  <L [3]
    <DATAID>            # U4，无特殊含义时填 0
    <CEID>              # 采集事件 ID
    <L [a]              # a 个报表；a=0 表示该事件未链接任何报表
      <L [2]
        <RPTID1>
        <L [b]          # 该报表含 b 个变量值
          <V1> ... <Vb>
        >
      >
      ...
    >
  >
```

**例外**：
1. 若事件未链接报表，视为一个 `null` 报表；
2. 报表列表 `L0` ＝ 该 CEID 未链接任何报表。

> **三个高频结构性错误**（真实主机对接失败的主因）：
> 1. 漏掉 `DATAID`，把消息体写成 `L[2]{CEID, L{报表}}`——主机按 L3 解析会整体错位；
> 2. `RPTID` 与 `L{b}` 之间漏一层，写成扁平结构；
> 3. 变量值顺序与 S2F33 定义 VID 的顺序不一致——值能解析，但语义全错。
>
> 本项目的 P0-2 即第 1 类问题，见 [全量评审 2026-10-20../../reports/code-review-2026-10-20.md)。

**S6F12**：`<ACKC6>`。

#### S6F13 / S6F14 注释事件报告（AERS / AERA）　E→H，W

**用途**：与 S6F11 相同，但每个变量**带上 VID**，接收方不依赖报表定义即可解析。代价是报文更长。

```
S6F13
  <L [3]
    <DATAID>
    <CEID>
    <L [a]
      <L [2]
        <RPTID1>
        <L [b]
          <L [2] <VID1> <V1> >
          ...
        >
      >
      ...
    >
  >
```

**S6F14**：`<ACKC6>`。

> 走 S6F11 还是 S6F13，由主机的布尔型**设备常数**决定（E5 S2F33 原文：False → S6F11，True → S6F13）。

#### S6F15–S6F18 按事件请求报表（ERR / ERD / AERR / AERD）　H→E，W

- **S6F15**：`<CEID>`；**S6F16**：结构与 S6F11 相同（不带 VID）。
- **S6F17**：`<CEID>`；**S6F18**：结构与 S6F13 相同（带 VID）。
- **例外**：返回零长度项 ＝ 该 CEID 未链接报表。

#### S6F19–S6F22 按报表请求数据（IRR / IRD / AIRR / AIRD）　H→E，W

- **S6F19**：`<RPTID>`；**S6F20**：`L [n] <V1>...<Vn>`，`n` 为该报表定义的变量数。
- **S6F21**：`<RPTID>`；**S6F22**：`L [n] {L,2 {VID, V}}`。
- **例外**：`L0` ＝ 该 RPTID 未定义。

#### S6F23 / S6F24 请求 Spool 数据（RSD / RSDAS）　H→E，W

**用途**：通信恢复后，主机请求设备补发暂存的消息，或清空暂存区。

- **S6F23**：`<RSDC>`——**0 = 发送暂存消息；1 = 清除暂存消息**；2–63 保留。
- **S6F24**：`<RSDA>`。

**RSDA 取值**：

| 值 | 含义 |
|---|---|
| 0 | 正常 |
| 1 | 拒绝：忙，稍后再试 |
| 2 | 拒绝：无暂存数据 |
| 3–63 | 保留 |

#### S6F25 / S6F26 通知报告（可选）

**用途**：变更通知（change notification）或确认报告（confirmation report）。
确认报告用于"延迟动作"——请求的应答已先返回，动作真正完成时再用本消息通知结果。

```
S6F25
  <L [7]
    <DATAID>
    <OPID>              # 变更通知时为零长度项
    <LINKID>            # 非零表示后续还有同一 OPID 的完成报告；变更通知时为零长度项
    <RCPSPEC>
    <RMCHGSTAT>
    <L [m] <L [2] <RCPATTRID> <RCPATTRDATA> > ... >
    <L [2]
      <RMACK>
      <L [p] <L [2] <ERRCODE> <ERRTEXT> > ... >   # p=0 表示无错误
    >
  >
```

**S6F26**：`<ACKC6>`。

#### S6F27–S6F30 追迹报告（较新形式，可选）

| 消息 | 方向 | 结构 |
|---|---|---|
| S6F27 Trace Report Send | E→H | `L [3] {DATAID, TRID, L [n]{L [p]{L,2{RPTID, L{m}{V}}}}}` |
| S6F28 Trace Report Acknowledge | H→E | `<TRID>` |
| S6F29 Trace Report Request | H→E | `<TRID>` |
| S6F30 Trace Report Data | E→H | `L [3] {TRID, L [n]{L,2{RPTID, L{m}{V}}}, ERRCODE}` |

**例外**：TRID 未知时返回 `L0`；无错误时第 3 项 ERRCODE 为零长度项。

### 8.6 Stream 9 系统错误

> Stream 9 是**设备单向回告**主机"你刚发的报文我处理不了，原因是 X"。
> 它是排障的第一手线索：主机侧收到的 S9Fx 直接指出报文在哪一层出问题。

**三条基本规则**：

1. **只有设备发** S9Fx，主机不回 S9Fx；
2. **S9 自身出错不再回 S9**（否则无限循环）；
3. **通信失败（Communication Failure）不发 S9**——SECS-I 中特指重试次数超过 RTY 的情形。
   通信**故障**（超时）与**报文故障**（内容/长度不合法）才发 S9。

#### 携带原始块头的四条（Message Fault）

| 消息 | 名称 | 触发原因 |
|---|---|---|
| **S9F1** | Unrecognized Device ID（UDN） | 块头里的 Device ID 在接收方不存在 |
| **S9F3** | Unrecognized Stream Type（USN） | 无法识别 Stream |
| **S9F5** | Unrecognized Function Type（UFN） | 能识别 Stream，但无法识别 Function |
| **S9F7** | Illegal Data（IDN） | Stream/Function 都能识别，但数据格式无法解析 |
| **S9F11** | Data Too Long（DLN） | 主机发来的数据超出设备能处理的上限 |

结构统一为 `<MHEAD>`（**10 字节**，即出错报文的块头原样回带）。

#### S9F9 事务超时（TTN）

- **结构**：`<SHEAD>`——与事务计时器相关的**已存块头**。
- **语义**：期望的应答在 T3 内未到达，事务已中止。后续如何处理由主机决定。

> 与 S9F1/F3/F5/F7 的区别：那四条回带的是**收到的报文**的块头，S9F9 回带的是**期望收到但没收到**的那条报文的块头线索。

#### S9F13 会话超时（CTN）

```
S9F13
  <L [2]
    <MEXP>        # 期望的消息，形如 "S07F03"
    <EDID>        # 期望的数据标识
  >
```

**EDID 的格式取决于 MEXP**：

| 期望的消息 | EDID 内容 |
|---|---|
| S2F3 | `<SPID>`，A[6] |
| S3F13 | `<PTN>`，B[1] |
| S7F3 | `<PPID>`，A[80] 或 B[80] |

**语义**：会话（多事务序列）在中途未按预期推进，设备已释放占用的资源。
典型触发：发出 S2F33 询问后主机迟迟不发授权/数据；或 S3F12 回 MIDRA=2 后主机不发 S3F13。

### 8.7 Stream 10 终端服务

> Stream 10 只做一件事：**在主机与设备操作员终端之间传文本**。
> 设备不解释文本内容，只负责显示或转发；人工响应时间由主机管理。
> GEM 只要求 F3/F4（主机→设备单行显示），其余为可选。

#### S10F1 / S10F2 终端请求（TRN / TRA）　E→H，[W]

操作员在设备终端上输入的文本，发往主机。

```
S10F1
  <L [2]
    <TID>         # 终端号：0 = 单终端/主终端；>0 = 附加终端
    <TEXT>        # 单行文本
  >
```

**S10F2**：`<ACKC10>`。

#### S10F3 / S10F4 单行显示（VTN / VTA）　H→E，[W]

主机要求设备在指定终端显示一行文本。**这是 GEM 终端服务能力的核心消息。**

```
S10F3
  <L [2]
    <TID>
    <TEXT>
  >
```

**S10F4**：`<ACKC10>`。

**ACKC10 取值**：

| 值 | 含义 |
|---|---|
| 0 | 已接受，将显示 |
| 1 | 不显示该消息（如文本过长） |
| 2 | 终端不可用 |
| 3–63 | 保留 |

> **GEM 额外要求**（E30 4.8）：设备必须有 "New Host Message" 指示灯与消息确认按钮，
> 操作员确认后产生 **Message Recognition** 采集事件。仅回 ACKC10=0 而没有确认机制不算合规。

#### S10F5 / S10F6 多行显示（VTN / VMA）　H→E，[W]

```
S10F5
  <L [2]
    <TID>
    <L [N]           # N 行文本
      <TEXT1> ... <TEXTN>
    >
  >
```

**S10F6**：`<ACKC10>`。

#### S10F7 不允许多块（MNN）　E→H

终端不支持多块显示时的错误回告：`<TID>`。

#### S10F9 / S10F10 广播（BCN / BCA）　H→E，[W]

- **S10F9**：`<TEXT>`——不指定 TID，设备收到后向**所有**终端显示。
- **S10F10**：`<ACKC10>`。

> 标准假定所有终端都支持广播；不支持的设备应改用多次 S10F3。

## 附：SML（SECS Message Language）记法

SML 用文本表达 SECS-II 消息结构，常见写法：

```
S1F13 W
  <L [2]
    <A "MDLN">
    <A "SOFTREV">
  >.

S6F11 W
  <L [3]
    <U4 10001>          DATAID
    <U4 1502>           CEID
    <L [1]
      <L [2]
        <U4 1001>       RPTID
        <L [3]
          <A "LotID">
          <U4 25>
          <F4 23.5>
        >
      >
    >
  >.
```

- `W` 表示期待应答；
- `<L [n] ...>` 列表，n 为元素个数；
- `<A "…">`、`<U4 n>`、`<F4 x>` 等对应格式码助记符（L/B/BOOLEAN/A/J/I1/I2/I4/I8/F4/F8/U1/U2/U4/U8）。
