## 引言

本指南旨在简化半导体设备接口及其通信标准的若干原理，**不能替代标准本身**——它只覆盖标准的部分细节，仅作为支持此类接口应用的概览。

## SECS 概述

SECS（Semiconductor Equipment Communication Standard）属于 SEMI 标准的 E4 与 E5（设备自动化/软件卷），1980 年由惠普（HP）开发。SECS 是经 RS-232 的点对点协议。

**三层结构**：
```
SECS-II 消息协议（Message Protocol）
SECS-I 块传输协议（Block Transfer Protocol）
RS-232 物理链路（Physical Link）
```

## SECS-II 消息协议

用于在主机与设备间发送 SECS-II 消息。每条 SECS-II 通信由一条**主消息（Primary）**与可选的**从应答消息（Secondary）**组成，合称事务（transaction）。

### Stream 与 Function
SECS-II 消息以 Stream（Sx）+ Function（Fy）称呼，如 Stream 1 Function 1 写作 S1F1。Stream 是消息**类别**，Function 是类别内的**具体消息**。主消息 Function 恒为**奇数**；应答为对应偶数（大 1）。

**Stream 类别表**：

| Stream | 类别 |
|---|---|
| 1 | 设备状态 |
| 2 | 设备控制 |
| 3 | 物料状态 |
| 4 | 物料控制 |
| 5 | 报警处理 |
| 6 | 数据采集 |
| 7 | 配方管理 |
| 8 | 控制程序传送 |
| 9 | 系统错误 |
| 10 | 终端服务 |
| 11 | （不用） |
| 12 | 晶圆映射 |
| 13 | 非格式化数据/数据集传送 |

**编号分配**：Stream 0 全部保留；Stream 1–63 的 Function 0–63 保留；Stream 64–127 的 Function 0 保留；其余可**用户自定义**。Function 0 在所有 Stream 中保留用于表示"事务中止"的应答。

### 消息布局（Layout）
消息布局（message layout）定义消息的全部数据项，即 Stream/Function 记号之后的部分。例如：

```
S2F41
<L
  <A "START">
  <L>
>.
```

接口手册（Interface Manual）通常由设备商提供，详列适用的 SECS 消息与布局，可附"数据项字典"（Data Item Dictionary）。

### 数据项（Data Items）
布局中的数据项由**格式码（format code）**定义（6 位）：

| 数据项类型 | 格式码（二进制） |
|---|---|
| List（列表） | 000000 |
| Binary | 001000 |
| Boolean | 001001 |
| ASCII | 010000 |
| JIS-8 | 010001 |
| 8 字节有符号整数 | 011000 |
| 1 字节有符号整数 | 011001 |
| 2 字节有符号整数 | 011010 |
| 4 字节有符号整数 | 011100 |
| 8 字节浮点 | 100000 |
| 4 字节浮点 | 100100 |
| 8 字节无符号整数 | 101000 |
| 1 字节无符号整数 | 101001 |
| 2 字节无符号整数 | 101010 |
| 4 字节无符号整数 | 101100 |

List 用于把多个数据项成组，且**列表可嵌套列表**。

### 布局编码（Layout Encoding）
消息发送前须编码布局：每个数据项编码后依次构成**数据结构（Data Structure）**，再经 SECS-I 发送。

**编码后的数据项格式**：
```
第 1 字节：位 7–2 = 数据项类型；位 1–0 = 长度字节数（0~3）
随后 0~3 字节：数据长度
随后 n 字节：数据
```

| 长度字节数 | 最大数据量 |
|---|---|
| 0 | 空项 |
| 1 | 256 字节 |
| 2 | 64 KB |
| 3 | 7.99 MB |

**编码示例**（`S2F41 <L <A "START"> <L>>.`，十六进制）：
```
01        List 项，1 个长度字节
02        列表含 2 个元素
41        ASCII 项，1 个长度字节
05        5 字节
53 54 41 52 54   "START"
01        List 项，1 个长度字节
00        列表含 0 个元素
```

### 多块消息（Multi-Block）
受 SECS-I 数据量限制，编码后的 SECS-II 消息可能装不进一个块，须**分块**发送。每块最多 **244 字节**编码数据；最多 **32767 块**，故 SECS-II 消息最大 244 × 32767 字节。

### SECS-II 参数
- **T3 应答超时**：发出主消息到收到从应答的时间；
- **T4 块间超时**：多块消息相邻块到达间隔。

### 消息交织（Interleaving）
同时处理多个事务（多个未闭合事务）的能力。非 SECS-II 强制要求。

### 常用 SECS-II 消息

**初始化/连接时**：
| 消息 | 说明 |
|---|---|
| S1F1 | 向设备打招呼（Are You There） |
| S1F13 | 与设备建立通信 |
| S2F15 | 设置设备常数 |
| S2F43 | 关闭 Spooling |
| S2F33 | 创建/删除报表 |
| S2F35 | 将报表链接到事件 |
| S2F37 | 使能/禁用事件 |
| S5F3 | 使能/禁用报警 |

**远程控制**：S2F41（远程设备控制——配方选择、远程启动、晶圆选择等）。

**数据采集**：S6F3 / S6F9（旧版事件报告）、**S6F11**（事件报告）。

**报警**：S5F1（设备报警上报）。**S9 系列**：设备检测到先前消息错误时发送。

## SECS-I 块传输协议

块传输协议用于建立通信方向并传递消息块。一条主消息或应答可能需要多次块传输（多块消息）。

### 握手序列
四个握手码控制数据流：

| 码 | 十六进制 | 含义 |
|---|---|---|
| ENQ | 05 | 请求发送 |
| EOT | 04 | 准备接收 |
| ACK | 06 | 正确接收 |
| NAK | 15 | 错误接收 |

**SECS-I 参数**：T1（字符间超时）、T2（ENQ/EOT 协议超时）、RTY（重试上限）、Master/Slave（争用解决，**设备=Master，主机=Slave**）。

**争用解决**：主机与设备同时想通信时，从方（主机）推迟发送：发 ENQ 后收到 ENQ → 准备接收、回 EOT，先收主方块。

### 块数据（Block Data）
```
长度字节（1 字节，= N 数据字节数，10–254）
N 数据字节（10 字节块头 + 0~244 字节数据结构）
校验和（2 字节）
```

### 10 字节块头

| 字节 | 字段 | 说明 |
|---|---|---|
| 1–2 | 设备 ID | 左字节最高位为 **R-bit**：0=主机→设备；1=设备→主机 |
| 3–4 | 消息 ID | 左字节最高位为 **W-bit**：0=不期待应答；1=期待应答。**上消息 ID = Stream，下消息 ID = Function** |
| 5–6 | 块号 | 左字节最高位为 **E-bit**：0=后续还有块；1=最后一块。最大块数 32767 |
| 7–10 | 系统字节 | 左 2 字节为源 ID（路由用），右 2 字节为事务 ID（每条消息唯一；主消息与应答的系统字节相同） |

### S1F1/S1F2 报文示例（单块）

主机发 S1F1（仅头，W=1），设备回 S1F2 `<L <A "Mark I"> <A "Ver1.1">>.`：

```
主机→设备（S1F1 块）:
  05                       长度=10（仅头）
  00 00                    设备 ID=0（R=0）
  81 01                    W=1, Stream=1; Function=1
  80 01                    E=1 最后一块; 块号=1
  40 5D 4A 9F              系统字节
  06 4C                    校验和

设备→主机（S1F2 块）:
  1C                       长度=28
  00 00                    设备 ID（R=1 方向：00 00 → 80 00? 图中 R=1 见原版）
  02 89                    Stream=2... （实际: 01 02 = W=0,S=1;F=2）
  80 01                    E=1; 块号=1
  40 5D 4A 9F              系统字节（同请求）
  01 02                    L, 2 元素
  41 06 "Mark I"           ASCII 6 字节
  41 06 "Ver1.1"           ASCII 6 字节
  （校验和）
```
（字节值以原版指南图为准，此处仅示意结构。）

### 典型 SECS 协议参数

| 参数 | 功能 | 典型值 |
|---|---|---|
| 波特率 | 串口速率 | 9600 |
| 设备 ID | 设备标识 | 0 |
| T1 | 字符间超时 | 1 s |
| T2 | ENQ/EOT 超时 | 10 s |
| T3 | 应答超时 | 45 s |
| T4 | 块间超时 | 45 s |
| RTY | 重试上限 | 3 |
| M/S | 主/从 | 主机=从，设备=主 |

### RS-232 物理链路
最低协议层，基于 RS-232-C，使用 25 针（或其他）D 型连接器。使用引脚：1（屏蔽）、2（设备发数据）、3（设备收数据）、7（信号地）、18/25（可选电源）。

设备在引脚 2 发送、引脚 3 接收，属 **DTE**。若主机侧是 DCE，用直连线缆；若主机侧也是 DTE（如 PC），须用 **null-modem（交叉）线缆**（等效交换 2/3 脚）。

### 协议排障

- **T2 超时**：主机试图通信但设备离线无响应——可能物理断连或设备下线。
- **T3 超时**：主消息发送成功但设备未回从应答——链路通，但设备不响应（可能尚未建立通信）。
- **Function 0（SxF0）**：所有 Stream 保留，由接收方发送，表示事务失败，使发送方不必干等 T3 超时。
- **Stream 9**：设备发给主机，表示主机消息无法处理，或设备检测到先前消息超时。

### 建立通信
发送 SECS-II 消息前必须先"建立通信"——用 **S1F13**。这应是初次启动或长时间不通信后发送的第一条消息。

> 实践提示：主机与设备常常**同时**发起 S1F13，结果双双超时——不建议这样做。最好让设备先发 S1F13，主机应答后再发自己的 S1F13。让设备发 S1F13 可能需要摸索（如进出远程模式、下线再上线）。

## HSMS（高速 SECS 消息服务）

HSMS 基于 SEMI E37 标准，本质是 **SECS-II over TCP/IP**，提供更高速的 SECS-II 消息传输。

### HSMS 过程（Procedures）

| 过程 | 说明 |
|---|---|
| Select | 与设备建立（HSMS）连接 |
| Deselect | 断开 HSMS 连接 |
| Data | 主机与设备间的 SECS 消息 |
| Link-test | 测试主机-设备链路是否活跃 |
| Separate | 立即终止 HSMS 连接 |

**Select**：主机（主动实体）TCP connect → 设备（被动实体）accept（受 **T7** 约束）→ 主机发 Select.req → 设备回 Select.rsp（受 **T6** 约束）。

**Deselect**：任一方可用，优雅断开。
**Link Test**：任一方可发，测链路活性。
**Data**：收发 SECS-II 消息（Primary / Reply）。

### HSMS 消息格式
```
消息长度（4 字节）＝ 头(10) + 文本长度
消息头（10 字节）
消息文本（0 ~ 约 8 MB，仅 Data 过程有意义，为编码后的 SECS-II）
```

**消息头布局与各过程对照**：

| 过程 | 字节 0–1（SessionID/DeviceID） | 字节 2 | 字节 3 | 字节 4 | 字节 5（SType） |
|---|---|---|---|---|---|
| Data | SECS Device ID | W-Bit + Stream | Function | 00 | 00 |
| select.req | Device ID | 00 | 00 | 00 | 01 |
| select.rsp | 同 .req | 00 | Select Status | 00 | 02 |
| deselect.req | 同 .req | 00 | 00 | 00 | 03 |
| deselect.rsp | 同 .req | 00 | Deselect Status | 00 | 04 |
| linktest.req | FFFF | 00 | 00 | 00 | 05 |
| linktest.rsp | FFFF | 00 | 00 | 00 | 06 |
| separate.req | FFFF | 00 | 00 | 00 | 09 |

### 典型 HSMS 协议参数

| 参数 | 功能 | 典型值 |
|---|---|---|
| SECS 设备 ID | 设备 ID | 0 |
| 主动/被动 | 客户端/服务端 | 主机=主动（客户端），设备=被动（服务端） |
| 被动实体 IP | IP 地址 | 192.9.200.1 |
| 被动实体 TCP 端口 | 端口号 | 5000 |
| T3 | 应答超时 | 30 s |
| T5 | 连接间隔超时 | 10 s |
| T6 | 控制事务超时 | 10 s |
| T7 | 未 Select 超时 | 10 s |
| T8 | 网络超时 | 10 s |

## GEM（制造设备通信与控制通用模型）

GEM 基于 SEMI E30 标准，定义一组通用的设备行为与通信能力。

### GEM 是什么
- SECS-II 定义主机与设备之间**发送什么消息与数据项**；
- **GEM 定义应该使用哪些 SECS-II 消息、以及何时使用**。
- GEM 标准不约束主机行为；设备收发 GEM 消息时行为可预期。
- GEM 消息是 SECS-II 消息的**子集**。

### GEM 合规
GEM 标准包含两部分规范：
1. **基本要求（Fundamental GEM Requirements）**：
   - 状态模型；设备加工状态；主机发起 S1F13/F14 场景；事件通知；在线识别；错误消息；控制（操作员发起）；文档；
   - 以及适用的：变量数据项、SECS-II 数据项限制、采集事件。
2. **附加能力（Additional GEM Capabilities）**：
   - 建立通信、事件通知、动态事件报表配置、变量数据采集、追迹数据采集、限值监测、状态数据采集、在线识别、报警管理、远程控制、设备常数、配方管理、物料移动、设备终端服务、错误消息、时钟（、Spooling）。

**GEM 合规的条件**：
- 满足全部基本要求；
- 凡实现了的附加能力，必须按 GEM 定义的方式实现。
  （例：不实现远程控制也可以合规；但一旦实现，就必须按 GEM 的方式实现。）
