# SECS Simulator 3.2.0 使用教程（实测版）

> 本教程基于 2026-11-18 对真实运行实例的逐页面逐按钮实测编写，
> 与当前 3.2 界面一致。适用于浏览器访问（本例中为 `http://127.0.0.1:5000`）。

---

## 0. 它是什么

SECS Simulator 是一台**用软件模拟的半导体设备**：它按 SECS/GEM 协议和你的主机（Host）程序对话，
让你在没有真实设备的情况下联调主机侧。浏览器打开即用，没有登录、没有令牌。

核心概念三句话：
- **设备**＝模拟器本身（监听一个 HSMS 端口，等主机来连）；
- **主机**＝模拟 Host 侧，主动连到设备、发报文；
- **配置区 / 运行区**：配置区定义"这台设备是什么"（改了要保存），运行区看"现在正在发生什么"（改了立即生效）。

## 1. 启动与打开界面

```bash
# 一体化模式 + 托管前端（最常用）
secs-sim --mode integrated --web-root secs-simulator-ui/dist

# 指定端口与工作目录
secs-sim --mode integrated --port 5000 --work-dir build/run --web-root secs-simulator-ui/dist
```

看到 `READY ... http=5000 ...` 后，浏览器打开 `http://127.0.0.1:5000`。
设备清单数据来自数据库，进程重启后仍在，但**都是停止状态**，需要在界面里点「启动」。

> 顶栏「连接设置」按钮可把界面指向另一台机器上的后端实例（填 `http://IP:端口`），保存后重载页面。

## 3. 五分钟上手：让第一台设备和主机对话

### 第 1 步：建一台设备
1. 左侧「设备清单」→ 顶部「**新建设备**」；
2. 选一个设备模板（如 `刻蚀腔 etch`、`CVD 沉积腔 cvd`，内置多套真实晶圆工艺模板）；
3. 系统自动分配唯一设备名、端口、Device ID → 点「创建设备」；
4. 表格出现该设备，状态 `OPEN` / 控制 `离线`，此时端口尚未监听。

### 第 2 步：启动设备
- 表格行内点「**启动**」→ 设备开始监听 HSMS 端口（提示"端口已开始监听，等主机连接"）；
- 顶部「停止设备」可随时停监听，**设备仍在清单里**，再点「启动设备」即可恢复。
- 想让设备"在线"：需先有主机连上（见第 3 步），再点「上线」（等价主机发 S1F17）。

### 第 3 步：建主机并连接
1. 左侧「主机清单」→「**＋ 新建主机**」；
2. 目标地址填设备的 `127.0.0.1:设备端口`，Device ID 与设备配置一致；可勾选「立即连接」；
3. 建好后点「**连接**」发起 TCP + Select 握手。成功后设备侧控制状态变 `COMMUNICATING`（通信中）。
4. 设备页点「**上线**」→ 控制状态 `ONLINE`，设备才能主动向主机上报事件/报警。

> 不用真主机也能自测：用探针模式 `secs-sim --mode probe --hsms-port 5000` 起一个只应答 S1F1 的假设备。

### 第 4 步：看报文
- 顶栏「**消息监控**」打开右侧抽屉，按设备/主机、收发方向筛选，看真实流动的 SML 报文；
- 所有报文同时留档在 `<work-dir>/logs/messages.jsonl`，可按 `S6F11`、`S5F1` 检索。

## 4. 设备详情页（两区）

点击设备清单里的一台设备进入。顶部有区切换：**配置区** / **运行区**。

### 4.1 配置区（定义设备是什么，改完要「校验 → 保存」）

| 子页 | 你能做什么 |
|---|---|
| **概览** | 设备身份、模板、监听端点摘要；启停/上线按钮 |
| **连接** | HSMS 连接参数（地址、端口、Device ID、超时、被动模式）——每个字段都有悬浮说明 |
| **结构** | 号段（SVID/CEID/RPTID 起点与步长）、单元（腔体）增删改 |
| **设备常量** | ECV 常量定义（如温度设定值） |
| **晶圆属性** | LOTID/RCPID/PPID/WAFERID 等随片变化的属性 |
| **变量配置** | 25 个 SVID 的定义与"值来源"（常量/曲线/表达式），每行可「预览曲线」「编辑」「删除」；可从参数模板库填入 |
| **事件与报告** | CEID 事件、RPT 报告的绑定关系；报告可引用 SVID / 设备常量 / 晶圆属性 |
| **工艺周期** | 一片 wafer 的节拍、片内事件、周期曲线预览；可启动/停止周期 |
| **事件计划** | 周期外的异常路径（触发规则），定义在这里，启停在运行区 |
| **配置原文** | 配置 JSON 原文：格式化、校验、保存、导入/导出；支持并发保护（409 时提示重新载入） |
| **版本历史** | 每次保存一条快照，可看差异（diff） |

**保存流程**：改完 → 点「校验」（走真实编译路径，不落盘）→ 点「保存」（原子写盘 + 相关会话按新配置重载）。
仅改事件编排/模板/限流可热生效不断链；改结构或连接标识会重启会话、主机需重连。

### 4.2 运行区（现在正在发生什么，改了立即生效）

| 子页 | 你能做什么 |
|---|---|
| **事件执行** | 计划启停、倒计时、累计触发次数；执行时间轴（SENT/PARTIAL/FAILED/SKIPPED）、只看失败、导出 CSV。**注：当前版本对配置内计划点「单步试跑」会失败（见问题清单问题 2）** |
| **工艺周期** | 运行态启停周期，显示当前片号/相位/进度、片内事件发送记录 |
| **手动与压测** | 手动发 SML（内置 S1F1/S1F13/S1F17 等快捷预设）、压测发送、事件上报压测、报警置位/清除、报警风暴 |

**报警示例**：ALID 填 1001、类别 1、文本 `TEMP_HIGH` →「置位报警」发 S5F1（带 W 位等 S5F2）；
「清除报警」发 ALCD=0 的 S5F1。是否到达主机去消息监控抽屉看 S5F1/S5F2。

## 5. 主机详情页

点击主机清单里的一台主机进入。同样分两区：

**配置区**：概览（名称/目标地址/Device ID/自动重连；连接/断开/使设置生效在实例头）、
报文模板（内置 16 条 SML 预设，每条都有说明与案例）、Trace 设置（S2F23 采样方案库）、
采集设置（S1F3 采集配置库）。
**运行区**：消息发送（以主机角色发 SML）、Trace 采集（下发 S2F23、看 S6F1 曲线）、
数据采集（下发采集配置、启停采集、看数据曲线）。
收发记录统一在右侧消息监控抽屉查看。

「主机模板」工具页可把一套 Trace/采集方案保存为模板，新建主机时一键套用。

## 6. 独立工具

- **设备模板**：内置 8+ 套（空骨架/湿法清洗/CMP/CVD/扩散炉/外延/刻蚀/量测…），
  内置只读，可复制出自定义模板改 JSON；新建设备时从这里选。
- **参数模板**：16 套值定义（恒温、分段炉温、正弦波动、随机游走…），内置只读。
  用法是"复制"：在设备·变量配置里「从模板库填入」，把值定义深拷贝进某个 SVID（之后互不影响）。
- **审计**：查所有运维操作（时间/操作者/角色/动作/目标/详情），可按动作类型/目标过滤、载入更早。

## 7. 常见问题

| 问题 | 处理 |
|---|---|
| 设备建好但主机连不上 | 确认设备已「启动」（端口在监听）、目标地址/端口/Device ID 一致；看消息监控抽屉与 `<work-dir>/logs/app.log` |
| 设备状态是「离线」 | 需主机连上后再点「上线」；离线设备不会主动上报事件 |
| 改了配置没生效 | 配置区点「校验 → 保存」；仅热生效类改动即时生效，结构/连接类改动需重启会话、主机重连 |
| 保存报 409 | 配置被别的窗口改过，点「重新载入」拿最新版本再改 |
| 打开旧设备地址白屏 | **已知问题**（问题清单问题 1）：设备被删或地址失效会白屏，请从「设备清单」重新进入 |
| 后端连不上 | 页面顶部红色横幅有「重试 / 修改地址」，在「连接设置」里核对后端地址 |
| 想看完整历史 | 报文/审计内存各留最近 5000/1000 条，完整历史在 `logs/messages.jsonl` / `logs/audit.jsonl` |
