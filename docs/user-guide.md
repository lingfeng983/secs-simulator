# SECS Simulator 使用手册

SECS/GEM 多单元设备模拟器:在电脑上模拟出一台(或多台)符合 SECS/GEM 规范的半导体设备,
供主机(Host)程序联调测试。浏览器打开即用,不需要 Spring、不需要安装,一个可执行文件搞定。

本手册面向使用界面的人。配置文件格式(Schema v5)见 [docs/schema-v5.md](schema-v5.md),
HTTP/SSE API 见 [docs/openapi.yaml](openapi.yaml),架构与模块见 [README.md](../README.md)。

---

## 1. 启动与登录

```powershell
# 最简单:一体化模式,只绑本机,默认开放访问(免令牌)
secs-sim --mode=integrated

# 顺便托管界面(推荐):构建一次前端后,浏览器直接打开 READY 行里的地址
secs-sim --mode=integrated --web-root frontend/dist

# 从配置文件装载设备
secs-sim --mode=integrated --config ./device.json --hsms-port 5000

# 服务端模式:对外提供访问,默认开放;需要限制时显式给凭据
secs-sim --mode=server --bind 0.0.0.0 --port 8080 --token $env:SECS_TOKEN
```

启动日志里会打印一行 `READY`:

```
READY mode=integrated http=60331 token= accounts=0 sessions=0 work=...
```

- `http=` 后面是界面地址,浏览器**直接打开就用**——内部工具默认开放访问,没有令牌、没有登录;
- 需要限制访问时显式给 `--token <口令>` 或 `--auth-users users.json`,此时 READY 行会带 token
  (注意:加了凭据后当前界面无法登录,受限访问请走 API/脚本);
- 要把界面指向另一台机器上的**运行时后端**:顶栏「连接」填后端地址,保存后页面重载。

## 2. 界面总览（v6.1:单功能页面）

每个页面只做一件事,不聚合。左侧导航分组:**总览 → 设备(动态)→ 管理**:

| 位置 | 核心功能 |
|---|---|
| **工作台**（默认页,`#/workbench`） | 所有设备的总览与管理:KPI、**设备总览表**(状态/速率/报警,点行进设备页)、**会话管理**(新建/批量新建/上报/重载/关闭) |
| **设备页**（`#/device/{id}/{子页}`） | 子页一页一能力:**事件设置**(采集事件 CEID 与报告 RPTID 的增删改 + 压测上报)、**事件编排**(引用已设置的事件做计划:增删改/启停/触发 + 本设备实时事件)、**报警**(置位/清除 + 报警风暴)、**状态变量**(SVID 增删改查 + 逐变量曲线预览 + 值设定)、**配置**(进入自动打开本设备的配置文件;保存带并发保护)、**发送**(手动 SML + 同一条消息的压测发送)、**主机模拟**(三面板:消息发送 / FDC Trace S2F23→S6F1 / S1F3 数据采集)。运行时的增删改不写回配置,重载会话后按配置恢复 |
| **系统**（`#/system/audit`） | 审计留痕 |

顶部一栏:刷新、命令面板、连接设置、日志级别、主题与密度。
侧栏「设备」组动态列出会话,绿点 = 在线。

**快捷键**(按 `?` 随时看):`Ctrl+K` 命令面板(可直达某台设备的配置/工具);
数字 `1..9`/`0` 跳静态入口;`R` 刷新;`/` 聚焦搜索框;`Esc` 关浮层。
操作结果统一在**右下角提示条**反馈,绿色=成功、红色=失败。

**开箱即用的两台演示设备**:首次启动会向 `--work-dir` 播种 `demo-etch.json`
(事件效果演示:超温闭环、pulse/shift/set 跳变)与 `demo-cvd.json`(主机拉取采集演示:
LOT_START/LOT_END 正好可做 S1F3 采集的启停 CEID)。加 `--demo-session` 直接开两台;
删掉文件重启即恢复默认,已有文件永不覆盖。

**快捷键**(按 `?` 随时看):`Ctrl+K` 命令面板;数字 `1..9`/`0` 直接跳面板;`R` 刷新;
`/` 聚焦搜索框;`Esc` 关浮层。操作结果统一在**右下角提示条**反馈,绿色=成功、红色=失败。

**排障**:顶栏「日志」下拉可随时切 error/info/debug(后端日志级别,切换会记审计);
后端连不上时页面顶部出红色横幅,「重试 / 修改地址」就在横幅上。

**历史保留窗口**:报文与审计历史在内存里各有一个回看窗口(报文默认最近 5000 条、
审计默认最近 1000 条,重启后从日志文件恢复这么多),可用 `--messages-recent <n>` /
`--audit-recent <n>` 调整;审计窗口就是界面上「载入更早」能翻多深。
窗口外的旧记录只剩磁盘上的 `logs/messages.jsonl` / `logs/audit.jsonl`,可以 grep 拿全量。

**个性化**:右上角可切浅色/深色/跟随系统、紧凑/宽松密度;当前页面与这些偏好跨刷新保留。
窗口变窄时侧边栏自动变成顶部横排,表格横向滚动,表单自动折列——手机宽度也能用。

## 3. 典型工作流

### 3.1 开一台设备

1. 把设备配置文件(格式见 schema-v5,可用设备页·配置里的「新建」生成骨架)放进
   `--work-dir` 指向的目录;
2. 工作台的「会话管理」→ 「新建会话的配置名」填配置名(`.json` 后缀可省略)→ 点「新建会话」;
3. 表格里出现该设备:状态 `OPEN`、控制 `离线`(还没主机连)。

同一进程可以同时跑多台设备,还能**批量操作**:会话表格勾选多台,
底部出现「批量上报 / 批量重载 / 批量关闭」,对勾选的设备逐台执行并汇总结果。
**批量开一排同类设备**:工作台「会话管理」→ 「批量新建」,
选一份设备配置模板,给数量、会话 id 前缀、起始端口和 device-id 起始——
第 i 台的会话 id = 前缀+i、端口 = 起始+i−1、device-id = 起始+i−1,
设备本体(单元、变量、事件、模板)全部复用模板。覆盖只在运行期生效,不写回模板文件;
单台创建时也可以带同样的覆盖(API 的 `sessionId` / `port` / `bindHost` / `deviceId` 字段)。

### 3.2 让主机连上来

设备的 HSMS 端口由配置 `session.port` 决定(passive 模式监听)。主机连上并
Select 之后,控制状态变为 `通信中`;主机发 S1F17(或设备接受通信)后变 `在线`。
只有**在线**的设备才能向主机主动上报(事件、报警)。

没有现成主机?探针模式(`secs-sim --mode=probe --hsms-port 5000`)
可以开一个只应答 S1F1 的假设备,用来验证主机侧。

### 3.3 改配置并让它生效

1. 设备页·配置 → 下拉选配置文件;默认**表单视图**,会话 / 设备 / 事件编排 / 模板
   四段都能在表单里改,不需要碰 JSON;
2. 点「校验」——走的是真实启动路径(解析 → 编译设备模型 → 建模板图),不过不会落盘;
3. 点「保存」——校验通过后原子写盘;
4. 运行中的会话不会自动变:**去工作台「会话管理」点该设备的「重载」**,新配置才生效。

保存带**并发保护**:编辑器记住打开时的文件修改时间,保存时带回后端核对——
如果这期间配置被别的窗口(或进程)改过,保存会被拒绝(409)并提示「重新载入」,
后保存的一方不会悄悄覆盖先保存的改动。
   重载是智能的:只改了事件编排/模板/限流/W 位时**原地热生效,主机连接不断**;
   设备结构(单元/变量/号段)或连接标识(id/端口/超时)变了才关旧开新、主机需重连。
   编译失败时旧会话原样不动。

要看 JSON 或粘贴整份配置时,切到「JSON 原文」视图;不动表单时保存逐字节写回,
手写的注释键、缩进都不会被改。

### 3.4 模拟一次报警

设备页·报警:填 ALID(如 1001)、类别、报警文本 → 点「置位」。设备向主机发
S5F1(带 W 位等 S5F2);「活动报警」表立即出现一行。点「清除」发 ALCD=0 的 S5F1,
报警从活动表移除。报文留档在 `logs/messages.jsonl`,可按 `S5F1` 检索。

### 3.4b 主机模拟(发主机方向的报文)

S2F33(定义报告)/S2F35(链接事件)/S2F37(启停事件)是**主机→设备**方向的报文,
设备侧界面发不出正确语义。设备页·主机模拟分三面板:①消息发送(以主机角色连到选中的
设备——设备只接受一个主机,真主机在线时会被拒绝;内置 S1F13/S2F33/35/37 预设一键填入,
发送后「事件设置」页的定义来源会变成"主机",事件编排启停状态同步变化)、
②FDC Trace 数据采集(S2F23 周期采样,设备按 REPGSZ 分条回 S6F1)、
③S1F3 数据采集(主机主动轮询拉取,可编辑采集计划、实时画图、导出 CSV)。

### 3.5 手动发报文与压测

设备页·发送:输入 SML 文本(如 `S1F1 W.`),点「发送 SML」。带 `W` 时会等
主机应答并显示回复报文与耗时;主机没连时会返回 409。SML 语法:报文头 `SxFy`,
数据项支持 `L/A/B/BOOLEAN/I1..I8/U1..U8/F4/F8`。

### 3.6

下方的**压测**把同一份报文重复发送 N 次(1–1000,并发 1–20,可设每轮间隔),
实时显示进度,结束后给出成功/失败/超时数、往返延迟(平均/最小/最大/P95)和吞吐。
同一条消息要重复发送:填好次数/间隔后点「压测发送」,服务端循环并统计成功/失败与延迟。

看曲线

设备页·状态变量:每个 SVID 一行,点「预览」画该变量最近 1 分钟的曲线
(min/max/avg 迷你图);「设定」把变量钉在给定值上(覆盖曲线与事件效果),
「取消设定」回到曲线值。

## 4. 页面速查

### 会话管理
- 表格列:id / 状态(OPEN…) / 控制(离线・通信中・在线) / 设备 / 单元数 / 计数器;
- 操作:**上报**(手动触发一次 S6F11,要求设备在线)、**重载**(按配置重建会话)、**关闭**(解绑端口);
- 搜索框即时过滤,点列头排序,「导出 CSV」拿全量;
- CEID 框配合设备页·目录的「填入」按钮用,不用背数字。

### 报警
- 置位/清除即时生效,活动报警与终端消息(S10F3 收到的)分表展示,都可搜索导出。

### 事件编排
- 改的是**运行时状态**:禁用后不再触发、已排队的延迟事件清掉;重载会话后按配置恢复。

### 设备页·配置
- 表单视图覆盖 session / equipment(号段、全局 SVID/CEID、ECV 常量、单元)/ events / templates;
- 事件计划的 CEID 输入框带自动补全;类型下拉是后端支持的 12 种 SECS-II 类型;
- 未知键永远保留;表单改动会把整份文件统一成 2 空格缩进(界面上有说明)。

### 审计
- 审计记录登录后的每个写操作(动作/目标/结果),落盘在 `logs/audit.jsonl`(重启保留最近 1000 条);
  动作/操作者是**服务端**精确过滤,「载入更早」以最早一条为游标往前翻,本地搜索是包含式过滤,三者互补。

## 5. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 上报/报警返回 409 | 设备不在线。主机必须已连接、完成 S1F13/S1F17 让设备进入**在线**;或先查工作台会话表的控制状态 |
| 新建会话报"必须是 .json 文件" | 输入的配置名带 `.json` 后缀(界面会自动补,直接输文件名即可) |
| 改了配置没生效 | 配置在会话启动时读入内存,保存后必须到工作台「会话管理」**重载**该会话 |
| 重载后主机断了 | 重载 = 关旧开新,HSMS 连接会断,主机重连即可;设备会重新监听原端口 |
| 事件断线 | SSE 断了,界面 2 秒后自动换票据重连;断线期间的报文留档在 `logs/messages.jsonl` |
| 报警文本含中文被拒 | S5F1 的 ALTX 是 ASCII 编码,换纯英文文本 |
| 曲线全是 0 | 配置有 `templates` 段时,没绑定到实例的 SVID 恒为 0(见 schema-v5);删掉 templates 段可回到默认随机曲线 |
| 校验报 `UNKNOWN_CEID` | 事件计划里的 `ceid` 在该设备的单元/全局 CEID 里没有定义;先在 `equipment` 段补上,或改计划引用的编号 |
| 主机写完 ECV 后配置被重排 | 正常现象:S2F15 回写只替换 `constants` 段,其余键与值不变,但缩进会统一成 2 空格 |
| 加了 --token 后界面连不上 | 界面为免凭据形态,内网场景去掉 `--token` 用开放访问;受限访问请走 API/脚本 |

## 6. 两种安装形态

| 形态 | 内容 | 用法 |
|---|---|---|
| **Windows 安装程序** `SECS Simulator_<版本>_x64-setup.exe` | Tauri 壳(前端内嵌) + 原生 exe 后端 | 安装后打开直接进界面,默认连本机后端(无需 JVM);`scripts/package-windows.ps1` 产出 |
| **Linux 服务端** `secs-sim-server-<版本>-linux.zip` | 模块 jar + 前端 + `start-server.sh` | 部署在 Linux 设备机,`./start-server.sh` 以 server 模式对外(目标机需 JDK 25+);`scripts/package-linux.ps1` 产出 |

远程场景:设备在 Linux 机(A)解压服务端包并 `./start-server.sh` 启动;
操作者在 Windows 机(B)安装程序,打开后点右上角「连接」,填 A 机地址(`http://A 机 IP:8080`)
保存——界面仍由 B 机的壳提供,但配置、批量、曲线、报文全部操作 A 机,本机后端自动停止。
要切回本机,同一对话框里清空地址保存即可。
本机场景则完全不依赖网络:安装程序内置后端与前端,打开即用。

## 7. 一分钟上手清单

1. `secs-sim --mode=integrated --web-root frontend/dist`
2. 浏览器开 READY 行的地址;
3. 工作台「会话管理」新建一个配置(没有就先在设备页·配置点「新建」);
4. 主机连配置里的 HSMS 端口,等控制状态变绿;
5. 设备页·事件看事件往上跑,设备页·曲线看数值。
