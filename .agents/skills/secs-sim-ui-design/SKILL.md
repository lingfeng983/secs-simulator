# SECS Simulator UI 设计规范(用户确认版)

本规范是历次交互中用户明确提出或逐条确认的要求,不是模型推测的风格偏好。
权威设计文档:`docs/design/redesign-2026-11-12.md` §3(信息架构/交互/视觉/文案);冲突时以用户新要求 > 本文件 > 设计文档为准。

## 1. 信息架构与导航

- **侧栏三组**:①设备清单(工作台 + 动态设备树)②主机清单(主机模拟 + 动态主机树)③独立工具(主机模板/设备模板/参数模板/审计)。
- **两段式页签**:每个实例详情页分「配置区(定义)」与「运行区(当前运行)」两段,hash 路由 `#/device/{id}/{zone}/{page}`、`#/hosts/{id}/{zone}/{page}`。
- **一页一能力**:页面按单一能力拆细,不聚合大页;顶层还有 events/messages/sessions 等独立全局页。
- **主机与设备同构**:共用同一套骨架(实例树/面包屑/实例头/两段式页签/待生效横幅),但**数据完全独立**——主机页不读设备列表,设备页不出现主机实例或主机连接状态。
- **主机独立多开**:新建主机只填 名称/目标地址/端口/Device ID,**无设备下拉**;默认名称 `host`、目标地址 `127.0.0.1`;可多台指向同一地址。
- **单主机运行区**:消息只发本主机、收发记录只看本主机,无跨主机多选。
- 新增子页时同步:`router.ts` 页签集 + `*_PAGE_NOTES`(SubTabs 悬浮说明)+ 导航/routeTitle/goTo/命令面板 id 映射 + router.test.ts 断言。

## 2. 配置区 / 运行区职责边界(核心原则:配置区管定义、运行区管运行)

- **配置区**:只描述"这个设备/主机是什么、怎么连、发什么、采什么"。保存后需重载/重连才生效。
- **运行区**:只做 启停/手动操作/压测/查看实时结果,**不保留**定义类编辑(SVID 钉值与曲线预览、运行态临时目录编辑都已按用户要求移除)。
- 方案(Trace/采集)的增删改入口只在配置区;运行区只剩 一键下发/发送 + 启停 + 曲线。
- 报警是纯运行态(配置里没有报警定义),不新增报警配置页。
- CEID 与报告合并为「事件与报告」一个页签;删页面前先确认功能归位,用户原则是"一项不删、只换位置"。

## 3. 视觉与状态映射

| 元素 | 配置区 | 运行区 |
|---|---|---|
| 主色 | 靛蓝 `#4457c7` | 青绿 `#0f8a6a` |
| 徽标 | `版本 vN · 已保存` +「保存后需重载」 | `当前运行 · 仅本次有效` / 呼吸点表示实时 |
| 危险色 | 仅「删除设备」 | 仅「删除主机」 |

- 链路状态:已连接 绿 / 连接中 蓝 / 已断开 灰 / 连接失败 红。**连接失败是终态,不显示「重试中」**(除非用户开了自动重连)。
- 断开 ≠ 删除:「断开」是普通按钮(非 danger),实体保留在列表与侧栏(灰色状态点),运行区显示空态,可一键重连。
- 删除是显式危险动作:收进 `⋯` 菜单,弹窗列出会删除的内容,链路未断开时禁用。
- 状态实时化用 SSE 驱动,不靠轮询发现"对象消失"。

## 4. 组件与表单惯例(先复用,不新造)

- **表单/弹窗对齐**:新建任何表单弹窗优先用 `session-form` 对齐网格(`05-pages.css`:说明在左 `session-field-name`+`session-field-help`、控件在右统一宽度),**不用松散的 `.form-row`**;每个字段要带帮助说明。
- **配置区编辑页**:直接用 `ConfigEditShell` + `ConfigFormEditor` 导出件(ConstantsForm/GlobalSvidsForm/GlobalCeidsForm/EventsForm);shell props 是显式 `{backend, sessionId?}`,不是 PanelBaseProps。
- **引用选择**:用 `RefMultiSelect`(勾选式,缺失项保底展示),不用手填字符串列表(旧 StringListField 已删)。
- **折叠**:内容多必须折叠——`ui/Collapsible.tsx`,默认只开第一段,标题带数量徽标与「热生效」类标注。
- **面板说明**:改悬浮气泡(`.panel-tip`,`:hover/:focus-within` 显示),不要常驻 `.panel-desc` 描述文字。
- **排版**:面板卡片化;field/模板 label 横排;统计统一右下角 `PanelFootnote`;侧栏无数字角标;panel-head sticky;响应式三档。
- **表格**:统一 DataTable,列宽拖拽(tableKey 持久化)、onRowClick、行 key 必须唯一稳定(清单纯行教训:rowKey 全 `''` 会留幽灵行)。
- 操作要有反馈:单台关闭/删除有确认(`ConfirmModal` 统一),批量有进度,保存 409 提示重新载入。
- 列表页结构 = 概览卡 + 表格 + 批量操作,与工作台同构。

## 5. 界面文案约束(硬门禁)

界面只描述**使用者能做的事**与**能看到的结果**。技术词一律不进产品界面:
数据库/SQLite/双库/表/字段/事务/投影/迁移/持久化/落盘/会话态/幂等键/快照/SHA256/乐观锁/If-Revision/API 路径/SSE/类名/模块名/ADR 编号等。

界面用词对照(完整表见 redesign 文档 §3.5):
- `config r7` → 「版本 v7 · 已保存」;配置漂移 → 「配置待生效」;钉值/pin → 「手动设定」;运行态不写盘 → 「当前运行 · 仅本次有效」;`SSE device-link` → 「实时更新」;`plan_execution` 台账 → 「执行记录」。
- 主机界面禁出现「本机/远程模式」「所属设备」「宿主会话」等绑定文案;变量来源用「变量自动获取 / 变量需手动填写」表达。
- 门禁:`scripts/check-ui-words.ps1` 扫 tsx/ts 字符串与 JSX 文本(「表」按词判定,列表/表格/图表放行;英文词按词边界);改动文案后必跑,新增白名单词要写明理由。
- 注意:「数据库」曾是禁用词,`ui-words` 检查有既有判定规则,文案改动以脚本通过为准。

## 6. 实施与验证流程(用户习惯)

- **大改(信息架构/新增分区/重设计)先写设计文档给用户逐条确认再动手**(如 `docs/design/redesign-2026-11-12.md` 三轮修订模式);小改可直接做。
- 明确不做的:纯视觉 churn、收益低的合并(如两套 badge markup、stat-card/kpi-card 合并)——用户确认过不做。
- **界面验证不用 Playwright**:①`npm run build` 构建到 `secs-simulator-ui/dist` ②起 mock 服务 `secs-simulator-ui/scripts/mock-ui-server.mjs`(端口 4199)③用 ZCode 内置浏览器打开 `http://127.0.0.1:8931/#token=xxx` 操作与视口截图(fullPage 与 sticky 顶栏有拼接伪影)。不跑 `npm run test:e2e`、不 `npx playwright install`;npx 意外改了 package.json/package-lock.json 要还原。
- 真·回归以 `scripts/e2e` 为准(e2e 断言要随 UI 语义同步改,如默认值改变后"空则禁用"用例要改写)。
- 每里程碑一笔提交;改动文案后跑 `check-ui-words` + `tsc --noEmit` + vitest。

## 7. 已踩过的实现坑(改 UI 前扫一眼)

- 跨 config↔runtime 区切换若复用同一组件实例,Modal 等状态会跨区残留——分发处加 `key="trace-config"` 之类。
- 值来源编辑器直接改解析树活引用会被重渲染冲掉,必须 `mutate` 写穿(editDocument 重新定位)。
- React `onBlur` 监听的是冒泡的 `focusout`;提交型输入框(CommitFields)要派发 `focusout`,且 input 与 focusout 分两次 evaluate。
- 常驻 2s 轮询重渲染会让 e2e 行点击 flake,下钻断言用侧栏入口兜底。
- 停止态设备也要可点进详情(路由 key 允许配置名),运行区显示「设备未启动」+ 启动按钮。
